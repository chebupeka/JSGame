## Уточнения против CURRICULUM.md

1. **Глава 20: 11 задач вместо «около 9».** В плане главы двенадцать новых мыслей, а правило акта — одна мысль на задачу. Первые шесть задач по 1–3 строки, поэтому вечер не вырастает: 40–60 минут.
2. **`useEffect`, StrictMode, управляемое поле, `children` и TSX переехали в главу 21.** Иначе глава 20 выросла бы до 16 задач. В главе 21 они нужны сразу: журнал грузится с сервера (`useEffect`), у него форма (управляемое поле), рамка для экранов (`children`), и весь каркас на TypeScript. StrictMode включён в каркасе, как в шаблоне Vite, и его последствие честно видно в задаче про эффект.
3. **Глава 21: 11 задач, как в CURRICULUM, но состав свой.** Фильтр и сортировка, доступность и переносной пульт не дают новой мысли: это гл. 5–6, 12 и 13. Они вошли в её итоговый сценарий журнала и в свою историю, а не в отдельные задачи. Зато две задачи разделены надвое, чтобы в каждой была одна мысль: зависимости эффекта и его уборка (21.5 и 21.6); маршруты в приложении и маршруты в тесте (21.9 и 21.10). Вторая пара — как на работе: правка со ссылками роняет старый тест каркаса.
4. **Кавычки.** Все строки JS — в обратных кавычках, как везде. Два исключения диктует сам язык, и Prettier их не трогает: путь в `import` (`from "react"`) и атрибут-строка в JSX (`className="lamp on"`). JSX — разметка, у неё кавычки HTML. В первой задаче с `import` на полях это сказано одной фразой.
5. **В главе 20 комнату рисует код игрока до задачи 20.8, дальше — станция.** С 20.8 `main.jsx` станции рисует `<Watch finds={…} />` сам и перерисовывает, когда море приносит находку. Так данные приходят пропсом, как в настоящем приложении, а проверка может менять их на ходу.
6. **Два последствия из плана главы 20 показаны иначе.** Стёртый `classList` в плане шёл через «отнести», но здесь отнесённая строка уходит целиком и `className` у неё не меняется. ## Сквозное для акта

- **Пока печатаешь, всё как прежде.** Реагирует только закрытый литеральный селектор (`` `#watch` ``) и датчик на `addEventListener`. JSX, хуки и пропсы молчат до запуска.
- **Рендер в мире.** Запуск — табличка корня `#watch` вспыхивает, потом импульс проходит через функцию компонента: её строки вспыхивают сверху вниз. На каждое изменение состояния импульс снова проходит через функцию. Меняются только те вещи, которые React правда тронул: их отмечает `MutationObserver` агента, и только они вспыхивают.
- **Датчики React.** Щуп на кнопке внутри React датчика не находит. Пучок датчиков висит на корне `#watch`, по одному на тип события. Это делегирование из гл. 6, сделанное за тебя.

Запрос наружу тоже не линия: пока ответа нет, у строки с запросом синяя кромка «жду», а ответ — импульс, строка вспыхивает светлым. Щуп на этой строке работает как вкладка Network: адрес, метод, `status`, время. [согласовать: MECHANICS §6 и акт IV ещё говорят «провод наружу»]
- **Под корпусом** у файла `.jsx` виден обычный JS после esbuild: `jsx("h1", { children: "Опись" })`.
- **Табло вахты** (`watch-board`, около 96×48) — ЭЛТ-экран над вахтенным столом. Текст `h1`, `p`, `li`, `b` рендер пишет шрифтом Tiny5 синим: его сделал твой код. `button` рисуется клавишей (`key` из гл. 9) с подписью. Незнакомый тег — серая пластина с именем тега (§9).

### 20.1 Лампа поста (`watch-lamp`)

- **Новое:** JSX: разметка в коде
- **Опирается на:** `document.querySelector`, `id` и класс (гл. 1), `import` (гл. 17)
- **Файл(ы):** `watch.jsx`
- **Текст файла при входе:**

```jsx
// Хочу, чтобы на вахтенном посту загорелась лампа.
//
// Дано:
// - табло вахты: <div id="watch" class="watch-board">,
//   пустое
// - строка с createRoot отдаёт табло React
// - root.render(разметка) рисует разметку на табло
// - лампа: <div class="lamp on">, в CSS станции горит
//
// Нарисуй лампу на табло.
import { createRoot } from "react-dom/client";

const root = createRoot(document.querySelector(`#watch`));

root.render();
```

- **Пометка при входе (поля):**
  1. React — чужой готовый код, библиотека: он сам создаёт и меняет вещи. Ты только описываешь, какими им быть: `render(…)` — «нарисуй вот так».
  2. Описание пишут прямо в коде, без кавычек вокруг: `<h1>текст</h1>`. Это JSX.
  3. Атрибуты в JSX — как в HTML, в обычных кавычках. Только `class` пишется `className`, а пустой тег закрывают сразу: `<div … />`.
- **Подсказки по щелчку:**
  1. Табло над столом тёмное и пустое. Это и есть `#watch`: его табличка уже горит, строка с `createRoot` его нашла.
  2. Внутрь `render(…)` кладётся сама разметка лампы, как в HTML, только без кавычек вокруг.
  3. `` root.render(<div className="____" />); ``
- **Эталонное решение:**

```jsx
import { createRoot } from "react-dom/client";

const root = createRoot(document.querySelector(`#watch`));

root.render(<div className="lamp on" />);
```

- **Она проверяет:** Она стоит у двери зала, в темноте: светятся только мониторы вдоль стены. После запуска агент смотрит снимок: внутри `#watch` есть элемент с классами `lamp` и `on`. Лампа загорается в углу табло, на стол ложится синее пятно. Она идёт вдоль стены к посту и встаёт у стола в свете.
  - **Почти:** `<div className="lamp" />` — лампа на табло есть, но тёмная. Она стоит у двери. Пометка: «Лампа есть, но не горит. В CSS станции горит `lamp` с классом `on`».
  - Если на табло текст, а не лампа (ошибка 1), она тоже стоит у двери: света нет.
- **Частые ошибки:**
  1. Строка вместо разметки, по привычке:
     ```jsx
     root.render(`<div className="lamp on" />`);
     ```
     Ошибки нет. На табло синими буквами написано `<div className="lamp on" />`. Щуп на табло: текст, а не элемент.
     Строка в обратных кавычках — это текст, и React честно рисует его буквами. JSX пишется без кавычек.

  2. Тег не закрыт:
     ```jsx
     root.render(<div className="lamp on">);
     ```
     Рубильник не встаёт в зацеп, засечка сразу за последней строкой файла.
     ```
     Unexpected end of file before a closing "div" tag
     строка 16
     ```
     - `Unexpected end of file` — файл кончился неожиданно,
     - `before a closing "div" tag` — а закрывающего тега `div` так и не было.

     В JSX каждый тег закрыт: `<div …></div>` или сразу `<div … />`. [сверить с esbuild игры]

  3. `class` вместо `className`:
     ```jsx
     root.render(<div class="lamp on" />);
     ```
     Лампа горит, она идёт к посту. Телетайп печатает:
     ```
     Invalid DOM property `class`. Did you mean `className`?
     ```
     - ``Invalid DOM property `class` `` — неверное имя свойства для DOM: `class`.
     - ``Did you mean `className`? `` — может, ты имел в виду `className`?

     Это предупреждение, а не ошибка: React сам поправил. Но в JSX класс пишется `className`. Задача засчитана, пометка при успехе: «Работает. Лента просит `className` — поправь, чтобы она молчала».

  4. По-утреннему: нарисовать и тут же найти:
     ```jsx
     root.render(<div className="lamp" />);
     document.querySelector(`.lamp`).classList.add(`on`);
     ```
     ```
     TypeError: Cannot read properties of null (reading 'classList')
     строка 16
     ```
     - `TypeError` — со значением сделали то, чего с ним делать нельзя.
     - `Cannot read properties of null` — пытались взять что-то у `null`, у «ничего».
     - `(reading 'classList')` — а именно `classList`.

     Автомат выбит. `render` не рисует сразу: он только просит React, а React рисует чуть позже, когда файл уже выполнился. Лампы ещё нет, поиск вернул `null`. Опиши лампу сразу горящей: `className="lamp on"`.
- **Код профи:** Разницы в работе нет: `<div className="lamp on" />` и `<div className="lamp on"></div>` дают один и тот же вызов. Prettier оставляет как написано.
- **В мире:**
  - Вещи: `<div id="watch" class="watch-board">` — пустое табло; стол, находки и ставень — как в «Комнате целиком».
  - CSS станции: `.lamp.on` горит, `.watch-board` 96×48.
  - Пока печатаешь: на закрывающей кавычке `` `#watch` `` строка синеет, табличка на табло загорается, щёлкает реле. JSX молчит.
  - Запуск медленный, как первый в задаче: табло на миг в светлых уголках, табличка `#watch` вспыхивает, потом строка `render` — и в углу табло зажигается лампа. Щуп на лампе: `<div class="lamp on">`. Под корпусом файл после esbuild: `root.render(jsx("div", { className: "lamp on" }))` — JSX стал обычным вызовом функции.
  - При успехе на полях: «Работает. Ту лампу утром ты нашёл. Эту ты описал, а создал её React».

### 20.2 Своя вещь: Lamp (`watch-component`)

- **Новое:** компонент
- **Опирается на:** JSX (20.1), функции-стрелки (гл. 2), `const` (гл. 1)
- **Файл(ы):** `watch.jsx`
- **Текст файла при входе:**

```jsx
// Хочу, чтобы лампа поста стала своей вещью: Lamp.
//
// Дано:
// - компонент — функция, которая возвращает разметку
// - имя компонента пишут с большой буквы
// - в разметке его ставят как тег: <Lamp />
//
// Сделай компонент Lamp с лампой и нарисуй его.
import { createRoot } from "react-dom/client";

const root = createRoot(document.querySelector(`#watch`));

root.render(<div className="lamp on" />);
```

- **Пометка при входе (поля):**
  1. Компонент: `const Имя = () => разметка`. Своя вещь, собранная из разметки.
  2. С маленькой буквы React примет имя за тег HTML.
  3. Скоро на табло будет много вещей. Каждая — свой компонент.
- **Подсказки по щелчку:**
  1. Лампа на табло та же. Меняется не мир, а то, как он записан.
  2. Нужна стрелка без параметров, которая возвращает разметку лампы. Потом в `render` — `<Lamp />`.
  3. Две строки:
     ```jsx
     const ____ = () => <div className="lamp on" />;

     root.render(<____ />);
     ```

- **Эталонное решение:**

```jsx
import { createRoot } from "react-dom/client";

const Lamp = () => <div className="lamp on" />;

const root = createRoot(document.querySelector(`#watch`));

root.render(<Lamp />);
```

- **Она проверяет:** Она стоит у стола в свете лампы. Станция проверяет две вещи: в разборе кода есть `const` с именем с большой буквы, чьё значение — стрелка с разметкой, и этот компонент стоит в `render` тегом; по снимку лампа в `#watch` горит. Тогда она остаётся в свете и кладёт руку на стол.
  - **Почти:** `render` всё ещё рисует `<div className="lamp on" />`, а `Lamp` объявлен и не нарисован. Свет есть, задача не засчитана. Пометка: «Лампа горит, но `Lamp` нигде не нарисован: `render` рисует `<div>`».
- **Частые ошибки:**
  1. Имя с маленькой буквы:
     ```jsx
     const lamp = () => <div className="lamp on" />;

     root.render(<lamp />);
     ```
     Свет гаснет, на табло серая пластина с надписью `lamp`: такой вещи станция не знает (§9). Щуп: `<lamp></lamp>`. Телетайп печатает (проверено на React 19.3):
     ```
     The tag <lamp> is unrecognized in this browser. If you meant to render a React component, start its name with an uppercase letter.
     ```
     - `The tag <lamp> is unrecognized in this browser` — браузер не знает тега `<lamp>`.
     - `If you meant to render a React component` — если ты хотел нарисовать компонент,
     - `start its name with an uppercase letter` — начни его имя с большой буквы.

     С маленькой буквы JSX считает имя тегом HTML и отдаёт его браузеру как есть. Она отступает от стола в темноту и ждёт.

  2. Функция вместо тега:
     ```jsx
     root.render(Lamp);
     ```
     Табло пустое, свет гаснет. Телетайп:
     ```
     Functions are not valid as a React child. This may happen if you return Lamp instead of <Lamp /> from render. Or maybe you meant to call this function rather than return it.
       root.render(Lamp)
     ```
     - `Functions are not valid as a React child` — функция не может быть вещью на табло.
     - `This may happen if you return Lamp instead of <Lamp />` — так бывает, если отдать `Lamp` вместо `<Lamp />`.
     - `Or maybe you meant to call this function` — или ты хотел её вызвать.

     `Lamp` — сама функция, а `<Lamp />` — просьба к React вызвать её и нарисовать результат.

  3. Фигурные скобки без `return`:
     ```jsx
     const Lamp = () => {
       <div className="lamp on" />;
     };
     ```
     Ошибки нет, табло пустое. Импульс входит в `Lamp` и возвращается полым: щуп на нём — `undefined`.
     С фигурными скобками стрелка ничего не возвращает без `return`. Без скобок она возвращает разметку сама.
- **Код профи:** Разницы в работе нет: браузер получает тот же `<div>`. Компонент нужен людям, как лесенка: у вещи появилось имя, и её можно поставить в разметку много раз.
- **В мире:**
  - Вещи и CSS — как в 20.1.
  - Запуск: импульс к табло, потом в строку `const Lamp` — она вспыхивает: React вызвал функцию. Лампа загорается.
  - Щуп на лампе: `<div class="lamp on">` и ниже, кто её вернул: `Lamp`. То же показывает вкладка Components в React DevTools, она снаружи.

### 20.3 Имя находки (`watch-find`)

- **Новое:** `{выражение}` в JSX
- **Опирается на:** компонент (20.2), объект и его поля (гл. 3), `import` (гл. 17)
- **Файл(ы):** `watch.jsx`
- **Текст файла при входе:**

```jsx
// Хочу, чтобы под заголовком стояло имя находки со стола.
//
// Дано:
// - находка на столе — find, её прислал сервер:
//   { id: 7, tag: `AB-007`, name: `кассета` }
// - в JSX {выражение} вставляет значение из JS
// - Watch собирает табло. Всё в одной обёртке
//   <section>: JSX отдаёт одну вещь
//
// Впиши в <p> имя находки из find.
import { createRoot } from "react-dom/client";
import { find } from "./finds.js";

const Lamp = () => <div className="lamp on" />;

const Watch = () => (
  <section>
    <Lamp />
    <h1>Опись</h1>
    <p></p>
  </section>
);

const root = createRoot(document.querySelector(`#watch`));

root.render(<Watch />);
```

- **Пометка при входе (поля):**
  1. Фигурные скобки в JSX — окно в JS: `{find.name}` подставит значение.
  2. Без скобок — просто буквы: `<p>find.name</p>` так и напишет.
  3. Обёртка `<section>` — потому что JSX отдаёт одну вещь, как функция один результат.
- **Подсказки по щелчку:**
  1. На столе лежит кассета. На табло под «Опись» пустая строка — это `<p>`.
  2. Нужно поле `name` объекта `find`. В JSX значение вставляют в фигурных скобках.
  3. `<p>{find.____}</p>`
- **Эталонное решение:**

```jsx
import { createRoot } from "react-dom/client";
import { find } from "./finds.js";

const Lamp = () => <div className="lamp on" />;

const Watch = () => (
  <section>
    <Lamp />
    <h1>Опись</h1>
    <p>{find.name}</p>
  </section>
);

const root = createRoot(document.querySelector(`#watch`));

root.render(<Watch />);
```

- **Она проверяет:** Как тест с двумя ответами сервера. Она берёт кассету со стола (трогать) и стоит у табло: текст `<p>` должен быть `кассета`. Потом она приносит линзу и кладёт на место кассеты (нести). Станция запускает файл заново, теперь `find` — линза, и текст должен быть `линза`. Совпало оба раза — она оставляет линзу на столе и стоит в свете.
  - **Почти:** `<p>кассета</p>` руками. В первый раз верно, во второй на табло «кассета», а у неё в руках линза. Она стоит с линзой у табло. Пометка: «На столе линза, а табло пишет «кассета». Имя должно браться из `find`».
- **Частые ошибки:**
  1. Без скобок:
     ```jsx
     <p>find.name</p>
     ```
     Ошибки нет, на табло буквы `find.name`. Без фигурных скобок JSX считает это обычным текстом.

  2. Весь объект:
     ```jsx
     <p>{find}</p>
     ```
     Выбит автомат, табло гаснет целиком, вместе с лампой.
     ```
     Uncaught Error: Objects are not valid as a React child (found: object with keys {id, tag, name}). If you meant to render a collection of children, use an array instead.
     ```
     - `Objects are not valid as a React child` — объект не может быть вещью на табло.
     - `(found: object with keys {id, tag, name})` — нашёлся объект с полями `id`, `tag`, `name`.
     - `If you meant to render a collection of children, use an array instead` — если хотел нарисовать несколько вещей, нужен массив.

     React не знает, как нарисовать объект целиком. Нужно одно его поле: `find.name`.

  3. Привычка шаблонных строк:
     ```jsx
     <p>${find.name}</p>
     ```
     Ошибки нет, на табло `$кассета`. `${…}` — для шаблонных строк. В JSX значение вставляют просто в `{…}`, и `$` остаётся буквой.

  4. Опечатка в поле:
     ```jsx
     <p>{find.nmae}</p>
     ```
     Ошибки нет, строка пустая. По строке бежит полый импульс, щуп: `find.nmae: undefined`. Такого поля нет, пришло «ничего», а его React не рисует.

  5. Вещь за обёрткой:
     ```jsx
     const Watch = () => (
       <section>
         <Lamp />
         <h1>Опись</h1>
       </section>
       <p>{find.name}</p>
     );
     ```
     Рубильник не встаёт в зацеп, засечка на строке с `<p>`.
     ```
     Expected "}" but found "."
     строка 21
     ```
     - `Expected "}"` — ждал закрывающую фигурную скобку,
     - `but found "."` — а нашёл точку.

     Текст сбивает с толку: разбор принял `<p>` за знак «меньше» и запутался дальше. Смотри не на слова, а на место: всё, что рисует компонент, — внутри одной обёртки. [сверить с esbuild игры]
- **В мире:**
  - На столе одна находка, кассета (`<div class="find" data-id="7">`), потом линза.
  - `finds.js` — файл станции, его монитор висит у стола. Щуп на `find` в коде после запуска: `{ id: 7, tag: "AB-007", name: "кассета", … }`.
  - Запуск: импульс проходит через `Watch` — строки вспыхивают сверху вниз, на строке `<p>` импульс несёт значение: щуп — `"кассета"`.
  - Под корпусом: `jsx("p", { children: find.name })`. Фигурные скобки — просто аргумент функции.

### 20.4 Три находки (`find-item`)

- **Новое:** пропсы
- **Опирается на:** компонент (20.2), `{выражение}` (20.3), `({ target })` в параметре (гл. 2)
- **Файл(ы):** `watch.jsx`
- **Текст файла при входе:**

```jsx
// Хочу, чтобы на табло были все три находки со стола.
//
// Дано:
// - находки cassette, lens и chain — такие же, как find
// - пропс — то, что отдают компоненту, как атрибут:
//   <FindItem find={cassette} />
// - компонент получает пропсы одним объектом:
//   ({ find }) => …
//
// Сделай FindItem над Watch: строка <li> с именем.
import { createRoot } from "react-dom/client";
import { cassette, chain, lens } from "./finds.js";

const Lamp = () => <div className="lamp on" />;

const Watch = () => (
  <section>
    <Lamp />
    <h1>Опись</h1>
    <ul>
      <FindItem find={cassette} />
      <FindItem find={lens} />
      <FindItem find={chain} />
    </ul>
  </section>
);

const root = createRoot(document.querySelector(`#watch`));

root.render(<Watch />);
```

- **Пометка при входе (поля):**
  1. Пропсы — как атрибуты у тега, только значение любое: `{cassette}` отдаёт объект целиком.
  2. Все пропсы приходят одним объектом. `({ find })` берёт из него `find`, как `({ target })` в гл. 2.
- **Подсказки по щелчку:**
  1. В `Watch` уже три строки `<FindItem find={…} />`, а самого `FindItem` в файле нет.
  2. `FindItem` — компонент, как `Lamp`, только с пропсом: `({ find }) => разметка`.
  3. `const FindItem = ({ ____ }) => <li>{____.name}</li>;`
- **Эталонное решение** (новая строка над `Watch`, остальное как при входе):

```jsx
const FindItem = ({ find }) => <li>{find.name}</li>;
```

- **Она проверяет:** Она приносит со стола три находки по одной и кладёт под табло (нести). Агент смотрит снимок: в `<ul>` три `<li>`, их тексты — `кассета`, `линза`, `цепь`, в этом порядке. Совпало — она стоит у стола в свете.
  - **Почти:** `<li>кассета</li>` руками — три строки «кассета». Она держит линзу у табло и ждёт. Пометка: «Все три строки — кассета. Имя должно приходить пропсом».
- **Частые ошибки:**
  1. Запуск без `FindItem`:
     ```
     ReferenceError: FindItem is not defined
     строка 21
     ```
     - `ReferenceError` — обратились к имени, которого нет.
     - `FindItem is not defined` — `FindItem` не объявлен.

     Автомат выбит, табло гаснет. В `Watch` стоит `<FindItem />`, а такой функции в файле нет.

  2. Параметр без фигурных скобок:
     ```jsx
     const FindItem = (find) => <li>{find.name}</li>;
     ```
     Ошибки нет, три пустые строки. Полые импульсы, щуп на параметре: `find: { find: { id: 7, … } }`. В параметр пришли все пропсы одним объектом, имя находки лежит глубже. Нужно `({ find })`.

  3. Чужое имя пропса:
     ```jsx
     const FindItem = ({ cassette }) => <li>{cassette.name}</li>;
     ```
     ```
     TypeError: Cannot read properties of undefined (reading 'name')
     ```
     - `TypeError` — со значением сделали то, чего с ним делать нельзя.
     - `Cannot read properties of undefined` — пытались взять что-то у `undefined`, у «ничего».
     - `(reading 'name')` — а именно `name`.

     Автомат выбит, табло гаснет. Пропс называется так же, как атрибут: `find={…}`. Пропса `cassette` никто не отдавал.
- **Код профи:** Разницы в работе нет: `(props) => <li>{props.find.name}</li>` работает так же. `({ find })` короче читать: сразу видно, какие пропсы нужны компоненту. Можешь не пользоваться.
- **В мире:**
  - На столе три находки: `data-id` 7, 12, 23.
  - Запуск: импульс проходит через `FindItem` три раза — одна функция, три вызова, три строки на табло.
  - Щуп на строке табло: `<li>линза</li>`, компонент `FindItem`, пропсы `{ find: { id: 12, tag: "AB-012", name: "линза", … } }`.

### 20.5 Хрупкое (`find-fragile`)

- **Новое:** условный рендер `&&`
- **Опирается на:** пропсы (20.4), `&&`, truthy и falsy (гл. 3)
- **Файл(ы):** `watch.jsx`
- **Текст файла при входе:**

```jsx
// Хочу, чтобы хрупкие находки были помечены на табло.
//
// Дано:
// - у находки поле fragile: true или false
// - пометка: <b>хрупкое</b> в строке, после имени
// - {условие && <разметка />} рисует разметку,
//   только когда условие истинно
//
// Помечай только хрупкие.
import { createRoot } from "react-dom/client";
import { cassette, chain, lens } from "./finds.js";

const Lamp = () => <div className="lamp on" />;

const FindItem = ({ find }) => <li>{find.name}</li>;

const Watch = () => (
  <section>
    <Lamp />
    <h1>Опись</h1>
    <ul>
      <FindItem find={cassette} />
      <FindItem find={lens} />
      <FindItem find={chain} />
    </ul>
  </section>
);

const root = createRoot(document.querySelector(`#watch`));

root.render(<Watch />);
```

- **Пометка при входе (поля):**
  1. `&&` ты знаешь с гл. 3: если слева ложь, дальше он не смотрит. `false` React не рисует.
  2. `if` внутри разметки не работает: в `{…}` помещается только выражение.
- **Подсказки по щелчку:**
  1. Кассета и линза хрупкие, цепь — нет. В `finds.js` у них `fragile: true` и `false`.
  2. Строка теперь из двух частей: имя и пометка при условии. Условие — `find.fragile`.
  3. Строка `<li>` целиком:
     ```jsx
     <li>
       {find.name}
       {find.____ && <b>хрупкое</b>}
     </li>
     ```
     Круглые скобки вокруг `<li>` поставит `Shift+Alt+F`.
- **Эталонное решение** (`FindItem`, остальное как при входе):

```jsx
const FindItem = ({ find }) => (
  <li>
    {find.name}
    {find.fragile && <b>хрупкое</b>}
  </li>
);
```

- **Она проверяет:** Она берёт со стола каждую находку по очереди (трогать) и смотрит на табло. Агент проверяет строку этой находки: `<b>хрупкое</b>` есть ровно тогда, когда `fragile` равно `true`. Совпало — она кладёт находку обратно и берёт следующую. После третьей она стоит у стола.
  - **Почти:** пометка у всех трёх или ни у кого. Она так и стоит с находкой в руках у табло. Пометка на полях — по тому, что на табло: «Цепь помечена хрупкой, а у неё `fragile: false`» или «У кассеты `fragile: true`, а пометки нет».
- **Частые ошибки:**
  1. `if` в разметке:
     ```jsx
     <li>
       {find.name}
       {if (find.fragile) <b>хрупкое</b>}
     </li>
     ```
     Рубильник не встаёт в зацеп.
     ```
     Unexpected "if"
     строка 18
     ```
     - `Unexpected "if"` — здесь не ждали `if`.

     В фигурные скобки JSX кладут выражение, у которого есть значение. `if` — команда, значения у неё нет. [сверить с esbuild игры]

  2. Сравнение со строкой:
     ```jsx
     {find.fragile === `true` && <b>хрупкое</b>}
     ```
     Ошибки нет, пометок нет ни у кого. Щуп на `find.fragile`: `true` без кавычек. В гл. 3 значения из `dataset` были строками, а здесь JSON с сервера: пришёл настоящий `true`.

  3. Одиночный `&`:
     ```jsx
     {find.fragile & <b>хрупкое</b>}
     ```
     Ошибки нет, у каждой находки после имени `0`. Одиночный `&` — другой оператор, он считает числа. `0` React рисует, а `false` — нет. Запомни этот ноль: он вернётся в 20.11.
- **В мире:**
  - Пометка рисуется маленькой яркой табличкой после имени: CSS станции `.watch-board b { margin-left: 4px; }`.
  - Трасса: на строке с `&&` у цепи импульс гаснет — дальше `&&` не смотрит. У кассеты и линзы проходит до `<b>`, и пометка вспыхивает.

### 20.6 Кнопка «отнести» (`find-carry-log`)

- **Новое:** событие в JSX: `onClick`
- **Опирается на:** `addEventListener` и функция-обработчик (гл. 2), всплытие и делегирование (гл. 6), `console.log` (гл. 4)
- **Файл(ы):** `watch.jsx`
- **Текст файла при входе:**

```jsx
// Хочу, чтобы «отнести» печатало на ленте бирку находки.
//
// Дано:
// - в строке находки, в конце, кнопка
//   <button>отнести</button>
// - в JSX датчик — атрибут: onClick={функция}
//
// По нажатию печатай бирку находки на ленте.
import { createRoot } from "react-dom/client";
import { cassette, chain, lens } from "./finds.js";

const Lamp = () => <div className="lamp on" />;

const FindItem = ({ find }) => (
  <li>
    {find.name}
    {find.fragile && <b>хрупкое</b>}
  </li>
);

const Watch = () => (
  <section>
    <Lamp />
    <h1>Опись</h1>
    <ul>
      <FindItem find={cassette} />
      <FindItem find={lens} />
      <FindItem find={chain} />
    </ul>
  </section>
);

const root = createRoot(document.querySelector(`#watch`));

root.render(<Watch />);
```

- **Пометка при входе (поля):**
  1. `onClick={функция}` — как `` addEventListener(`click`, функция) ``, только прямо в разметке.
  2. Отдай функцию, а не вызов. React вызовет её сам, когда нажмут.
- **Подсказки по щелчку:**
  1. Кнопок на табло пока нет. Нужна клавиша в каждой строке, после пометки.
  2. У кнопки атрибут `onClick`, в нём стрелка, которая печатает `find.tag`.
  3. `<button onClick={() => console.log(____)}>отнести</button>`
- **Эталонное решение** (`FindItem`):

```jsx
const FindItem = ({ find }) => (
  <li>
    {find.name}
    {find.fragile && <b>хрупкое</b>}
    <button onClick={() => console.log(find.tag)}>
      отнести
    </button>
  </li>
);
```

- **Она проверяет:** Она нажимает «отнести» в строке линзы (нажимать — настоящий `click` по тому, что у неё под пальцем). Телетайп должен напечатать `AB-012` один раз. Она берёт со стола находку с этой биркой и несёт к ставню. Потом то же с кассетой: лента — `AB-007`. Обе бирки совпали — она ставит кассету у ставня рядом с линзой и стоит там.
  - **Почти:** лента напечатала все три бирки сразу при запуске, а на нажатие молчит (ошибка 1). Она нажимает, ничего не происходит, она стоит с рукой у табло. Пометка: «Лента печатала при запуске, а на нажатие молчит. В `onClick` попала не функция».
- **Частые ошибки:**
  1. Вызов вместо функции:
     ```jsx
     <button onClick={console.log(find.tag)}>отнести</button>
     ```
     Ошибки нет. При запуске телетайп печатает `AB-007`, `AB-012`, `KL-023`, на нажатие — тишина. Скобки вызвали `console.log` сразу, при рисовании, а в `onClick` попал его результат: `undefined`.

  2. Имя события по-HTML:
     ```jsx
     <button onclick={() => console.log(find.tag)}>
     ```
     Кнопки мёртвые. Телетайп:
     ```
     Invalid event handler property `onclick`. Did you mean `onClick`?
     ```
     - ``Invalid event handler property `onclick` `` — нет такого датчика: `onclick`.
     - ``Did you mean `onClick`? `` — может, `onClick`?

     В JSX имена событий пишутся с большой буквы в середине: `onClick`, `onInput`.

  3. Код строкой, как в HTML:
     ```jsx
     <button onClick="console.log(find.tag)">
     ```
     Кнопки мёртвые. Телетайп:
     ```
     Expected `onClick` listener to be a function, instead got a value of `string` type.
     ```
     - ``Expected `onClick` listener to be a function`` — в `onClick` ждали функцию,
     - ``instead got a value of `string` type`` — а пришла строка.

     В HTML код пишут в атрибут строкой. В JSX — саму функцию, в фигурных скобках.
- **В мире:**
  - Клавиши «отнести» рисуются спрайтом `key` из гл. 9: отжата, нажата.
  - **Щуп на клавише датчика не находит.** Щуп на табло `#watch`: пучок датчиков, по одному на тип события (`click`, `input`, `keydown` и другие). Это делегирование из гл. 6, сделанное за тебя: React вешает датчики на корень, а не на каждую кнопку.
  - На нажатие импульс поднимается от клавиши к корню `#watch` (всплытие, как в Архиве), на корне вспыхивает датчик `click`, потом строка со стрелкой, стучит телетайп.

### 20.7 Заметка на бирке (`find-open`)

- **Новое:** состояние: `useState`
- **Опирается на:** `onClick` (20.6), `&&` в JSX (20.5), деструктуризация массива (гл. 5), функция с телом и `return` (гл. 3)
- **Файл(ы):** `watch.jsx`
- **Текст файла при входе:**

```jsx
// Хочу, чтобы карточка раскрывалась и показывала заметку.
//
// Дано:
// - у находки есть note: что написано на бирке
// - имя находки — тоже кнопка: щелчок раскрывает
//   и закрывает карточку
// - раскрытая карточка показывает <p>{find.note}</p>
// - память компонента:
//   const [x, setX] = useState(начало);
//   x — что сейчас, setX(новое) — запомнить
//   и нарисовать заново
//
// Помни в FindItem, раскрыта ли карточка.
import { useState } from "react";
import { createRoot } from "react-dom/client";
import { cassette, chain, lens } from "./finds.js";

const Lamp = () => <div className="lamp on" />;

const FindItem = ({ find }) => (
  <li>
    {find.name}
    {find.fragile && <b>хрупкое</b>}
    <button onClick={() => console.log(find.tag)}>
      отнести
    </button>
  </li>
);

const Watch = () => (
  <section>
    <Lamp />
    <h1>Опись</h1>
    <ul>
      <FindItem find={cassette} />
      <FindItem find={lens} />
      <FindItem find={chain} />
    </ul>
  </section>
);

const root = createRoot(document.querySelector(`#watch`));

root.render(<Watch />);
```

- **Пометка при входе (поля):**
  1. Обычная переменная живёт один вызов функции. Память, которая переживает перерисовку, — `useState`.
  2. `setOpen` не меняет `open` сразу. Он запоминает новое и просит React вызвать `FindItem` ещё раз.
- **Подсказки по щелчку:**
  1. Заметки уже лежат в `find.note`, а на табло их не видно: карточки ничего не помнят.
  2. Память `open`, сначала `false`. Щелчок по имени — `setOpen(!open)`. Заметка — при условии `open`, через `&&`.
  3. Компоненту с памятью нужно тело: сначала память, потом `return` с разметкой.
     ```jsx
     const FindItem = ({ find }) => {
       const [open, setOpen] = useState(____);

       return (
         <li>
           <button onClick={() => setOpen(____)}>
             {find.name}
           </button>
           {find.fragile && <b>хрупкое</b>}
           {____ && <p>{find.note}</p>}
           …кнопка «отнести», как была
         </li>
       );
     };
     ```

- **Эталонное решение** (`FindItem`):

```jsx
const FindItem = ({ find }) => {
  const [open, setOpen] = useState(false);

  return (
    <li>
      <button onClick={() => setOpen(!open)}>
        {find.name}
      </button>
      {find.fragile && <b>хрупкое</b>}
      {open && <p>{find.note}</p>}
      <button onClick={() => console.log(find.tag)}>
        отнести
      </button>
    </li>
  );
};
```

- **Она проверяет:** Она нажимает на имя кассеты: в строке кассеты появляется `<p>` с заметкой, в других строках нет. Нажимает ещё раз — заметка исчезает. Открывает линзу: заметка линзы есть, кассета закрыта — у каждой карточки своя память. Всё совпало — она оставляет линзу раскрытой и стоит у табло.
  - **Почти:** обычная переменная (ошибка 1). Импульс бежит, а табло не меняется. Она нажимает трижды и опускает руку. Пометка: «Импульс дошёл, а табло не перерисовалось: про обычную переменную React не знает».
- **Частые ошибки:**
  1. Обычная переменная:
     ```jsx
     let open = false;
     // …
     <button onClick={() => (open = !open)}>
     ```
     Ошибки нет. Импульс доходит до строки, щуп: `open: true`, а табло прежнее. React не видит обычную переменную, а при следующем вызове `FindItem` она снова `false`. Память, которая переживает перерисовку, — `useState`.

  2. Вызов вместо функции:
     ```jsx
     <button onClick={setOpen(!open)}>{find.name}</button>
     ```
     ```
     Uncaught Error: Too many re-renders. React limits the number of renders to prevent an infinite loop.
     ```
     - `Too many re-renders` — слишком много перерисовок.
     - `React limits the number of renders` — React ограничивает их число,
     - `to prevent an infinite loop` — чтобы не было бесконечного цикла.

     Импульс несколько раз проносится по кругу через `FindItem`, потом тяжёлый щелчок: автомат выбит, табло гаснет. `setOpen` вызвался прямо при рисовании, он просит нарисовать заново, и снова. В `onClick` нужна стрелка: `() => setOpen(!open)`.

  3. Присвоить напрямую:
     ```jsx
     <button onClick={() => (open = true)}>
     ```
     ```
     TypeError: Assignment to constant variable.
     ```
     - `Assignment to constant variable` — присваивание константе.

     Выбита только эта ветка (ошибка внутри обработчика, §3.3): датчик слушает дальше. `open` меняют только через `setOpen`.
- **Код профи:** Разницы в работе нет: можно писать `setOpen((open) => !open)`. Здесь одно нажатие — одно обновление, результат тот же.
- **В мире:**
  - Память — не новая вещь. Щуп на строке табло показывает её рядом с пропсами: `open: false`, как раздел hooks в React DevTools.
  - Нажатие: импульс от клавиши к корню, вспыхивает строка с `setOpen`, и импульс снова проходит через `FindItem` этой строки. Вспыхивают строки функции, а на табло вспыхивает только новый `<p>`: агент видит, что React добавил один узел.

### 20.8 Вся опись ночи (`find-list`)

- **Новое:** список из массива и `key`
- **Опирается на:** `map` (гл. 5), пропсы (20.4), состояние (20.7), `export` (гл. 17)
- **Файл(ы):** `watch.jsx`; под корпусом `main.jsx` станции
- **Текст файла при входе:**

```jsx
// Хочу, чтобы на табло была вся опись ночи.
//
// Дано:
// - станция сама рисует <Watch finds={…} />:
//   finds — массив находок с сервера, сколько угодно
// - JSX рисует и массив вещей:
//   {finds.map((find) => …)}
// - у каждой вещи из массива пропс key — метка,
//   своя в этом списке; у находки есть id
//
// Нарисуй FindItem на каждую находку из finds.
import { useState } from "react";

const Lamp = () => <div className="lamp on" />;

const FindItem = ({ find }) => {
  const [open, setOpen] = useState(false);

  return (
    <li>
      <button onClick={() => setOpen(!open)}>
        {find.name}
      </button>
      {find.fragile && <b>хрупкое</b>}
      {open && <p>{find.note}</p>}
      <button onClick={() => console.log(find.tag)}>
        отнести
      </button>
    </li>
  );
};

export const Watch = ({ finds }) => (
  <section>
    <Lamp />
    <h1>Опись</h1>
    <ul></ul>
  </section>
);
```

- **Пометка при входе (поля):**
  1. `map` из гл. 5 делает из массива находок массив строк `<FindItem />`. Массив вещей React рисует подряд.
  2. По `key` React узнаёт строку, когда список меняется. Бери `id` находки: номер места сдвигается вместе со списком.
- **Подсказки по щелчку:**
  1. Табло пустое, а находок на столе четыре. Под корпусом видно: станция отдаёт `Watch` весь массив.
  2. `finds.map` превращает каждую находку в `<FindItem find={find} />`, и у каждой `key`.
  3. Внутри `<ul>`:
     ```jsx
     {finds.map((find) => (
       <FindItem key={____} find={find} />
     ))}
     ```

- **Эталонное решение** (`Watch`):

```jsx
export const Watch = ({ finds }) => (
  <section>
    <Lamp />
    <h1>Опись</h1>
    <ul>
      {finds.map((find) => (
        <FindItem key={find.id} find={find} />
      ))}
    </ul>
  </section>
);
```

- **Она проверяет:** На табло четыре строки: кассета, линза, цепь, поплавок. Она раскрывает кассету (нажимает на имя). Тут море задвигает под ставень ракушку, и станция рисует `Watch` заново: ракушка — первой в массиве. Раскрытой должна остаться кассета, ракушка — закрытой. Так и есть — она подбирает ракушку у ставня и несёт к столу.
  - **Почти:** `key` — номер места или его нет вовсе (ошибки 1 и 2). Раскрыта ракушка, кассета закрыта. Она стоит у табло, рука на строке кассеты. Пометка: «Раскрыта не та. React узнаёт строку по `key`, а у тебя это место в списке. Наверх пришла новая находка, и все места сдвинулись».
- **Частые ошибки:**
  1. Без `key`:
     ```jsx
     {finds.map((find) => <FindItem find={find} />)}
     ```
     Табло рисуется, телетайп печатает:
     ```
     Each child in a list should have a unique "key" prop.

     Check the render method of `Watch`. See https://react.dev/link/warning-keys for more information.
     ```
     - `Each child in a list should have a unique "key" prop` — у каждой вещи в списке должен быть свой `key`.
     - ``Check the render method of `Watch` `` — смотри, что рисует `Watch`.
     - `See https://react.dev/…` — подробно на сайте React.

     Без `key` React узнаёт строки по месту, и когда список сдвигается, путает их: раскрытой оказывается ракушка.

  2. Номер места:
     ```jsx
     {finds.map((find, i) => (
       <FindItem key={i} find={find} />
     ))}
     ```
     Предупреждения нет, а баг тот же: раскрыта ракушка. Тихая ошибка, хуже громкой. Номер места — не имя вещи: новая находка наверху сдвинула все номера.

  3. Фигурные скобки без `return`:
     ```jsx
     {finds.map((find) => {
       <FindItem key={find.id} find={find} />;
     })}
     ```
     Ошибки нет, список пустой. Импульс обходит четыре находки и каждый раз возвращается полым. С фигурными скобками стрелка без `return` ничего не отдаёт.

  4. `forEach` вместо `map`:
     ```jsx
     {finds.forEach((find) => (
       <FindItem key={find.id} find={find} />
     ))}
     ```
     Ошибки нет, список пустой. `forEach` ничего не возвращает, рисовать нечего. `map` отдаёт новый массив.

  5. `key` внутри `FindItem`, на `<li>`: телетайп печатает то же предупреждение, что в ошибке 1, и раскрыта ракушка. `key` ставят там, где массив: на `<FindItem />` в `map`.
- **Код профи:** Это и есть правильный ответ, и разница измерима. С `key={find.id}` море добавило одну строку: агент видит один новый узел, на табло вспыхивает только ракушка. С номером места React переписал текст во всех строках и добавил одну в конец: вспыхивает всё табло, а раскрытая память осталась на первом месте. Подойдёт любая метка, которая у находки не меняется и не повторяется: `id` или `tag`.
- **В мире:**
  - Под корпусом `main.jsx` станции:
    ```jsx
    import { createRoot } from "react-dom/client";
    import { finds } from "./finds.js";
    import { Watch } from "./watch.jsx";

    const root = createRoot(document.querySelector(`#watch`));

    root.render(<Watch finds={finds} />);
    ```
    Когда море приносит ракушку, станция вызывает `render` ещё раз: `<Watch finds={[shell, ...finds]} />`. Это обычный код, его видно.
  - Строки `createRoot` из твоего файла переехали сюда: дальше табло рисует станция, а ты пишешь, *что* на нём.
  - Ракушка — новая вещь на полу у ставня: `<div class="find" data-id="52">`, её добавляет станция.
  - В этой проверке станция отдаёт четыре находки ночи, без фляги. Тогда ракушка и раскрытая заметка кассеты как раз умещаются на табло. Фляга вернётся в 20.9, где переполнение и есть урок.

### 20.9 Одна раскрытая (`find-accordion`)

- **Новое:** подъём состояния
- **Опирается на:** `useState` (20.7), пропсы (20.4), `onClick` (20.6), `===` (гл. 3)
- **Файл(ы):** `watch.jsx`
- **Текст файла при входе:**

```jsx
// Хочу, чтобы раскрытой была только одна карточка.
//
// Дано:
// - две раскрытые не влезают: нижняя строка уходит
//   под рамку табло
// - память, нужную многим, держит их общий родитель
//   и раздаёт пропсами: значение и функцию
//
// Помни в Watch id раскрытой. FindItem отдай open
// и onOpen.
import { useState } from "react";

const Lamp = () => <div className="lamp on" />;

const FindItem = ({ find }) => {
  const [open, setOpen] = useState(false);

  return (
    <li>

        {find.name}
      </button>
      {find.fragile && <b>хрупкое</b>}
      {open && <p>{find.note}</p>}
      <button onClick={() => console.log(find.tag)}>
        отнести
      </button>
    </li>
  );
};

export const Watch = ({ finds }) => (
  <section>
    <Lamp />

```

- **Пометка при входе (поля):** Поднять состояние: память переезжает к родителю, а детям — значение и функция, чтобы её менять.
- **Подсказки по щелчку:**
  1. Раскрой сам кассету и линзу: фляга внизу уходит под рамку. Каждая карточка помнит своё и про соседей не знает.
  2. Память `openId` — в `Watch`, сначала `null`. Карточке — `open` (её ли это id) и `onOpen` (запомнить её id).
  3. `Watch` получает тело, как `FindItem` в 20.7: память, потом `return` с разметкой. В нём:
     ```jsx
     const [openId, setOpenId] = useState(null);

     <FindItem
       key={find.id}
       find={find}
       open={find.id === ____}
       onOpen={() => setOpenId(____)}
     />
     ```
     В `FindItem`: `({ find, open, onOpen })` и `<button onClick={____}>`. Своя память `open` в `FindItem` больше не нужна.
- **Эталонное решение:**

```jsx
const FindItem = ({ find, open, onOpen }) => (
  <li>
    <button onClick={onOpen}>{find.name}</button>
    {find.fragile && <b>хрупкое</b>}
    {open && <p>{find.note}</p>}
    <button onClick={() => console.log(find.tag)}>
      отнести
    </button>
  </li>
);

export const Watch = ({ finds }) => {
  const [openId, setOpenId] = useState(null);

  return (
    <section>
      <Lamp />
      <h1>Опись</h1>
      <ul>
        {finds.map((find) => (
          <FindItem
            key={find.id}
            find={find}
            open={find.id === openId}
            onOpen={() => setOpenId(find.id)}
          />
        ))}
      </ul>
    </section>
  );
};
```

- **Она проверяет:** Находок пять, последняя — фляга. Она раскрывает кассету, потом линзу: кассета должна закрыться, в списке один `<p>`. Потом она тянется к «отнести» во флягиной строке: под пальцем (`elementFromPoint`) должна оказаться эта клавиша. Лента печатает `KL-040`, она несёт флягу к ставню.
  - **Почти:** раскрыты две, фляга ушла под рамку. Под пальцем рамка табло, нажатие ни во что не попадает. Она стоит, рука поднята к табло. Пометка: «Под рукой у неё рамка, а не клавиша фляги: две раскрытые карточки вытолкнули строку».
- **Частые ошибки:**
  1. `open` получает сам id:
     ```jsx
     open={openId}
     ```
     Ошибки нет. После первого нажатия раскрыты все пять: у каждой `open: 7`, а 7 — истина. Табло переполнено. `open` должен быть «да или нет»: эта ли карточка раскрыта. Сравни: `find.id === openId`.

  2. Старая память осталась в `FindItem`: `const [open, setOpen] = useState(false)` и `onClick={() => setOpen(!open)}`. Ошибки нет, раскрываются по-прежнему две. Карточка слушает свою память, а не пропс. Память теперь одна, у `Watch`: в `FindItem` её быть не должно.

  3. Вызов вместо функции в `FindItem`:
     ```jsx
     <button onClick={onOpen()}>{find.name}</button>
     ```
     Сразу после запуска раскрыта фляга, нажатия мёртвые. Телетайп:
     ```
     Cannot update a component (`Watch`) while rendering a different component (`FindItem`). To locate the bad setState() call inside `FindItem`, follow the stack trace as described in https://react.dev/link/setstate-in-render
     ```
     - ``Cannot update a component (`Watch`)`` — нельзя менять `Watch`,
     - ``while rendering a different component (`FindItem`)`` — пока рисуется другой компонент, `FindItem`.
     - ``To locate the bad setState() call inside `FindItem` `` — чтобы найти неверный вызов в `FindItem`, смотри стек.

     `onOpen()` вызвался при рисовании каждой строки, последней была фляга. В `onClick` отдают саму функцию: `onClick={onOpen}`.
- **В мире:**
  - Щуп на табло: у `Watch` память `openId: 12`; у строки — пропсы `open: true`, `onOpen: ƒ`.
  - Нажатие на имя: импульс от клавиши к корню, в строку `onOpen` у `FindItem`, оттуда в `setOpenId` у `Watch`. Вспыхивают строки `Watch`, потом `FindItem` всех пяти строк: React вызвал их заново. А на табло меняются два узла: один `<p>` ушёл, другой появился.
  - Повторное нажатие карточку теперь не закрывает: `setOpenId(find.id)` запоминает тот же `id`. Она проверяет только, что раскрыта одна, и для этой задачи так и надо.

### 20.10 Отнесённая уходит (`find-carry`)

- **Новое:** неизменяемое обновление: `[...x, новое]`
- **Опирается на:** подъём состояния (20.9), `[...список]` (гл. 5), `filter` (гл. 5), `includes` у строк (гл. 7)
- **Файл(ы):** `watch.jsx`
- **Текст файла при входе** (под строками задачи — эталон 20.9 целиком):

```jsx
// Хочу, чтобы отнесённая находка уходила с табло.
//
// Дано:
// - в Watch память carried — id отнесённых, сначала []
// - массив в памяти не меняют, а дают новый:
//   setX([...x, новое])
// - includes есть и у массива: [7, 12].includes(7)
//
// «Отнести» запоминает id. На табло — неотнесённые.
```

- **Пометка при входе (поля):** React сверяет: тот же это массив или новый. Тот же, даже изменённый, для него значит «ничего не случилось».
- **Подсказки по щелчку:**
  1. Нажми «отнести» сам: лента печатает бирку, а строка на месте. Отнесённых пока никто не помнит.
  2. Память `carried` — в `Watch`. `onCarry` в `FindItem` — как `onOpen`. Новый массив — `[...carried, find.id]`. Рисуй `left`: `finds` без отнесённых.
  3. В `Watch`:
     ```jsx
     const [carried, setCarried] = useState([]);
     const left = finds.filter(
       (find) => !carried.____(find.id),
     );

     onCarry={() => setCarried([...____, find.id])}
     ```
     В `FindItem`: пропс `onCarry` и `<button onClick={onCarry}>отнести</button>`. В `<ul>` — `left.map`.
- **Эталонное решение:**

```jsx
const FindItem = ({ find, open, onOpen, onCarry }) => (
  <li>
    <button onClick={onOpen}>{find.name}</button>
    {find.fragile && <b>хрупкое</b>}
    {open && <p>{find.note}</p>}
    <button onClick={onCarry}>отнести</button>
  </li>
);

export const Watch = ({ finds }) => {
  const [openId, setOpenId] = useState(null);
  const [carried, setCarried] = useState([]);
  const left = finds.filter(
    (find) => !carried.includes(find.id),
  );

  return (
    <section>
      <Lamp />
      <h1>Опись</h1>
      <ul>
        {left.map((find) => (
          <FindItem
            key={find.id}
            find={find}
            open={find.id === openId}
            onOpen={() => setOpenId(find.id)}
            onCarry={() =>
              setCarried([...carried, find.id])
            }
          />
        ))}
      </ul>
    </section>
  );
};
```

- **Она проверяет:** Она нажимает «отнести» у кассеты: строка кассеты должна исчезнуть, остальные остаться. Она несёт кассету к ставню. Потом цепь, потом линзу — порядок любой, каждый раз уходит ровно та строка. После третьей она стоит у ставня рядом с тремя находками.
  - **Почти:** `push` (ошибка 1). Строка на месте. Она нажимает ещё раз, опускает руку и стоит у стола. Пометка: «Импульс дошёл, а табло не перерисовалось: в память положили тот же массив».
- **Частые ошибки:**
  1. Изменить на месте:
     ```jsx
     onCarry={() => {
       carried.push(find.id);
       setCarried(carried);
     }}
     ```
     Ошибки нет. Щуп на `carried`: `[7]` — массив изменился, а табло прежнее. Самые неприятные ошибки — молчаливые. Массив тот же, только изменённый, и React решает, что перерисовывать нечего.

  2. Результат `push` в память:
     ```jsx
     onCarry={() => setCarried(carried.push(find.id))}
     ```
     ```
     TypeError: carried.includes is not a function
     ```
     - `carried.includes` — у `carried` взяли `includes`,
     - `is not a function` — а это не функция.

     Автомат выбит, табло гаснет. `push` возвращает не массив, а новую длину. В память попало число `1`, а у числа `includes` нет.

  3. Рисуешь всё равно `finds`: `{finds.map(…)}`. Ошибки нет, строки не уходят, хотя щуп на `carried` показывает `[7]`. Память помнит отнесённое, а рисуется весь список. Рисуй `left`.
- **Код профи:** Разницы в работе нет: можно писать `setCarried((carried) => [...carried, find.id])`. Каждое нажатие — отдельный импульс и одно обновление, результат тот же.
- **В мире:**
  - Находку со стола переносит станция: `<div class="find" data-id="7">` переезжает к ставню, когда она её несёт. Это код станции, его видно под корпусом.
  - Нажатие: React убирает один `<li>`, на табло гаснет только эта строка.

### 20.11 Всё у проёма (`all-carried`)

- **Новое:** производное состояние
- **Опирается на:** память `carried` и `left` (20.10), `&&` в JSX (20.5), компонент `Lamp` (20.2)
- **Файл(ы):** `watch.jsx`
- **Текст файла при входе** (под строками задачи — эталон 20.10 целиком):

```jsx
// Хочу, чтобы загоралась лампа, когда всё у проёма.
//
// Дано:
// - сигнал — второй <Lamp /> сразу после заголовка
//
// Лампа горит, когда на табло не осталось находок.
```

- **Пометка при входе (поля):** То, что можно вычислить из памяти, отдельно не хранят: вычисляют при каждой перерисовке.
- **Подсказки по щелчку:**
  1. Отнеси сам все находки: табло пустеет, а сигнала нет.
  2. Условие уже есть: пуст ли `left`. Отдельная память для лампы не нужна.
  3. `{left.length === ____ && <Lamp />}`
- **Эталонное решение** (в `Watch`):

```jsx
const done = left.length === 0;

// …

<h1>Опись</h1>
{done && <Lamp />}
```

Запись прямо в разметке, `{left.length === 0 && <Lamp />}`, тоже верна.
- **Она проверяет:** Она относит пять находок по одной. После каждого нажатия, кроме последнего, сигнальной лампы нет. После последнего — горит. Она ставит флягу к остальным, садится на пол у ставня рядом с находками, лицом к ставню, и ждёт.
  - **Почти:** отдельная память для лампы (ошибка 2). После последней находки табло пустое, лампы нет. Она стоит у пустого табло. Пометка: «Табло пустое, а лампа не зажглась. Лишняя память отстаёт на шаг».
- **Частые ошибки:**
  1. Длина как условие:
     ```jsx
     {left.length && <Lamp />}
     ```
     Ошибки нет. Лампа горит с самого начала, пока находки есть. А в конце вместо лампы на табло одинокий `0`. `&&` отдаёт левую часть, если она ложь, и `0` React рисует. Вот он, ноль из 20.5.

  2. Отдельная память:
     ```jsx
     const [done, setDone] = useState(false);
     // …
     onCarry={() => {
       setCarried([...carried, find.id]);
       setDone(left.length === 0);
     }}
     ```
     Ошибки нет. После последней находки лампа не горит и уже не загорится. `left` в обработчике — из прошлой перерисовки: в нём ещё лежит та, которую только что отнесли. Вычисляй лампу из памяти, а не храни.

  3. Сравнение с пустым массивом:
     ```jsx
     {left === [] && <Lamp />}
     ```
     Ошибки нет, лампа не горит никогда. Два массива равны, только если это один и тот же массив. Пустоту проверяют длиной.
- **Код профи:** Разница измерима: с лишней памятью лампа отстаёт на шаг и в конце не горит. Профи хранит минимум, остальное вычисляет.

  Вторая пометка после успеха, про утреннюю привычку: «`classList.add` на вещи React живёт, пока React сам не перепишет её `className`. Он запишет своё, а твой класс сотрёт. Хочешь менять вещь — меняй память». Проверено на React 19.3: `class="row mine"` после смены `className` стало `class="row open"`; пока `className` не менялся, `mine` оставался.
- **В мире:**
  - Вторая лампа загорается рядом с «Опись», на пол у стола ложится второе пятно света.
  - Щуп на `Watch`: память `openId` и `carried: [7, 23, 12, 31, 40]`. Лампы в памяти нет: `done` вычисляется заново на каждой перерисовке.
  - При успехе файл `watch.jsx` уходит на монитор у вахтенного стола, экран загорается твоим кодом. Табло остаётся гореть: пустая опись и две лампы. Под ставнем, у самого пола, проступает первая серая полоска: прошло время.
  - На полях после паузы: «Работает. Под корпусом всё те же `createElement`, `append` и `classList`. Их делает React, а ты пишешь, какой должна быть вещь».

### 21.1 Опись в журнале (`journal-types`)

- **Опирается на:** пропсы (20.4), `type` и типы функций (гл. 19), рубильник с проверкой типов (гл. 19)
- **Файл(ы):** `src/components/FindItem.tsx`; README, «Опись в журнале»
- **История в README:**

```md
### Опись в журнале

Как вахтенный, я хочу видеть в журнале карточки
находок, как на табло вахты.
Готово, когда: рубильник встаёт в зацеп, в журнале
карточки ночи, «отнести» работает.
```

- **Текст файла при входе:**

```tsx
// Хочу, чтобы карточка находки жила в журнале на TS.
//
// История: README, «Опись в журнале».
//
// Дано:
// - тип пропсов — объект: type Props = { имя: Тип };
// - его ставят на параметр: ({ find }: Props)
// - функция без ответа: () => void
//
// Опиши пропсы FindItem, чтобы рубильник встал в зацеп.
import type { Find } from "../types.ts";

export const FindItem = ({ find, onCarry }) => (
  <li>
    {find.name}
    {find.fragile && <b>хрупкое</b>}
    <button onClick={onCarry}>отнести</button>
  </li>
);
```

- **Пометка при входе (поля):**
  1. README — описание проекта. Истории в нём — задачи словами того, кто будет пользоваться: «Как вахтенный, я хочу…».
  2. Пропсы — параметр функции, и у него тоже бывает тип, как `(percent: number)` в гл. 19.
  3. `import type` берёт из файла только тип. Рубильник проверяет весь проект: засечка может стоять в другом файле.
- **Подсказки по щелчку:**
  1. Рубильник отскакивает. На полях две TS7031: про `find` и про `onCarry`.
  2. Опиши тип `Props`: `find` — это `Find`, `onCarry` — функция без ответа. Поставь его на параметр.
  3. Над компонентом и в параметре:
     ```tsx
     type Props = { find: ____; onCarry: () => ____ };

     export const FindItem = ({ find, onCarry }: ____) => (
     ```

- **Эталонное решение** (две строки: тип и `: Props`):

```tsx
import type { Find } from "../types.ts";

type Props = { find: Find; onCarry: () => void };

export const FindItem = ({ find, onCarry }: Props) => (
  <li>
    {find.name}
    {find.fragile && <b>хрупкое</b>}
    <button onClick={onCarry}>отнести</button>
  </li>
);
```

Prettier оставляет короткий тип в одну строку. Если записать его столбиком, оставит столбиком: так он обходится со всеми объектами.
- **Она проверяет:** Рубильник встаёт в зацеп, по разбору кода в файле нет `any`, `as` и `!` (как в гл. 19). На табло карточки ночи. Она нажимает «отнести» у линзы: уходит `PATCH /api/finds/12`, ответ `200`, строка гаснет. Она кладёт руку на пульт: на узком экране линзы тоже нет — данные одни.
  - **Почти:** `find: any`. Зацеп есть, но станция находит `any` в разборе. Пометка: «`any` выключает проверку: зацеп есть, а типы больше ничего не ловят».
- **Частые ошибки:**
  1. Без типа (так файл и входит):
     ```
     src/components/FindItem.tsx(13,28): error TS7031: Binding element 'find' implicitly has an 'any' type.
     src/components/FindItem.tsx(13,34): error TS7031: Binding element 'onCarry' implicitly has an 'any' type.
     ```
     - `Binding element 'find'` — имя `find` в фигурных скобках параметра.
     - `implicitly has an 'any' type` — неявно получило тип `any`, «что угодно».

     TS не знает, что придёт в `find`, а в строгом режиме «что угодно» не принимается.

  2. Тип не тот:
     ```tsx
     type Props = { find: string; onCarry: () => void };
     ```
     ```
     src/components/FindItem.tsx(17,11): error TS2339: Property 'name' does not exist on type 'string'.
     src/components/FindItem.tsx(18,11): error TS2339: Property 'fragile' does not exist on type 'string'.
     src/components/FindList.tsx(23,11): error TS2322: Type 'Find' is not assignable to type 'string'.
     ```
     - `Property 'name' does not exist` — свойства `name` нет
     - `on type 'string'` — у строки.

     `find` — объект находки, его тип `Find` из `types.ts`. Третья засечка — в `FindList.tsx`: он отдаёт `Find`, а тип ждёт строку.

  3. Забыт `onCarry` в `Props`: `type Props = { find: Find };`
     ```
     src/components/FindItem.tsx(15,34): error TS2339: Property 'onCarry' does not exist on type 'Props'.
     src/components/FindList.tsx(24,11): error TS2322: Type '{ key: number; find: Find; onCarry: () => Promise<void>; }' is not assignable to type 'IntrinsicAttributes & Props'.
       Property 'onCarry' does not exist on type 'IntrinsicAttributes & Props'.
     ```
     Параметр берёт из пропсов то, чего в их типе нет, а `FindList` отдаёт пропс, которого тип не знает. Тип описывает все пропсы.

  4. Лишний обязательный пропс, например `open: boolean` из гл. 20. Засечка не в твоём файле, а в `FindList.tsx`:
     ```
     src/components/FindList.tsx(21,10): error TS2741: Property 'open' is missing in type '{ key: number; find: Find; onCarry: () => Promise<void>; }' but required in type 'Props'.
     ```
     - `Property 'open' is missing` — не хватает свойства `open`
     - `in type '{ key: number; find: Find; … }'` — в том, что передал `FindList`,
     - `but required in type 'Props'` — а твой тип его требует.

     Тип проверяет и того, кто вызывает компонент. Ошибка дошла до терминала, а не до неё.
- **Код профи:** Разницы в работе нет: типы стираются перед запуском, тип прямо в параметре работает так же. Отдельный `type Props` короче читать, и его видно одним взглядом. На полях, как в гл. 19: «Типы не делают код быстрее. Они переносят ошибку из её рук в твой терминал».
- **В мире:**
  - Табло `#watch` рисует журнал: корень теперь в `main.tsx` проекта. Переносной пульт — вторая настоящая страница шириной 64 (гл. 12) с тем же проектом.
  - Рубильник: сначала проверка типов. С ошибкой он отскакивает, засечка на `find` в строке 13. Первая строка-задача остаётся в файле и после решения: это его описание, как в настоящем коде. Под корпусом — JS после стирания типов: на месте `: Props` пробелы, номера строк твои.
  - «Отнести»: у строки с запросом кромка «жду», импульс возвращается со `status: 200`, строка списка гаснет.

- **Пометка при входе (поля):**

  2. `ReactNode` — тип «всё, что React умеет нарисовать»: разметка, текст, список.
- **Подсказки по щелчку:**
  1. На стене журнал без рамки и заголовка, на пульте тоже.
  2. `Page` получает `title` и `children` и кладёт `children` в `<section>` под `<h1>`. В `App` — `<Page title="Журнал моря">…</Page>` вокруг списка.
  3. В `Page.tsx`:
     ```tsx
     type Props = {
       title: string;
       children: ____;
     };

     export const Page = ({ title, children }: Props) => (
       <section className="page">
         <h1>{____}</h1>
         {____}
       </section>
     );
     ```
     В `App.tsx` — `<Page title="Журнал моря">` вокруг списка и строка `import`, как у `FindList`.
- **Эталонное решение:**

```tsx
import type { ReactNode } from "react";

type Props = {
  title: string;
  children: ReactNode;
};

export const Page = ({ title, children }: Props) => (
  <section className="page">
    <h1>{title}</h1>
    {children}
  </section>
);
```

```tsx
import { FindList } from "./components/FindList.tsx";
import { Page } from "./components/Page.tsx";
import { finds } from "./finds.ts";

export const App = () => (
  <Page title="Журнал моря">
    <FindList finds={finds} />
  </Page>

```

- **Она проверяет:** На табло и на пульте: `section.page` с `<h1>` «Журнал моря», а список `<ul>` лежит внутри этой `section`. На пульте рамка не вылезает за край: ни у одной вещи `scrollWidth > clientWidth` (гл. 12). Она нажимает «отнести» у цепи на пульте — строка уходит. Она убирает руку от пульта.
  - **Почти:** рамка с заголовком, а внутри пусто (ошибка 1). Она стоит над пустым журналом. Пометка: «Рамка есть, а внутри пусто: `children` пришли и не нарисованы».
- **Частые ошибки:**
  1. `children` не поставлен в разметку. Ошибки нет, TS молчит: неиспользованный пропс — не ошибка. Рамка пустая. То, что пришло между тегами, рисуется только там, где стоит `{children}`.

  2. `children` нет в типе:
     ```tsx
     type Props = {
       title: string;
     };
     ```
     Засечка в `App.tsx`:
     ```
     src/App.tsx(6,4): error TS2322: Type '{ children: Element; title: string; }' is not assignable to type 'IntrinsicAttributes & Props'.
       Property 'children' does not exist on type 'IntrinsicAttributes & Props'.
     ```
     - `Type '{ children: Element; title: string; }'` — то, что передал `App`: заголовок и содержимое,
     - `is not assignable to type '… & Props'` — не подходит под твой тип.
     - `Property 'children' does not exist` — свойства `children` в нём нет.

     Всё, что между тегами, приходит пропсом `children`, и тип должен его назвать.

  3. `Page` не взят в `import` в `App.tsx`:
     ```
     src/App.tsx(5,4): error TS2304: Cannot find name 'Page'.
     src/App.tsx(7,5): error TS2304: Cannot find name 'Page'.
     ```
     - `Cannot find name 'Page'` — имени `Page` в файле нет.

     Имя из другого файла сначала берут через `import`. Засечек две: на открывающем теге и на закрывающем.
- **В мире:**
  - CSS станции для рамки, его видно под корпусом: `.page { border: 1px solid; padding: 2px; }`. Рамка рисуется тонкой линией по настоящему прямоугольнику (`getBoundingClientRect`), на стене и на пульте разной ширины.
  - Щуп на рамке: `<section class="page">`, компонент `Page`, пропсы `title: "Журнал моря"`, `children: <FindList />`.

### 21.3 Записать находку (`journal-form`)

- **Новое:** управляемое поле
- **Опирается на:** `useState` (20.7), `onChange` как датчик `input` (гл. 2, 20.6), форма, `submit`, `pattern` (гл. 10), `toUpperCase` (гл. 7), `POST` (гл. 15)
- **Файл(ы):** `src/components/FindForm.tsx`; README, «Записать находку»
- **История в README:**

```md
### Записать находку

Как вахтенный, я хочу записать находку: бирку и имя.
Бирку набираю как попало, журнал пишет её заглавными.
Готово, когда: набираю ab-052 и ракушка, в поле
бирки AB-052; после «Записать» сервер отвечает 201,
поля пустые.
```

- **Текст файла при входе** (форма уже стоит в `App` над списком):

```tsx
// Хочу, чтобы бирка писалась заглавными, пока её набирают.
//
// История: README, «Записать находку».
//
// Дано:
// - управляемое поле: значение живёт в памяти,
//   поле только показывает его:
//   value={x} onChange={(evt) => setX(evt.target.value)}
//
// Свяжи оба поля с памятью. После записи очисти их.
import { useState } from "react";
import type { FormEvent } from "react";
import { createFind } from "../api.ts";

export const FindForm = () => {
  const [tag, setTag] = useState(``);
  const [name, setName] = useState(``);

  const save = async (evt: FormEvent) => {
    evt.preventDefault();
    await createFind({ tag, name });
  };

  return (
    <form onSubmit={save}>
      <label>
        Бирка
        <input required pattern="[A-Z]{2}-\d{3}" />
      </label>
      <label>
        Имя
        <input required />
      </label>
      <button>Записать</button>
    </form>
  );
};
```

- **Пометка при входе (поля):**
  1. Управляемое поле: правду хранит память, поле её только показывает. Хочешь поменять текст — поменяй память.
  2. Поэтому очистить поле — это ``setTag(``)``, а заглавные — `toUpperCase()` прямо в `onChange`.
  3. `onChange` в React срабатывает на каждую букву, как событие `input` из гл. 2, а не как `change`.
- **Подсказки по щелчку:**
  1. Набери в бирке `ab-052` и нажми «Записать»: браузер не пускает, `pattern` ждёт заглавные. А щуп на `tag` в памяти показывает пустую строку.
  2. У поля `value` — из памяти, `onChange` — в память. Для бирки в `onChange` ещё `.toUpperCase()`. После `await` — ``setTag(``)`` и ``setName(``)``.
  3. Поле бирки и конец `save`:
     ```tsx
     <input
       required
       pattern="[A-Z]{2}-\d{3}"
       value={____}
       onChange={(evt) =>
         setTag(evt.target.value.____())
       }
     />

     await createFind({ tag, name });
     setTag(____);
     setName(____);
     ```

- **Эталонное решение:**

```tsx
export const FindForm = () => {
  const [tag, setTag] = useState(``);
  const [name, setName] = useState(``);

  const save = async (evt: FormEvent) => {
    evt.preventDefault();
    await createFind({ tag, name });
    setTag(``);
    setName(``);
  };

  return (
    <form onSubmit={save}>
      <label>
        Бирка
        <input
          required
          pattern="[A-Z]{2}-\d{3}"
          value={tag}
          onChange={(evt) =>
            setTag(evt.target.value.toUpperCase())
          }
        />
      </label>
      <label>
        Имя
        <input
          required
          value={name}
          onChange={(evt) => setName(evt.target.value)}
        />
      </label>
      <button>Записать</button>
    </form>
  );
};
```

- **Она проверяет:** Она набирает в поле бирки `ab-052` по букве (настоящие события `input`, как `user.type`). После каждой буквы в поле заглавные: `A`, `AB`, `AB-`, … `AB-052`. В поле имени — `ракушка`. Она нажимает «Записать»: уходит `POST /api/finds` с телом `{ "tag": "AB-052", "name": "ракушка" }`, ответ `201`, оба поля пустые. Она берёт со стола ракушку, которую море принесло в главе 20, и несёт к ставню: теперь она записана.
  - **Почти:** запись ушла, а поля не очистились. Она стоит с рукой над пультом. Пометка: «Запись ушла, а в полях старое. Следующую находку она запишет поверх».
  - Без заглавных форма не уходит вовсе: браузер останавливает её на `pattern`, щуп показывает `validationMessage` (гл. 10).
- **Частые ошибки:**
  1. `value` без `onChange`:
     ```tsx
     <input required pattern="[A-Z]{2}-\d{3}" value={tag} />
     ```
     Она печатает — в поле ничего не появляется. Телетайп:
     ```
     You provided a `value` prop to a form field without an `onChange` handler. This will render a read-only field. If the field should be mutable use `defaultValue`. Otherwise, set either `onChange` or `readOnly`.
     ```
     - ``You provided a `value` prop … without an `onChange` handler`` — ты дал полю `value`, но не дал `onChange`.
     - `This will render a read-only field` — поле будет только для чтения.
     - ``Otherwise, set either `onChange` or `readOnly` `` — поставь `onChange` или честно `readOnly`.

     Поле показывает память, а память никто не меняет.

  2. `onChange` без `value`: в поле `ab-052`, как набрала, а в памяти `AB-052`. Форма не уходит: браузер проверяет `pattern` по тексту поля, а не по памяти. Поле не управляется, пока у него нет `value`.

  3. Опечатка в поле события:
     ```tsx
     onChange={(evt) => setTag(evt.target.vlaue)}
     ```
     Рубильник отскакивает:
     ```
     src/components/FindForm.tsx(34,48): error TS2551: Property 'vlaue' does not exist on type 'EventTarget & HTMLInputElement'. Did you mean 'value'?
     ```
     Та самая `vlaue` из утра. В гл. 2 она давала полый импульс, здесь до запуска не доходит.
- **Код профи:** Очистка стоит после `await`, и это работает в её пользу. Если бирка занята, сервер отвечает `409`, `createFind` бросает ошибку, строки ниже не выполняются, и поля остаются заполненными: набирать заново не нужно. На ленте при этом `Uncaught (in promise) Error: HTTP 409` [проверить в браузере]. Показать ошибку у поля ты умеешь с гл. 15, в этой истории это не требуется.
- **В мире:**
  - Поля и клавиша «Записать» рисуются набором вещей из гл. 10. Её «набирать» — это «нажимать» по клавишам пульта, буквы — настоящие события `input`.
  - Щуп на поле бирки: `value: "AB-0"` и память `tag: "AB-0"` — одно и то же, в этом и смысл.
  - Запрос: у строки `await createFind` кромка «жду», импульс возвращается со `status: 201`. На ленте ничего не печатается.

```tsx
// Хочу, чтобы журнал при открытии брал находки с сервера.

// История: README, «Журнал с сервера».
//
// Дано:

// - useEffect(() => { код }, []) выполняет код после
//   того, как React нарисовал; [] — один раз
//
// Положи находки с сервера в память finds.
import { useState } from "react";
import { getFinds } from "./api.ts";
import { FindForm } from "./components/FindForm.tsx";
import { FindList } from "./components/FindList.tsx";
import { Page } from "./components/Page.tsx";
import type { Find } from "./types.ts";

export const App = () => {
  const [finds, setFinds] = useState<Find[]>([]);

  return (
    <Page title="Журнал моря">
      <FindForm />
      <FindList finds={finds} />
    </Page>
  );
};
```

- **Пометка при входе (поля):**
  1. Тело компонента — только рисование. Запрос — последствие рисования, его ставят в `useEffect`.
  2. `.then(функция)` отдаёт функции ответ, когда он придёт, как `Promise.resolve().then(…)` в гл. 8. `Find[]` — тип «массив находок».
  3. В разработке React нарочно запускает эффект дважды: так `StrictMode` из `main.tsx` ищет, где нет уборки.
- **Подсказки по щелчку:**
  1. Журнал говорит «пусто»: память `finds` начинается с `[]` и больше не меняется.
  2. `useEffect` с `[]` — один раз после рисования. Внутри `getFinds()`, ответ — в `setFinds`. Не забудь добавить `useEffect` в `import`.
  3. 
     ```tsx
     useEffect(() => {
       getFinds().then(____);
     }, []);
     ```

- **Эталонное решение:**

```tsx
import { useEffect, useState } from "react";

// …

export const App = () => {
  const [finds, setFinds] = useState<Find[]>([]);

  useEffect(() => {
    getFinds().then(setFinds);
  }, []);

  return (
    <Page title="Журнал моря">
      <FindForm />
      <FindList finds={finds} />
    </Page>
  );
};
```

- **Она проверяет:** Рубильник — чистая страница. В журнале все находки с сервера, и среди них ракушка, которую она записала в прошлой истории: запись живёт на сервере. Агент считает запросы `GET /api/finds`: после загрузки новых нет секунду подряд. Она находит ракушку в списке и опускает руку.
  - **Почти:** список есть, но кромка у строки с запросом мигает без конца (ошибки 1 и 2). Она ждёт у табло. Пометка: «Список есть, а запросы не затихают: щуп насчитал их уже сотни».
- **Частые ошибки:**
  1. Запрос прямо в теле компонента:
     ```tsx
     const [finds, setFinds] = useState<Find[]>([]);
     getFinds().then(setFinds);
     ```
     Ошибки нет, и это хуже ошибки. Кромка у строки с запросом мигает без конца, реле трещит, щуп на строке: запросов сотни. Тело компонента выполняется на каждую перерисовку. Ответ перерисовывает журнал, а перерисовка снова шлёт запрос. Это тот же круг, что `Too many re-renders` в 20.7, только растянутый во времени, и React его не ловит.

  2. Эффект без второго аргумента:
     ```tsx
     useEffect(() => {
       getFinds().then(setFinds);
     });
     ```
     Те же бесконечные запросы. Без второго аргумента эффект запускается после каждой перерисовки.

  3. `async` прямо в `useEffect`:
     ```tsx
     useEffect(async () => {
       setFinds(await getFinds());
     }, []);
     ```
     Рубильник отскакивает:
     ```
     src/App.tsx(21,13): error TS2345: Argument of type '() => Promise<void>' is not assignable to parameter of type 'EffectCallback'.
       Type 'Promise<void>' is not assignable to type 'void | Destructor'.
     ```
     - `Argument of type '() => Promise<void>'` — ты отдал функцию, которая возвращает Promise,
     - `is not assignable to parameter of type 'EffectCallback'` — а `useEffect` ждёт эффект другого вида.
     - `Type 'Promise<void>' is not assignable to type 'void | Destructor'` — эффект может вернуть только ничего или функцию уборки.

     `async`-функция всегда возвращает Promise, а React ждёт от эффекта функцию уборки. Возьми `then` или объяви `async`-функцию внутри эффекта.
- **Код профи:** Слышишь двойной щелчок при каждом рубильнике? Это `StrictMode`: в разработке React запускает эффект, убирает и запускает снова. Кромка у строки с запросом мигает дважды, щуп на ней: два одинаковых запроса. В сборке (`npm run build`) запрос один, и пометка так и говорит: «Двойной запуск — проверка, а не ошибка. Как убирать за эффектом — в истории «Опоздавший ответ»».
- **В мире:**
  - Трасса: импульс проходит через `App` — строки вспыхивают, журнал рисуется пустым. Потом вспыхивает строка `useEffect`, у неё кромка «жду», импульс возвращается с ответом, `setFinds` — и импульс снова проходит через `App`, список появляется.
  - `StrictMode` виден буквально: строка эффекта вспыхивает дважды, наружу уходят два запроса.

### 21.5 Найти по слову (`journal-search`)

- **Новое:** зависимости эффекта
- **Опирается на:** `useEffect` (21.4), управляемое поле (21.3), debounce (гл. 15), `GET` с параметром `?q=` (гл. 15)
- **Файл(ы):** `src/App.tsx`; README, «Найти по слову»
- **История в README:**

```md
### Найти по слову

Как вахтенный, я хочу искать в журнале по слову:
набираю — и список сужается.
Готово, когда: набираю «кас» — в списке кассета
и каска; дописываю «сета» — только кассета.
Запрос уходит после паузы, а не на каждую букву.
```

- **Текст файла при входе** (поле поиска уже стоит, управляемое, как в 21.3: его поставил коммит каркаса):

```tsx
// Хочу искать в журнале по слову.
//
// История: README, «Найти по слову».
//
// Дано:
// - searchFinds(слово) из api.ts: GET /api/finds?q=слово
// - useDebounce(значение, мс) отдаёт значение, когда
//   его перестали менять на мс
// - useEffect(эффект, [x]) запускается снова, когда
//   меняется x
//
// Ищи по слову из поля, запрос — после паузы 300 мс.
import { useEffect, useState } from "react";
import { getFinds, searchFinds } from "./api.ts";
import { FindForm } from "./components/FindForm.tsx";
import { FindList } from "./components/FindList.tsx";
import { Page } from "./components/Page.tsx";
import { useDebounce } from "./hooks.ts";
import type { Find } from "./types.ts";

export const App = () => {
  const [finds, setFinds] = useState<Find[]>([]);
  const [word, setWord] = useState(``);

  useEffect(() => {
    getFinds().then(setFinds);
  }, []);

  return (
    <Page title="Журнал моря">
      <FindForm />
      <input
        type="search"
        aria-label="Поиск"
        value={word}
        onChange={(evt) => setWord(evt.target.value)}
      />
      <FindList finds={finds} />
    </Page>
  );
};
```

- **Пометка при входе (поля):**
  1. Второй аргумент `useEffect` — список того, от чего зависит эффект. Поменялось что-то из списка — эффект запускается снова. `[]` значит «ни от чего»: один раз.
  2. `useDebounce` держит слово, пока его набирают, и отдаёт после паузы. От этого слова эффект и зависит.
- **Подсказки по щелчку:**
  1. Набери «кас»: список не меняется. Эффект грузит всё один раз и про слово не знает.
  2. Слово после паузы — `useDebounce(word, 300)`. В эффекте вместо `getFinds()` — `searchFinds` с этим словом, и в зависимостях оно же.
  3. Вместо старого эффекта:
     ```tsx
     const query = useDebounce(____, 300);

     useEffect(() => {
       searchFinds(____).then(setFinds);
     }, [____]);
     ```

- **Эталонное решение** (в `App`, остальное как при входе):

```tsx
const query = useDebounce(word, 300);

useEffect(() => {
  searchFinds(query).then(setFinds);
}, [query]);
```

`getFinds` в `import` больше не нужен. Оставишь — не ошибка, проверка типов о нём молчит.
- **Она проверяет:** Сервер в этой истории отвечает ровно, за 0,3 секунды. Она быстро набирает «кас» и замирает: после паузы в списке кассета и каска. Потом быстро дописывает «сета» и снова ждёт: в списке одна кассета. Агент считает запросы `GET /api/finds?q=…`: после двух при открытии (это `StrictMode`, 21.4) ровно два — `q=кас` и `q=кассета`. Она находит кассету в списке и опускает руку.
  - **Почти:** список верный, а запросов семь (ошибка 2). Она ждёт у табло. Пометка: «Список верный, а запросов семь, по одному на букву. В истории — запрос после паузы».
- **Частые ошибки:**
  1. Зависимости как были: `searchFinds(query)` внутри, а в конце `}, []);`. Ошибки нет, список не сужается. Эффект запустился при открытии со словом `""`, а пустое слово отдаёт все находки (README). `[]` значит «больше не запускать».

  2. Мимо паузы:
     ```tsx
     useEffect(() => {
       searchFinds(word).then(setFinds);
     }, [word]);
     ```
     Ошибки нет, список верный. Но эффект зависит от того, что меняется на каждую букву. На «кассета» уходит семь запросов: кромка у строки с запросом мигает семь раз, реле трещит. Пауза живёт в `query`, от него и зависеть.

  3. Зависимость не та:
     ```tsx
     useEffect(() => {
       searchFinds(query).then(setFinds);
     }, [word]);
     ```
     Ошибки нет, а список отстаёт на одно слово: после «кас» в нём все находки, после «кассета» — кассета и каска. Эффект запускается на каждую букву, пока `query` ещё старый. А когда пауза кончилась и `query` стал новым, эффект не узнал: `query` нет в списке. В зависимостях — всё, чем эффект пользуется. Снаружи такую ошибку подчёркивает ESLint: в выгрузке уже настроено правило `react-hooks/exhaustive-deps`.

  4. Пауза без длины:
     ```tsx
     const query = useDebounce(word);
     ```
     Рубильник отскакивает:
     ```
     src/App.tsx(24,17): error TS2554: Expected 2 arguments, but got 1.
     ```
     - `Expected 2 arguments` — ждали два аргумента,
     - `but got 1` — а получили один.

     `useDebounce` должен знать, сколько ждать: `useDebounce(word, 300)`.
- **В мире:**
  - Набор в поле: импульс через `App` на каждую букву, а строка эффекта вспыхивает только после паузы — её держит `useDebounce`.
  - Щуп на `[query]`: что сейчас в списке зависимостей, `["кас"]`.
  - Щуп на строке с запросом: адрес `/api/finds?q=%D0%BA%D0%B0%D1%81` и рядом то же по-человечески, `q=кас`, `status: 200`, время ответа.

### 21.6 Опоздавший ответ (`journal-race`)

- **Новое:** уборка эффекта
- **Опирается на:** зависимости эффекта (21.5), замыкание (гл. 8), `clearInterval` — уборка за таймером (гл. 8), `let`, `if` и `!` (гл. 1, 3)
- **Файл(ы):** `src/App.tsx`; README, «Опоздавший ответ»
- **История в README:**

```md
### Опоздавший ответ

Как вахтенный, я хочу видеть в списке то, что ищу
сейчас, даже когда сеть медленная.
Готово, когда: набираю «кас», потом «кассета», и в
списке находки по «кассета», даже если сервер
ответит на «кас» позже.
```

- **Текст файла при входе** (под строками задачи — эталон 21.5):

```tsx
// Хочу, чтобы ответ на старое слово не затирал новое.
//
// История: README, «Опоздавший ответ».
//
// Дано:
// - сервер нарочно отвечает на «кас» за 2 секунды,
//   а на «кассета» — за 0,3
// - эффект может вернуть функцию уборки: React вызовет
//   её перед следующим запуском эффекта
//
// Пусть опоздавший ответ не трогает память.
```

- **Пометка при входе (поля):**
  1. Уборка — функция, которую эффект отдаёт React: `return () => {…}`. Перед новым запуском React вызывает её, и старый запуск узнаёт, что опоздал.
  2. Так бывает в настоящей сети: ответы приходят не в том порядке, в каком ушли запросы.
- **Подсказки по щелчку:**
  1. Набери «кас», подожди полсекунды, допиши «сета». Сначала в списке кассета, а через две секунды — кассета и каска: ответ на «кас» пришёл последним и затёр новый.
  2. В эффекте флажок `stale` — «опоздал», сначала `false`. Уборка ставит его в `true`. Ответ кладут в память, только если не `stale`.
  3. Эффект целиком:
     ```tsx
     useEffect(() => {
       let stale = false;

       searchFinds(query).then((found) => {
         if (!stale) setFinds(____);
       });

       return () => {
         stale = ____;
       };
     }, [query]);
     ```

- **Эталонное решение:**

```tsx
useEffect(() => {
  let stale = false;

  searchFinds(query).then((found) => {
    if (!stale) setFinds(found);
  });

  return () => {
    stale = true;
  };
}, [query]);
```

- **Она проверяет:** Она быстро набирает «кас» и замирает на полсекунды, потом быстро дописывает «сета». Сервер станции нарочно отвечает на «кас» за 2 секунды, а на «кассета» — за 0,3. Пометка при запуске проверки говорит это прямо: «Сервер нарочно отвечает на первое слово дольше. Так бывает в настоящей сети». Через 3 секунды в списке ровно находки по «кассета»: одна кассета, каски нет. Она находит кассету в списке и опускает руку.
  - **Почти:** уборки нет, как при входе. Сначала в списке кассета, через 2 секунды список меняется: кассета и каска. Она стоит перед табло, где только что появилась каска. Пометка: «Ответ на «кас» пришёл последним и затёр «кассета». Уборка должна сказать старому запуску, что он опоздал».
- **Частые ошибки:**
  1. Уборка — не функция:
     ```tsx
     return (stale = true);
     ```
     Рубильник отскакивает:
     ```
     src/App.tsx(25,13): error TS2345: Argument of type '() => boolean' is not assignable to parameter of type 'EffectCallback'.
       Type 'boolean' is not assignable to type 'void | Destructor'.
     ```
     - `Argument of type '() => boolean'` — ты отдал функцию, которая возвращает `true` или `false`,
     - `is not assignable to parameter of type 'EffectCallback'` — а `useEffect` ждёт эффект другого вида.
     - `Type 'boolean' is not assignable to type 'void | Destructor'` — эффект может вернуть только ничего или функцию уборки.

     Присваивание выполнилось бы сразу, а уборка нужна позже. Поэтому её отдают функцией: `return () => { stale = true; };`.

  2. Один флажок на все запуски — `let stale = false;` наверху файла, над `App`, а в эффекте только проверка и уборка. Ошибки нет, а журнал с самого открытия «пусто» и не оживает. При открытии `StrictMode` запускает эффект, убирает и запускает снова (21.4). Первая же уборка подняла общий флажок навсегда, и все ответы считаются опоздавшими. У каждого запуска свой флажок: `let stale` внутри эффекта. Двойной запуск `StrictMode` для того и нужен: он показал ошибку сразу.

  3. Проверка не там:
     ```tsx
     if (!stale) searchFinds(query).then(setFinds);
     ```
     Ошибки нет, гонка осталась. Когда запрос уходит, никто ещё не опоздал: `stale` всегда `false`. Опоздание видно только тогда, когда ответ пришёл, поэтому проверка — внутри `then`.
- **Код профи:** `AbortController` вместо флажка. Флажок прячет опоздавший ответ, а запрос всё равно идёт до конца: кромка «жду» горит, сервер отвечает зря. `abort()` обрывает запрос сразу, щуп на строке — `(canceled)`, как во вкладке Network. Измеримо: агент видит один отменённый запрос вместо одного выброшенного ответа.

  ```tsx
  useEffect(() => {
    const controller = new AbortController();

    searchFinds(query, controller.signal)
      .then(setFinds)
      .catch((error) => {
        if (error.name !== `AbortError`) throw error;
      });

    return () => controller.abort();
  }, [query]);
  ```

  Честно на полях: «`abort()` кончает запрос отказом `AbortError`. `.catch(функция)` ловит его, как `catch` у `try`, иначе на ленте `Uncaught (in promise)`». И там же: «Так же устроены готовые библиотеки запросов, вроде TanStack Query. Они снаружи».
- **В мире:**
  - Уборка видна: перед новым запуском вспыхивает строка `stale = true`, и ответ на старый запрос возвращается полым импульсом: до `setFinds` он не доходит.
  - Два запроса ждут разом. Щуп на строке показывает оба, у каждого своё слово и время ответа: видно, что «кас» вернулся вторым.

### 21.7 Шторм (`journal-status`)

- **Новое:** `useReducer`
- **Опирается на:** объединения типов и сужение (гл. 19), ранний `return` (гл. 3), неизменяемое обновление (20.10), уборка эффекта (21.6), статусы и `503` (гл. 14)
- **Файл(ы):** `src/journal.ts`; под ним `src/App.tsx`; README, «Шторм»
- **История в README:**

```md
### Шторм

Как вахтенный, я хочу, чтобы журнал честно говорил,
что происходит: «ждём», «нет связи» или «пусто».
Готово, когда: в шторм горит только «нет связи»;
после шторма — список; по слову без находок — «пусто».
```

Каркас уже переложил `App.tsx` на `useReducer`, коммитом «App: память журнала через reducer». Так приходит чужой коммит на работе: `git log --oneline` показывает его сверху (гл. 16), а что он изменил, видно на мониторе `App.tsx`. Теперь `App` держит одну память `state` и шлёт действия, а что с ними делать — пустое место в `journal.ts`. До твоего кода журнал навсегда «ждём».

Что стало в `App.tsx` (главное):

```tsx
const [state, dispatch] = useReducer(journal, {
  status: `loading`,
});

// в эффекте поиска:
dispatch({ type: `start` });
searchFinds(query)
  .then((finds) => {
    if (!stale) dispatch({ type: `done`, finds });
  })
  .catch(() => {
    if (!stale) dispatch({ type: `fail` });
  });

// в разметке:
{state.status === `loading` && <p>ждём</p>}
{state.status === `error` && <p>нет связи</p>}
{state.status === `ready` && (
  <FindList finds={state.finds} />
)}
```

`.catch(функция)` — тот же `catch`, что у `try`, только звеном цепочки: сработает, если запрос не удался.
- **Текст файла при входе** (`journal.ts`):

```ts
// Хочу, чтобы журнал честно говорил, что происходит.
//
// История: README, «Шторм».
//
// Дано:
// - reducer: (было, действие) => стало
// - App зовёт useReducer(journal, начало) и шлёт
//   действия: dispatch({ type: `start` }) и другие
//
// Допиши journal: на каждое действие — своё состояние.
import type { Find } from "./types.ts";

export type State =
  | { status: `loading` }
  | { status: `error` }
  | { status: `ready`; finds: Find[] };

export type Action =
  | { type: `start` }
  | { type: `fail` }
  | { type: `done`; finds: Find[] };

export const journal = (
  state: State,
  action: Action,
): State => {
  return state;
};
```

- **Пометка при входе (поля):** Все изменения памяти — в одной функции: было и что случилось → стало. Невозможное состояние в ней просто не написать.
- **Подсказки по щелчку:**
  1. Журнал навсегда «ждём»: `journal` на любое действие отдаёт то, что было.
  2. На `start` — `` { status: `loading` } ``, на `fail` — `` { status: `error` } ``, на `done` — `ready` и `finds` из действия.
  3. 
     ```ts
     if (action.type === `start`) return { status: ____ };
     if (action.type === `fail`) return { status: ____ };

     return { status: `ready`, finds: action.____ };
     ```

- **Эталонное решение:**

```ts
export const journal = (
  state: State,
  action: Action,
): State => {
  if (action.type === `start`) return { status: `loading` };
  if (action.type === `fail`) return { status: `error` };

  return { status: `ready`, finds: action.finds };
};
```

- **Она проверяет:** Станция ведёт её по погоде. Штиль: после рубильника на табло «ждём», потом список. Она набирает «якорь»: такого нет, на табло «пусто». Шторм: сервер отвечает `503` на всё, клац рубильника — на табло только «нет связи», ни «ждём», ни списка. Шторм стихает, рубильник — список. Каждый раз агент проверяет, какие из трёх надписей есть в DOM: ровно одна. Она садится у стола и смотрит на полоску под ставнем.
  - **Почти:** на `fail` вернулось `loading`. В шторм журнал «ждём» и дальше, она ждёт у табло. Пометка: «Шторм, а журнал всё ещё ждёт. На `fail` нужен `error`».
- **Частые ошибки:**
  1. Опечатка в состоянии:
     ```ts
     if (action.type === `fail`) return { status: `eror` };
     ```
     ```
     src/journal.ts(28,40): error TS2820: Type '"eror"' is not assignable to type '"loading" | "error" | "ready"'. Did you mean '"error"'?
     ```
     - `Type '"eror"' is not assignable` — значение `"eror"` не подходит
     - `to type '"loading" | "error" | "ready"'` — под три разрешённых.
     - `Did you mean '"error"'?` — может, `"error"`?

     У `State` всего три состояния, опечатку TS видит до запуска. В шторм она бы просто стояла перед пустым табло.

  2. Готово без находок:
     ```ts
     return { status: `ready` };
     ```
     ```
     src/journal.ts(30,3): error TS2322: Type '{ status: "ready"; }' is not assignable to type 'State'.
       Property 'finds' is missing in type '{ status: "ready"; }' but required in type '{ status: "ready"; finds: Find[]; }'.
     ```
     Готовый журнал без находок — невозможное состояние, и тип его не пускает.

  3. Забыта ветка `fail`:
     ```ts
     if (action.type === `start`) return { status: `loading` };

     return { status: `ready`, finds: action.finds };
     ```
     ```
     src/journal.ts(29,43): error TS2339: Property 'finds' does not exist on type '{ type: "fail"; } | { type: "done"; finds: Find[]; }'.
       Property 'finds' does not exist on type '{ type: "fail"; }'.
     ```
     TS видит: до этой строки может дойти и `fail`, а у него `finds` нет. Сужение из гл. 19 работает и здесь.
- **Код профи:** Три отдельные памяти — `loading`, `error`, `finds` — так пишет новичок. В шторм он ставит `setError(true)` и забывает `setLoading(false)`: на табло горят и «ждём», и «нет связи» сразу. Агент это измеряет: в DOM две надписи. С `State` из трёх вариантов так не бывает: невозможного состояния нет в типе. На полях честно: «Redux Toolkit и Zustand — снаружи. Внутри у них тот же reducer».
- **В мире:**
  - Шторм — по-настоящему: сервер станции отвечает `503`, импульс возвращается с плохой вестью, это не выбитый автомат (§6). Щуп на строке с запросом: `status: 503`.
  - `dispatch` на трассе: импульс идёт в `journal`, вспыхивает ровно та строка с `return`, которая сработала. Видно, какое действие во что превратилось.
  - Под ставнем полоска заметно светлее: прошло время.

```tsx
// Хочу, чтобы флажок оставлял только хрупкие находки.
import { useState } from "react";
import { carryFind } from "../api.ts";
import type { Find } from "../types.ts";
import { FindItem } from "./FindItem.tsx";

type Props = {
  finds: Find[];
};

export const FindList = ({ finds }: Props) => {
  const [carried, setCarried] = useState<number[]>([]);
  const [onlyFragile, setOnlyFragile] = useState(false);
  const left = finds.filter(
    (find) => !find.carried && !carried.includes(find.id),
  );
  const shown = left.filter(
    (find) => find.fragile || !onlyFragile,
  );

  return (
    <div>
      <label>
        <input
          type="checkbox"
          checked={onlyFragile}
          onChange={(evt) =>
            setOnlyFragile(evt.target.checked)
          }
        />
        только хрупкие
      </label>
      {shown.length === 0 && <p>пусто</p>}
      <ul>
        {shown.map((find) => (
          <FindItem
            key={find.id}
            find={find}
            onCarry={() =>
              carryFind(find.id).then(() =>
                setCarried((carried) => [
                  ...carried,
                  find.id,
                ]),
              )
            }
          />
        ))}
      </ul>
    </div>
  );
};
```
