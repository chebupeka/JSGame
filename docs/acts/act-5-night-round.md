## Что этот акт

Полночь. Полоски света под ставнем нет: в кадре светится только то, что сделал твой код, — лампы, окно, мониторы с файлами. Она в последний раз перед рассветом обходит тёмную станцию: Архив, Аппаратную, Насосную и комнату с фальш-окном. В каждом месте ты возвращаешься к своему утреннему коду с инструментом профи. Так и выглядит работа junior: большую часть времени он работает со старым кодом.

| Глава | Место и время | Инструмент | Её нужда |

Писать тесты на свои функции и на страницу так, как её видит человек, и сначала ловить баг тестом, а потом чинить. Переводить свой JavaScript на TypeScript без `as`, `any` и `!` и читать ошибки компилятора с кодом `TS…`.

- **Помощь.** В первой задаче каждой главы полный «Дано» и новый инструмент на полях в общем виде. Дальше «Дано» в одну-три строки, пометки в одну фразу. Три подсказки по щелчку везде.

## Глава 16. Архив ночью — полночь (git)

**Место.** Архив находок, тот же фон, что утром и после полудня, ночь рисует код. Свет в кадре только твой: мониторы с файлами на стене, а у полки — синее пятно от лампы, которую ты зажёг утром. Ночью море принесло запертые ящики: у них кадр «заперт» из главы 3.

**Её нужда.** Ты переделываешь `shelf.js`, а она и после переделки должна взять свою находку с первого раза. Она тянет ящики, как живой человек: сначала из любопытства трогает запертый, иногда дёргает свой два раза подряд.

**Что учит глава.** Git — инструмент, который помнит каждую сохранённую версию кода и позволяет вернуться к любой. Своей картинки у git нет: это инструмент, как Prettier. Команды набираются в строке `$` внизу того же ЭЛТ, ответ печатает телетайп.

**Почему задач 11, а не около 8, как в CURRICULUM.** У git десять разных команд, и каждая — новое понятие. Две команды в одной задаче нарушили бы правило «одно новое на задачу». Каждая задача короткая: одна-три команды и иногда одна строка кода. Самая трудная, конфликт, стоит девятой: раньше её не поставить, ей нужны ветки и слияние. Последняя — одна команда.

**Порядок.** Сначала увидеть историю (log), потом свою правку глазами git (status, diff), сохранить её (add, commit). Потом две ветки с правками в одном месте (switch -c, switch), слияние и конфликт (merge). В конце две отмены: коммита (revert) и несохранённой правки (restore). Глава заканчивается тем, что ломать не страшно.

Enter в ней — тот же запуск, что рубильник: клац, станция перезапускается с файлами из рабочей папки, а ответ команды печатает телетайп. Строка понимает только `git` и `npm`. На всё остальное (`ls`, `cd`) станция отвечает своими словами: «Это не bash. Здесь только git и npm. Полная командная строка — снаружи». Сообщение коммита пишется в двойных кавычках, как в настоящей командной строке: обратные кавычки там значат другое.

В начале главы из этих записей собирается настоящий репозиторий: объекты, коммиты и ветки настоящие (isomorphic-git), хэши видны только на ленте. Сообщение каждого дневного коммита — строка задачи. Автор — «станция». `diff`, `revert` и разметку конфликта в isomorphic-git делаем мы поверх него, результат — настоящие коммиты, и пометка это говорит. Тексты вывода — дословные формулировки настоящего git 2.45.

**Листок задачи `night.js`.** Задача этой главы лежит не в `shelf.js`, а в отдельном файле `night.js`, иначе каждая новая задача сама появлялась бы в `git status` и `git diff`. ### 16.1 Твой день (`git-log`)

- **Новое:** история коммитов: `git log --oneline`
- **Опирается на:** файлы станции и их мониторы (гл. 10–11), телетайп как консоль (гл. 4)
- **Файл(ы):** `night.js`, строка `$`
- **Текст файла при входе:**

```js
// Хочу увидеть, как прошёл мой день.
//
// Дано:
// - внизу экрана строка $: в ней пишут команды git,
//   Enter — запуск, ответ печатает телетайп
// - с утра станция сохраняла каждую твою решённую
//   версию файла. Такая запись — коммит, а все
//   коммиты вместе — репозиторий
// - git log печатает коммиты, новые сверху;
//   с флагом --oneline — по строке на коммит
//
// Выведи свою историю по строке на коммит.
```

- **Пометка при входе (поля):**
  1. «Команда git: `git <что сделать>`. Флаг с двумя минусами меняет вид ответа.»
  2. «Это не bash: строка понимает только git и npm.»
  3. «Эти коммиты сделала станция. Дальше их делаешь ты.»
- **Подсказки по щелчку:**
  1. Строка `$` — внизу того же экрана, под кодом. Щёлкни по ней.
  2. Нужна команда `log` и флаг `--oneline`: one line, одна строка.
  3. `git ___ --_______`
- **Эталонное решение:**

```text
$ git log --oneline
```

Лента (хэши у каждого игрока свои):

```text
a41c9e2 Хочу видеть на экране журнала волну у мыса.
…
c5ad5df Хочу, чтобы открывались и новые ящики.
…
d05067b Хочу, чтобы окно светило тем цветом, что на ручке.
…
3d82de3 Хочу, чтобы в щитовой загорелась лампа.
```

- **Она проверяет:** она стоит у полки в темноте. Когда телетайп допечатал, она подходит и отрывает ленту, как в Сигнальной. Лента длинная, до пола: на ней весь твой день, от лампы до последней задачи. Засчитано, когда на ленте история по строке на коммит. «Почти»: `git log` без флага печатает то же подробно, с `Author:` и `Date:` у каждого коммита. Она не отрывает ленту и ждёт. Пометка: «Это та же история, только подробно. По строке на коммит — флаг `--oneline`».
- **Частые ошибки:**
  - `git log --online` → `fatal: unrecognized argument: --online` [git 2.45.1]
    - `fatal` — git остановился и ничего не сделал;
    - `unrecognized argument` — не понял, что ему дали;
    - `--online` — вот это.

    «Флаг называется `--oneline`: one line, а не online.»
  - `git lgo --oneline` → [git 2.45.1]
    ```text
    git: 'lgo' is not a git command. See 'git --help'.

    The most similar command is
    	log
    ```
    - `'lgo' is not a git command` — такой команды у git нет;
    - `The most similar command is log` — похожая есть: `log`.

    «Git сам подсказывает, что ты имел в виду.»
  - `log --oneline` без `git` → ответ станции: «Это не bash. Здесь только git и npm». «Команда начинается со слова git.»
- **Код профи:** разницы в работе нет.
- **В мире:** строка `$` внизу ЭЛТ; телетайп печатает ленту, она ложится на пол. На ленте хэш — короткое имя коммита, его считает git из содержимого. В репозитории все файлы станции, которые ты решал: `lamp.js`, `frame.js`, `shelf.js` и дальше. В `.gitignore` одна строка: `night.js`.

### 16.2 Что изменилось (`git-status`)

- **Новое:** `git status`: чем рабочая папка отличается от последнего коммита
- **Опирается на:** история коммитов (16.1), ранний `return` и `classList.contains` (гл. 3), делегирование (гл. 6)
- **Файл(ы):** `night.js`, `shelf.js`
- **Текст файла при входе:**

```js
// Хочу, чтобы запертые ящики не дёргались.
//
// Дано:
// - запертый ящик: <div class="drawer locked">
// - git status говорит, какие файлы изменились
//
// В shelf.js положи ящик в const drawer и выйди,
// если ящика нет или он заперт. Потом переключи его
// и спроси git, что изменилось.
```

- **Пометка при входе (поля):**
  1. «Рабочая папка — файлы, как они сейчас. Коммит — как они были сохранены. `git status` сравнивает.»
  2. «Напоминание из Архива: `` вещь.classList.contains(`класс`) `` — `true`, если класс есть.»
- **Подсказки по щелчку:**
  1. Открой `shelf.js` щелчком по его монитору. Строка с `closest` делает всё сразу: и находит ящик, и переключает. Её надо разделить.
  2. Ящик — в `const drawer`. Два ранних `return`, как утром в Архиве: если ящика нет и если у него класс `locked`. Потом `toggle`. И в строке `$` — `git status`.
  3. Строки вместо той, что с `closest`, и потом `git ______`:

     ```js
     const drawer = target.closest(`.drawer`);

     if (!______) return;
     if (drawer.classList.contains(`______`)) return;

     drawer.classList.toggle(`open`);
     ```

- **Эталонное решение:**

```js
// Хочу, чтобы по датчику полки сразу было видно:
// из события ему нужен только target.
document
  .querySelector(`.shelf`)
  .addEventListener(`click`, ({ target }) => {
    const drawer = target.closest(`.drawer`);

    if (!drawer) return;
    if (drawer.classList.contains(`locked`)) return;

    drawer.classList.toggle(`open`);
  });
```

```text
$ git status
On branch main
Changes not staged for commit:
  (use "git add <file>..." to update what will be committed)
  (use "git restore <file>..." to discard changes in working directory)
	modified:   shelf.js

no changes added to commit (use "git add" and/or "git commit -a")
```

- **Она проверяет:** сначала трогает запертый ящик: он не дёргается, класса `open` у него нет. Потом тянет свой, второй: он выезжает, она берёт находку (нести). Засчитано, когда это так и на ленте `git status` после правки есть `modified:   shelf.js`. «Почти»: если `git status` набран до правки, на ленте `nothing to commit, working tree clean`. Пометка: «Пока нечего: файл совпадает с последним коммитом. Сначала правка». Если проверка стоит под `toggle`, запертый ящик успевает получить `open` и дёргается. Она убирает руку и ждёт.
- **Частые ошибки:**
  - `` if (drawer.classList.contains(`locked`) return; `` (не хватает скобки) → `SyntaxError: Unexpected token 'return'` [Node 24 / V8]
    - `SyntaxError` — код не разобран, не выполнилась ни одна строка;
    - `Unexpected token 'return'` — разбор споткнулся о `return`: перед ним ждали закрывающую скобку `if`.

    «Посчитай скобки: у `if` своя пара, у `contains` своя.» Рубильник не встаёт в зацеп.
  - `drawer.classlist.contains(…)` → `TypeError: Cannot read properties of undefined (reading 'contains')` [Node 24 / V8]
    - `Cannot read properties of undefined` — взяли что-то у «ничего»;
    - `(reading 'contains')` — а именно `contains`.

    «`classlist` с маленькой буквы — `undefined`. Нужно `classList`.» Выбивает только ветку обработчика, датчик слушает дальше.
  - `git stauts` → [git 2.45.1]
    ```text
    git: 'stauts' is not a git command. See 'git --help'.

    The most similar command is
    	status
    ```
    «Опечатка в команде. Git показывает похожую.»
  - Тихая: `` contains(`.locked`) `` с точкой. Класса с точкой в имени нет, проверка всегда ложна, запертый ящик дёргается. «Точка нужна в селекторе, а в `classList` — просто имя класса.»
  - Строка `if (!drawer) return;` забыта. Ящики работают, но щелчок в щель выбивает ветку: `TypeError: Cannot read properties of null (reading 'classList')` [Node 24 / V8]. Утром эту работу делал `?.`. «В щели ящика нет: `closest` дал `null`. Выйди раньше.»
- **Код профи:** разницы в работе нет.
- **В мире:** на её рывок датчик полки вспыхивает, импульс отскакивает ровно от строки с `locked`. Монитор `shelf.js` на стене показывает новый текст. Пометка после первого `git status`: «`modified` — изменён. `not staged for commit` — правка ещё не отложена для коммита, это следующий шаг. Строки в скобках — подсказки git про следующие шаги».

### 16.3 Своя правка глазами git (`git-diff`)

- **Новое:** `git diff`: что именно изменилось, построчно
- **Опирается на:** `git status` (16.2)
- **Файл(ы):** `night.js`, строка `$`
- **Текст файла при входе:**

```js
// Хочу увидеть свою правку так, как её видит git.
//
// Дано:
// - git diff показывает строки, которыми рабочая
//   папка отличается от последнего коммита
//

```

- **Пометка при входе (поля):** «Плюс — строка добавлена, минус — убрана, без знака — соседи для ориентира.»
- **Подсказки по щелчку:**
  1. Правка из прошлой задачи ещё не сохранена в коммит: `git status` её видел.
  2. Нужна команда `diff`, без флагов.
  3. `git ____`
- **Эталонное решение:**

```text
$ git diff
diff --git a/shelf.js b/shelf.js
index 7c3c1da..ba4b81a 100644
--- a/shelf.js
+++ b/shelf.js
@@ -3,5 +3,10 @@
 document
   .querySelector(`.shelf`)
   .addEventListener(`click`, ({ target }) => {
-    target.closest(`.drawer`)?.classList.toggle(`open`);
+    const drawer = target.closest(`.drawer`);
+
+    if (!drawer) return;
+    if (drawer.classList.contains(`locked`)) return;
+
+    drawer.classList.toggle(`open`);
   });
```

Вывод записан по правилам git и сверен с `diff -u` [проверить в git].

- **Она проверяет:** она подходит к телетайпу и отрывает ленту, когда на ней есть строка с `+`. Засчитано: на ленте diff `shelf.js`, где старая строка с `closest` убрана, а новые добавлены. «Почти»: если телетайп ничего не напечатал, правки нет (её стёрли). Она не отрывает пустую ленту. Пометка: «Пусто: рабочая папка совпадает с коммитом».
- **Частые ошибки:**
  - `git dif` → [git 2.45.1]
    ```text
    git: 'dif' is not a git command. See 'git --help'.

    The most similar commands are
    	diff
    	config
    	difftool
    	init
    ```
    «Похожих несколько. Тебе нужна первая: `diff`.»
  - Тихая: игрок ищет красное и зелёное, как в VS Code. На ленте их нет: телетайп печатает чёрной краской, а красного на станции нет нигде. «Смотри на первый знак строки: `+` или `-`.»
- **Код профи:** разницы в работе нет. На полях: «Смотри diff перед каждым коммитом. Так видно лишнее, что попало в правку случайно».
- **В мире:** строка `@@ -3,5 +3,10 @@` — «было пять строк начиная с третьей, стало десять». Щуп на этой строке ленты говорит это словами. `a/` и `b/` — «до» и «после».

### 16.4 Коробка для коммита (`git-add`)

- **Новое:** `git add`: положить правку в будущий коммит
- **Опирается на:** `git status` (16.2), `git diff` (16.3)
- **Файл(ы):** `night.js`, строка `$`
- **Текст файла при входе:**

```js
// Хочу отложить правку shelf.js для коммита.
//
// Дано:
// - git add <файл> кладёт правку в коробку будущего
//   коммита; git status покажет её отдельно
//
// Положи shelf.js в коробку и проверь статусом.
```

- **Пометка при входе (поля):** «Коммит делают в два шага: сложить в коробку (`add`), потом запечатать и подписать (`commit`). Настоящее имя коробки — staging area.»
- **Подсказки по щелчку:**
  1. Имя файла видно на шильдике терминала и в выводе `git status`.
  2. Сначала `add` с именем файла, потом `status`.
  3. `git ___ ________` и `git ______`
- **Эталонное решение:**

```text
$ git add shelf.js
$ git status
On branch main
Changes to be committed:
  (use "git restore --staged <file>..." to unstage)
	modified:   shelf.js
```

- **Она проверяет:** отрывает ленту, когда на ней `Changes to be committed`. «Почти»: если на ленте всё ещё `Changes not staged for commit`, `add` не дошёл. Она ждёт.
- **Частые ошибки:**
  - `git add shelf` → `fatal: pathspec 'shelf' did not match any files` [git 2.45.1]
    - `pathspec` — то, что ты указал как путь к файлу;
    - `did not match any files` — ни один файл так не называется.

    «Имя файла целиком, с `.js`.»
  - `git add night.js` → [git 2.45.1]
    ```text
    The following paths are ignored by one of your .gitignore files:
    night.js
    hint: Use -f if you really want to add them.
    hint: Disable this message with "git config advice.addIgnoredFile false"
    ```
    - `ignored by one of your .gitignore files` — этот файл git нарочно не замечает.

    «Это листок задачи. В коммит идёт `shelf.js`.»
  - Тихая: `git diff` после `add` печатает пустоту. «diff показывает то, что ещё не в коробке. Правка не пропала: она в коробке.»
- **Код профи:** на полях: «В коробку кладут только то, что относится к одной мысли. Остальное ждёт своего коммита».
- **В мире:** у git нет картинки. Только лента и строка `(use "git restore --staged <file>..." to unstage)`: «Так достают из коробки обратно. Пока не нужно».

### 16.5 Коммит своими руками (`git-commit`)

- **Новое:** `git commit -m`: запечатать коробку и подписать
- **Опирается на:** `git add` (16.4), история коммитов (16.1)
- **Файл(ы):** `night.js`, строка `$`
- **Текст файла при входе:**

```js
// Хочу сохранить правку в историю.
//
// Дано:
// - git commit -m "сообщение" делает коммит из того,
//   что лежит в коробке
//
// Сделай коммит: в сообщении — что изменилось.
```

- **Пометка при входе (поля):** «Сообщение — для тебя через неделю. Что изменилось, обычными словами.»
- **Подсказки по щелчку:**
  1. Посмотри на ленту `git log --oneline`: так выглядят сообщения коммитов.
  2. Команда `commit`, флаг `-m` и сообщение в двойных кавычках. Потом `git log --oneline`.
  3. `git ______ -_ "__________________"`
- **Эталонное решение:**

```text
$ git commit -m "Не трогать запертые ящики"
[main 7f5fb09] Не трогать запертые ящики
 1 file changed, 6 insertions(+), 1 deletion(-)
$ git log --oneline
7f5fb09 Не трогать запертые ящики
a41c9e2 Хочу видеть на экране журнала волну у мыса.
…
```

- **Она проверяет:** отрывает ленту, когда на ней новый коммит. Засчитано: в истории сверху твой коммит, `git status` — `nothing to commit, working tree clean`. В мире ничего не меняется: коммит — запись, а не ток. Пометка так и говорит.
- **Частые ошибки:**
  - `git commit -m Не трогать запертые ящики` (без кавычек) → [git 2.45.1]
    ```text
    error: pathspec 'трогать' did not match any file(s) known to git
    error: pathspec 'запертые' did not match any file(s) known to git
    error: pathspec 'ящики' did not match any file(s) known to git
    ```
    - сообщением стало только первое слово, `Не`;
    - остальные слова git принял за имена файлов и не нашёл их.

    «Сообщение из нескольких слов — в двойных кавычках.»
  - `git commit -m "Не трогать запертые ящики"` до `add` → [git 2.45.1]
    ```text
    On branch main
    Changes not staged for commit:
      (use "git add <file>..." to update what will be committed)
      (use "git restore <file>..." to discard changes in working directory)
    	modified:   shelf.js

    no changes added to commit (use "git add" and/or "git commit -a")
    ```
    - `no changes added to commit` — коробка пустая, коммитить нечего.

    «Сначала `git add shelf.js`.»
  - Сообщение в обратных кавычках → ответ станции: «В строке $ сообщение — в двойных кавычках. Обратные в настоящей командной строке запускают команду».
  - Повторный `git commit -m "…"` → `nothing to commit, working tree clean` [git 2.45.1]. «Всё уже сохранено.»
- **Код профи:** хорошее сообщение говорит, что изменилось: «Не трогать запертые ящики». Сообщение «fix» через неделю не говорит ничего. Последствие настоящее: в задаче 16.10 по сообщениям на ленте ты будешь искать нужный коммит. Ещё на полях: «Автора станция вписала сама. Снаружи git один раз спросит имя и почту: `git config`».
- **В мире:** `[main 7f5fb09]` — ветка и короткий хэш нового коммита. `1 file changed, 6 insertions(+), 1 deletion(-)` — один файл, шесть строк добавлено, одна убрана. Это вывод git, не игры.

### 16.6 Своя ветка (`git-branch`)

- **Новое:** ветка: `git switch -c <имя>`
- **Опирается на:** `git add`, `git commit -m` (16.4–16.5), `dataset` — строка (гл. 3)
- **Файл(ы):** `night.js`, `shelf.js`
- **Текст файла при входе:**

```js
// Хочу, чтобы пустые ящики не выдвигались.
//
// Дано:
// - у пустого ящика data-count="0"
// - git switch -c <имя> заводит ветку и переходит
//   на неё; коммиты в ней не трогают main
//
// Заведи ветку empty, допиши выход для пустого
// ящика и закоммить.
```

- **Пометка при входе (поля):** «Ветка — своя линия коммитов. Пробуй на ней, main останется как был.»
- **Подсказки по щелчку:**
  1. Строка `On branch main` на ленте `git status` — это ветка, где ты сейчас.
  2. Сначала `switch -c empty`, потом правка под проверкой `locked`, потом `add` и `commit`. В `dataset` всегда строка.
  3. `git ______ -_ _____` и `` if (drawer.dataset.count === `_`) return; ``
- **Эталонное решение:**

```text
$ git switch -c empty
Switched to a new branch 'empty'
```

```js
    if (!drawer) return;
    if (drawer.classList.contains(`locked`)) return;
    if (drawer.dataset.count === `0`) return;
```

```text
$ git add shelf.js
$ git commit -m "Не выдвигать пустые ящики"
[empty 8ddaf87] Не выдвигать пустые ящики
 1 file changed, 1 insertion(+)
```

- **Она проверяет:** тянет пустой ящик: он не выезжает. Тянет свой: выезжает, она берёт находку. Засчитано: коммит лежит на ветке `empty`, а `main` его не содержит. «Почти»: если `switch -c` забыт, коммит лёг в `main` (на ленте `[main …]`). Ящики ведут себя правильно, но пометка: «Работает, но коммит лёг в main, а ветки empty нет. Так бывает и на работе. Спасают две строки ниже». Под ней на полях две строки целиком, для копирования:

  ```text
  $ git branch empty
  $ git reset --hard HEAD~1
  HEAD is now at 7f5fb09 Не трогать запертые ящики
  ```

  Первая вешает ветку `empty` на твой коммит, вторая возвращает `main` на коммит назад [проверить в git]. Пометка рядом: «Это спасательные команды, в задачах их нет. `reset --hard` стирает несохранённые правки, но сейчас их нет». После них задача засчитана: коммит на `empty`, в `main` его нет. Без этого выхода дальше не пройти: в 16.9 не было бы спора.
- **Частые ошибки:**
  - Второй раз `git switch -c empty` → `fatal: a branch named 'empty' already exists` [git 2.45.1]
    - `a branch named 'empty' already exists` — такая ветка уже есть.

    «Ветку заводят один раз. Перейти на готовую — следующая задача.»
  - Тихая: `drawer.dataset.count === 0` — число вместо строки. Всегда ложь, пустой ящик выезжает. «В `dataset` всегда строка.» (как в главе 3)
- **Код профи:** имя ветки короткое и про правку: `empty`, а не `test2`. В работе разницы нет, это для людей.
- **В мире:** у ветки нет картинки. На шильдике терминала рядом с именем файла мелко стоит имя ветки, как в строке состояния VS Code: `shelf.js · empty`.

### 16.7 Переход между ветками (`git-switch`)

- **Новое:** `git switch <ветка>`: файлы становятся такими, как на ветке
- **Опирается на:** ветка (16.6), коммит (16.5)
- **Файл(ы):** `night.js`, `shelf.js`
- **Текст файла при входе:**

```js
// Хочу, чтобы она могла дёрнуть ящик дважды.
//
// Дано:
// - git switch <ветка> переходит на готовую ветку
// - она тянет свой ящик два раза подряд; открытый
//   ящик второй рывок не должен задвинуть
//
// Вернись на main, заведи от неё ветку stay-open,
// допиши выход для открытого ящика, закоммить.
```

- **Пометка при входе (поля):** «Смотри на терминал, когда переходишь: текст `shelf.js` поменяется сам.»
- **Подсказки по щелчку:**
  1. Держи `shelf.js` открытым: на `main` строки про пустые ящики нет, на `empty` есть.
  2. `switch main`, потом `switch -c stay-open`. Проверка: если у ящика уже есть класс `open`, выйти.
  3. `git ______ ____` и `` if (drawer.classList.contains(`____`)) return; ``
- **Эталонное решение:**

```text
$ git switch main
Switched to branch 'main'
$ git switch -c stay-open
Switched to a new branch 'stay-open'
```

```js
    if (!drawer) return;
    if (drawer.classList.contains(`locked`)) return;
    if (drawer.classList.contains(`open`)) return;
```

```text
$ git add shelf.js
$ git commit -m "Не задвигать открытый ящик"
[stay-open 8c3253c] Не задвигать открытый ящик
 1 file changed, 1 insertion(+)
```

- **Она проверяет:** после `git switch main` станция перезапускается, и строка про пустые ящики исчезает из терминала. Она тянет пустой ящик, и тот выезжает: на `main` этой правки нет. Она задвигает его и ждёт. На ветке `stay-open` она дёргает свой ящик дважды подряд: он остаётся открытым, она берёт находку. Засчитано: на `stay-open` есть этот коммит, а строки про пустые ящики нет, то есть ветка выросла из `main`. «Почти»: если `switch main` забыт, `stay-open` выросла из `empty` и несёт обе правки. Ящики работают, но пометка: «Ветка выросла из empty. Слияние потом пройдёт без спора, и ты его не увидишь. Заведи её заново от main». Под ней на полях строки целиком:

  ```text
  $ git switch main
  $ git switch -C stay-open
  Switched to and reset branch 'stay-open'
  ```

  Большая `C` — «заведи заново, даже если такая ветка есть» [проверить в git]. Ветка теперь начинается с `main`, и строки про открытый ящик в ней нет: её дописывают снова, потом `add` и `commit`. Тогда задача засчитана.
- **Частые ошибки:**
  - `git switch mian` → `fatal: invalid reference: mian` [git 2.45.1]
    - `invalid reference` — git не знает такого имени ветки.

    «Ветка называется `main`.»
  - Правка на `empty` не закоммичена, потом `git switch main` → [git 2.45.1]
    ```text
    error: Your local changes to the following files would be overwritten by checkout:
    	shelf.js
    Please commit your changes or stash them before you switch branches.
    Aborting
    ```
    - `would be overwritten` — переход стёр бы твою несохранённую правку;
    - `Aborting` — поэтому git ничего не сделал.

    «Сначала коммит, потом переход.»
  - Тихая: правка не закоммичена, а файл на двух ветках одинаковый. Тогда git переносит её с собой молча и печатает `M	shelf.js` над `Switched to branch 'main'` [git 2.45.1]. Правка оказывается не на той ветке. «Буква M — несохранённая правка, она пришла с тобой.»
- **Код профи — машина времени.** Необязательно. На ленте `git log` найди утренний коммит Архива «Хочу, чтобы задвинутый ящик можно было выдвинуть.» (3.13).
  ```text
  $ git switch --detach 1a2b3c4
  HEAD is now at 1a2b3c4 Хочу, чтобы задвинутый ящик можно было выдвинуть.
  ```
  Станция перезапускается с утренними файлами, на стене только мониторы утра. `shelf.js` такой, как утром: датчики на каждом ящике, как до делегирования. Ящики, что принесло море, мёртвые: она тянет новый, и ничего. `git switch main` печатает `Previous HEAD position was 1a2b3c4 …` и `Switched to branch 'main'` [git 2.45.1], и всё снова работает. Без `--detach` git отвечает `fatal: a branch is expected, got commit '1a2b3c4'` и `hint: If you want to detach HEAD at the commit, try again with the --detach option.` [git 2.45.1]. На полях: «Старый коммит можно смотреть, а новые коммиты делают на ветке».
- **В мире:** на шильдике терминала имя ветки меняется: `shelf.js · main`, `shelf.js · stay-open`. Монитор `shelf.js` на стене показывает текст той ветки, где ты стоишь.

### 16.8 Слить ветку (`git-merge`)

- **Новое:** `git merge <ветка>`: забрать коммиты ветки туда, где стоишь
- **Опирается на:** ветка и переход (16.6–16.7)
- **Файл(ы):** `night.js`, строка `$`
- **Текст файла при входе:**

```js
// Хочу, чтобы на main пустые ящики тоже стояли.
//
// Дано:
// - git merge <ветка> забирает её коммиты в ту
//   ветку, на которой ты стоишь
//
// Перейди на main и слей в неё ветку empty.
```

- **Пометка при входе (поля):** «Сливают туда, где стоишь. Сначала встань на main.»
- **Подсказки по щелчку:**
  1. Сейчас ты на `stay-open`: это видно на шильдике.
  2. `switch main`, потом `merge empty`.
  3. `git ______ ____` и `git _____ _____`
- **Эталонное решение:**

```text
$ git switch main
Switched to branch 'main'
$ git merge empty
Updating 7f5fb09..8ddaf87
Fast-forward
 shelf.js | 1 +
 1 file changed, 1 insertion(+)
```

- **Она проверяет:** на `main` тянет пустой ящик: он не выезжает. Тянет свой: выезжает. Засчитано: `main` содержит коммит «Не выдвигать пустые ящики». «Почти»: слито не в `main`. Пометка: «Слито не в main. Смотри на шильдик».
- **Частые ошибки:**
  - `git merge empy` → `merge: empy - not something we can merge` [git 2.45.1]
    - `not something we can merge` — такого, что можно слить, git не нашёл.

    «Опечатка в имени ветки.»
  - `git merge empty`, стоя на самой `empty` → `Already up to date.` [git 2.45.1]. «Ветку сливают в другую, не в саму себя.»
- **Код профи:** разницы в работе нет. На полях про `Fast-forward`: «У main не было своих новых коммитов, и она просто догнала empty. Новый коммит не понадобился».
- **В мире:** строка `Updating 7f5fb09..8ddaf87` — «было здесь, стало здесь»: `7f5fb09` — твой коммит про запертые ящики, `8ddaf87` — коммит ветки `empty`. Текст `shelf.js` в терминале меняется сам.

### 16.9 Конфликт (`git-conflict`)

- **Новое:** конфликт слияния: маркеры `<<<<<<<`, `=======`, `>>>>>>>` и ручное решение
- **Опирается на:** слияние (16.8), `git add` и `git commit -m` (16.4–16.5), `SyntaxError` (гл. 4)
- **Файл(ы):** `night.js`, `shelf.js`
- **Текст файла при входе:**

```js
// Хочу, чтобы на main работали обе правки.
//
// Дано:
// - обе ветки дописали строку в одно и то же место,
//   и git не знает, какую взять
// - спорное место он размечает прямо в shelf.js:
//   <<<<<<< твоё, ======= граница, >>>>>>> чужое
//
// Слей stay-open в main, оставь обе проверки,
// убери разметку и закоммить.
```

- **Пометка при входе (поля):** «Конфликт — не поломка. Git просит решить человека.»
- **Подсказки по щелчку:**
  1. После `merge` открой `shelf.js`: спор — между строками со стрелками.
  2. Обе строки нужны: одна про пустые ящики, другая про открытые. Сотри три строки разметки, потом `add` и `commit`.
  3. Сотри `<<<<<<< HEAD`, `=======`, `>>>>>>> stay-open`, затем `git add ________` и `git commit -m "_____"`
- **Эталонное решение:**

```text
$ git merge stay-open
Auto-merging shelf.js
CONFLICT (content): Merge conflict in shelf.js
Automatic merge failed; fix conflicts and then commit the result.
```

`shelf.js` после `merge`, как его пишет git:

```js
    if (!drawer) return;
    if (drawer.classList.contains(`locked`)) return;
<<<<<<< HEAD
    if (drawer.dataset.count === `0`) return;
=======
    if (drawer.classList.contains(`open`)) return;
>>>>>>> stay-open

    drawer.classList.toggle(`open`);
```

После решения:

```js
// Хочу, чтобы по датчику полки сразу было видно:
// из события ему нужен только target.
document
  .querySelector(`.shelf`)
  .addEventListener(`click`, ({ target }) => {
    const drawer = target.closest(`.drawer`);

    if (!drawer) return;
    if (drawer.classList.contains(`locked`)) return;
    if (drawer.dataset.count === `0`) return;
    if (drawer.classList.contains(`open`)) return;

    drawer.classList.toggle(`open`);
  });
```

```text
$ git add shelf.js
$ git commit -m "Слить stay-open: пустые и открытые вместе"
[main 103faa7] Слить stay-open: пустые и открытые вместе
$ git status
On branch main
nothing to commit, working tree clean
```

- **Она проверяет:** сразу после `merge` станция перезапускается, и рубильник отскакивает: в `shelf.js` маркеры, это уже не JS. Она стоит у полки. После решения: трогает запертый — не дёргается; тянет пустой — не выезжает; дёргает свой дважды — остаётся открытым, она берёт находку. Засчитано: так ведут себя все три, `git status` чистый, последний коммит — слияние с двумя родителями. «Почти»: если оставлена одна строка из двух, одна проверка пропадает. Пустой ящик выезжает, или второй рывок задвигает её ящик. Она останавливается у этого ящика. Пометка: «Одна мысль потерялась: в споре были обе строки».
- **Частые ошибки:**
  - Запуск, пока маркеры в файле → `SyntaxError: Unexpected token '<<'`, строка 10 [Node 24 / V8]
    - `SyntaxError` — файл не разобран, не выполнилась ни одна строка;
    - `Unexpected token '<<'` — разбор споткнулся о `<<`: так начинается маркер `<<<<<<<`.

    «Это разметка git, а не код. Убери её.» Засечка в коде на строке 10.
  - Стёрты `<<<<<<<` и `>>>>>>>`, а `=======` остался → `SyntaxError: Unexpected token '==='` [Node 24 / V8]. «Осталась граница `=======`.»
  - Стёрты `<<<<<<<` и `=======`, а `>>>>>>>` остался → `SyntaxError: Unexpected token '>>>'` [Node 24 / V8]. «Маркеров три. Сотри все три строки.»
  - `git commit -m "…"` до `git add` → [git 2.45.1]
    ```text
    error: Committing is not possible because you have unmerged files.
    hint: Fix them up in the work tree, and then use 'git add/rm <file>'
    hint: as appropriate to mark resolution and make a commit.
    fatal: Exiting because of an unresolved conflict.
    U	shelf.js
    ```
    - `unmerged files` — есть файл, где спор ещё не отмечен как решённый;
    - `use 'git add'` — отметить решение — это `git add`;
    - `U	shelf.js` — вот он.

    «Решил спор — скажи об этом git через `add`.»
- **Код профи:** разницы в работе нет. На полях: «Чем дольше живёт ветка, тем больше споров. Сливай маленькие ветки рано». И про аварийный выход, который `git status` сам печатает при конфликте: «Запутался — `git merge --abort` вернёт всё, как было до слияния».
- **В мире:** `HEAD` в маркере — «ветка, где ты стоишь», то есть `main`. Ниже `=======` — пришедшее из `stay-open`. Вывод `git status` во время конфликта [git 2.45.1]: `You have unmerged paths.` и `both modified:   shelf.js` — «обе ветки правили этот файл». После `add`: `All conflicts fixed but you are still merging.`

### 16.10 Отменить коммит (`git-revert`)

- **Новое:** `git revert <хэш>`: новый коммит, который отменяет старый
- **Опирается на:** история и хэши (16.1), коммит (16.4–16.5), `null` и `TypeError` (гл. 1), ошибка в обработчике выбивает только ветку (гл. 2)
- **Файл(ы):** `night.js`, `shelf.js`
- **Текст файла при входе:**

```js
// Хочу проверить, нужна ли проверка на щель.
//
// Дано:
// - if (!drawer) return; ловит щелчок мимо ящика
// - git revert <хэш> делает новый коммит, который
//   отменяет старый; хэш — на ленте git log
//
// Убери эту строку и закоммить. Посмотри, что
// будет, когда она тронет щель. Потом отмени
// свой коммит.
```

- **Пометка при входе (поля):** «revert не стирает историю. Ошибка и её отмена остаются на ленте.»
- **Подсказки по щелчку:**
  1. Щель — место между ящиками. Там `closest` ничего не находит.
  2. Удали строку, `add`, `commit`. Хэш своего коммита возьми из `git log --oneline`: он сверху.
  3. `git ______ _______`
- **Эталонное решение:**

```text
$ git add shelf.js
$ git commit -m "Пробую без проверки на щель"
[main 42f63b2] Пробую без проверки на щель
 1 file changed, 1 deletion(-)
$ git revert 42f63b2
[main e65bcff] Revert "Пробую без проверки на щель"
 1 file changed, 1 insertion(+)
$ git log --oneline
e65bcff Revert "Пробую без проверки на щель"
42f63b2 Пробую без проверки на щель
103faa7 Слить stay-open: пустые и открытые вместе
…
```

- **Она проверяет:** после пробного коммита она трогает щель между ящиками. Строка 8 выбивает ветку обработчика: `TypeError: Cannot read properties of null (reading 'classList')` [Node 24 / V8]. Импульс гаснет на строке 8. Потом она тянет свой ящик, и он выезжает: датчик продолжает слушать. После `revert` строка вернулась. Она трогает щель, импульс тихо гаснет на `if (!drawer) return;`. Засчитано: последний коммит — `Revert "…"`, пробный коммит остался в истории, строка на месте, `git status` чистый. «Почти»: если строку вписали обратно руками и закоммитили, всё работает, но пометка: «Работает. revert сделал бы это точно и записал, что отменили. Попробуй им». Задача не засчитана без коммита `Revert`.
- **Частые ошибки:**
  - `git revert` без хэша → git печатает справку, первая строка: `usage: git revert [--[no-]edit] [-n] [-m <parent-number>] [-s] [-S[<keyid>]] <commit>...` [git 2.45.1]
    - `usage` — «пишется так»;
    - `<commit>...` — в конце нужен коммит, то есть его хэш.

    «Не хватает хэша.»
  - `git revert 1234567` (хэша нет) → `fatal: bad revision '1234567'` [git 2.45.1]
    - `bad revision` — такого коммита нет.

    «Скопируй хэш с ленты: он у каждого свой.»
  - Хэш коммита слияния → `error: commit 103faa7… is a merge but no -m option was given.` и `fatal: revert failed` [git 2.45.1] (git печатает хэш целиком)
    - `is a merge` — это слияние, у него два родителя, и git не знает, к какому вернуться.

    «Ты взял строку слияния. Нужна строка выше, твой пробный коммит.»
- **Код профи:** маленькие коммиты. Твой пробный коммит менял одну строку, и revert отменил ровно её. Если бы в том же коммите была ещё правка про запертые ящики, revert убрал бы и её. Один большой коммит «fix» откатывается только целиком. На полях честно: «Снаружи git откроет редактор с этим сообщением. Здесь станция берёт сообщение как есть, будто с `--no-edit`».
- **В мире:** ошибка в обработчике выбивает только эту ветку (§3.3): импульс гаснет у строки 8, датчик продолжает мигать. Строка 8 — первая строка после стёртой: `` if (drawer.classList.contains(`locked`)) return; ``.

### 16.11 Ломать не страшно (`git-restore`)

- **Новое:** `git restore <файл>`: вернуть файл к последнему коммиту
- **Опирается на:** `git status` (16.2), коммит (16.5)
- **Файл(ы):** `night.js`, `shelf.js`
- **Текст файла при входе:**

```js
// Хочу знать, что ломать не страшно.
//
// Дано:
// - git restore <файл> возвращает файл к последнему
//   коммиту; всё незакоммиченное в нём пропадает
//
// Сотри в shelf.js всё, запусти. Потом верни файл.
```

- **Пометка при входе (поля):** «restore не переспрашивает. Возвращает к коммиту, а несохранённое пропадает насовсем.»
- **Подсказки по щелчку:**
  1. `Ctrl+A` и `Delete` в `shelf.js`, потом `Ctrl+Enter`.
  2. Команда `restore` и имя файла.
  3. `git _______ ________`
- **Эталонное решение:**

```text
$ git restore shelf.js
$ git status
On branch main
nothing to commit, working tree clean
```

- **Она проверяет:** с пустым `shelf.js` она тянет свой ящик, и ничего: на полке нет датчика. Она ждёт. После `restore` текст возвращается в терминал на глазах, станция перезапускается. Она тянет ящик дважды, берёт находку и уходит из Архива к двери в коридор. Засчитано: `git status` чистый, у неё находка. «Почти»: если текст вернули `Ctrl+Z`, всё работает, но пометка: «Работает. Ctrl+Z помнит минуты, restore — любой коммит». Задача засчитана и так.
- **Частые ошибки:**
  - `git restore shelf` → `error: pathspec 'shelf' did not match any file(s) known to git` [git 2.45.1]
    «Имя файла целиком: `shelf.js`.»
  - `git restore` без имени → `fatal: you must specify path(s) to restore` [git 2.45.1]
    - `you must specify path(s)` — скажи, какой файл вернуть.

    «Restore не угадывает файл.»
- **Код профи:** разницы в работе нет. На полях последняя пометка главы: «Дальше снаружи: `git remote add` и `git push` отправляют историю на GitHub, а pull request просит другого человека посмотреть код. В выгрузке станции история git уже настоящая».
- **В мире:** у полки снова горит синее пятно. Монитор `shelf.js` на стене светится, на нём весь файл. Щелчки стихают, остаётся море.

## Глава 17. Аппаратная ночью — после полуночи (модули и сборка)

**Место.** Аппаратная: ровная стена, на ней сетка мониторов из главы 11, по монитору на каждый твой файл. Ночь рисует код. Справа дверь в коридор, у двери лампа. На конторке у двери переносной пульт из главы 12 и маленький экран с кнопкой.

**Её нужда.** Ночью станция после рубильника поднимается медленно, и она ждёт у двери в темноте, пока у двери не загорится лампа. Ей нужно, чтобы станция вставала сразу.

**Что учит глава.** Как код разложен по файлам и как файлы находят друг друга (`import`, `export`, пути). Что такое `package.json` и его скрипты. Зачем сборка: станция из многих файлов собирается в один, и это измеримо — меньше ожидания у двери.

**Почему задач 8, а не около 7.** В CURRICULUM `export` и `import` стоят одной темой. Здесь это две задачи: одна берёт готовое имя из чужого файла, вторая открывает своё. Иначе в первой задаче было бы два новых понятия. Самая трудная — третья (`../`, главная задача CURRICULUM) и шестая (сборка). Последняя — одна строка в `.gitignore`.

### Мир главы (общий для всех задач)

**Как поднимается станция.** С этой главы станция встаёт так, как настоящий сайт. `index.html` грузит один файл, `main.js`, а он импортирует все твои файлы:

```js
// Файл станции: отсюда она поднимается.
import "./lamp.js";
import "./frame.js";
import "./shelf.js";
import "./intake.js";
import "./archive.js";
import "./cape.js";
import "./log/tag-hint.js";
import "./machine.js";
```

`import` без имён просто выполняет файл. `main.js` — файл станции, его видно на мониторе и «под корпусом», править его в этой главе не нужно. В `index.html` станция собрала все комнаты одним документом, страницу журнала тоже. Здесь показаны главные файлы, настоящий список длиннее: по строке на каждый твой файл.

```html
<!-- index.html, файл станции -->
<script type="module" src="./main.js"></script>
```

**Ночная линия.** Файлы отдаёт service worker песочницы по настоящим путям. Ночью он даёт каждому ответу одну и ту же задержку, как режим Slow 3G во вкладке Network в F12. Пометка говорит это прямо: иначе это была бы выдуманная медлительность. Браузер узнаёт, что нужен следующий файл, только когда пришёл тот, кто его импортирует. Поэтому файлы приходят волнами: `main.js`, потом всё, что он импортирует, потом то, что импортируют они. Время подъёма — число волн, а не число файлов. Код начинает выполняться, только когда пришёл последний файл: так устроены модули.

**Как это видно.** В §6 `import` назван проводом между мониторами. По решению 9 линии через стену нет. Пока файл в пути, на его мониторе мигает лампа запроса, как на вводе в Радиорубке. Пришёл — монитор загорается, на нём текст файла. Когда пришёл последний, код выполняется, и вещи меняются. Наведи щуп на строку `import`, и монитор того файла вспыхивает. Щуп на самом мониторе показывает запрос, как вкладка Network, и кто этот файл берёт.

**Вещи:**

```html
<div id="door" class="door"></div>
<div id="door-lamp" class="lamp"></div>
<button id="tide-button">прилив</button>
<pre id="tide-screen"></pre>
```

CSS станции: `.lamp.on` горит, `.door.open` отъезжает в сторону.

**Пульт.** Переносной пульт (гл. 12) лежит на конторке. Это вторая настоящая страница. Ночью на ней страница журнала: поле поиска `#search`, журнал `#log`, поле бирки `#tag` и место для ошибки `#tag-error` (гл. 15). Так она проверяет журнал, не уходя от двери. Нажимает и печатает она на пульте, лежащем на конторке, новой позы нет.

**Файл станции `log/tag-hint.js`.** Станция принесла ещё один файл: пока она набирает бирку, он спрашивает сервер, занята ли она (`GET /api/finds?tag=…`, гл. 15). В него скопирован твой `debounce`, и лежит он в папке `log/`. Текст — в 17.3.

**Она** стоит у двери. После каждого рубильника ждёт, пока загорится лампа у двери, и только тогда трогает дверь.

**Новые файлы.** Новый файл создают так же, как открывают: `Ctrl+P`, имя файла, Enter. Его монитор появляется на стене. Файл, с которого начинается задача (в нём «Хочу…»), станция сама дописывает в `main.js` строкой `import "./файл.js";`, как раньше сама подключала каждый решённый файл. Эту строку видно на мониторе `main.js`. Файл, который создаёшь ты сам (`utils.js`, `door.js`), в `main.js` не попадает: он выполнится, когда его импортирует другой файл. При переименовании файла станция правит и строку в `main.js`, как это делает VS Code.

**Коммиты.** С главы 16 станция больше не коммитит за тебя решённые задачи. После каждой задачи пометка один раз напоминает: «Решил — закоммить: `git add` с именами файлов и `git commit -m`». Это по желанию, задачи не ждут коммита, кроме 17.8.

### 17.1 Взять из другого файла (`import-named`)

- **Новое:** `import { имя } from "./файл.js"`
- **Опирается на:** функции-стрелки и вызов (гл. 2), файлы станции по путям (гл. 10), мониторы на стене (гл. 11)
- **Файл(ы):** `machine.js` (новый, твой), `power.js` (файл станции)
- **Текст файла при входе:**

```js
// Хочу, чтобы у двери Аппаратной горела лампа.
//
// Дано:
// - лампа у двери: <div id="door-lamp" class="lamp">
// - в CSS станции лампа с классом on горит
// - в файле станции power.js есть готовая функция:
//   export const turnOn = (selector) => { … }
//   она находит вещь по селектору и даёт ей класс on
//
// Возьми turnOn из power.js и зажги лампу у двери.
```

Файл станции `power.js` (виден на мониторе):

```js
// Файл станции. Его можно читать, править не нужно.
export const turnOn = (selector) => {
  document.querySelector(selector).classList.add(`on`);
};

export const turnOff = (selector) => {
  document.querySelector(selector).classList.remove(`on`);
};
```

- **Пометка при входе (поля):**
  1. «Взять из другого файла: `import { имя } from "./файл.js";`. `./` значит «в этой же папке».»
  2. «Путь — обычная строка в двойных кавычках. Обратные кавычки `import` не принимает.»
  3. «`import` пишут в самом верху файла.»
- **Подсказки по щелчку:**
  1. Открой `power.js` щелчком по его монитору: перед `turnOn` стоит `export`, значит его можно брать.
  2. Сверху строка `import`, ниже вызов `turnOn` с селектором лампы.
  3. ``import { ______ } from "./_____.js";`` и `` turnOn(`#_________`); ``
- **Эталонное решение:**

```js
// Хочу, чтобы у двери Аппаратной горела лампа.
import { turnOn } from "./power.js";

turnOn(`#door-lamp`);
```

- **Она проверяет:** рубильник. Мониторы загораются волнами, на тех, что в пути, мигают лампы запроса, она ждёт у двери. Когда пришёл последний файл, лампа у двери загорается. Она трогает дверь. Засчитано: у `#door-lamp` есть класс `on`. «Почти»: селектор без решётки, `` turnOn(`door-lamp`) ``. Лампа не горит, она ждёт у двери в темноте (ошибка ниже).
- **Частые ошибки:**
  - `` import { turnOn } from `./power.js`; `` → `SyntaxError: Unexpected template string` [Node 24 / V8]
    - `Unexpected template string` — разбор споткнулся о строку в обратных кавычках.

    «Это единственное место в JS, где обратные кавычки нельзя: путь в `import` наверху файла — обычная строка.» Рубильник не встаёт в зацеп.
  - `import { turnon } from "./power.js";` → `SyntaxError: The requested module './power.js' does not provide an export named 'turnon'` [Node 24 / V8]
    - `The requested module './power.js'` — файл нашёлся;
    - `does not provide an export named 'turnon'` — но имени `turnon` он не отдаёт.

    «В `power.js` имя пишется `turnOn`, с большой O.»
  - `import { turnOn } from "power.js";` (без `./`) → `TypeError: Failed to resolve module specifier "power.js". Relative references must start with either "/", "./", or "../".` [проверить в браузере]
    - `Failed to resolve module specifier` — браузер не понял, где искать;
    - `Relative references must start with …` — путь к своему файлу начинается с `./` или `../`.

    «Без `./` браузер ищет пакет с таким именем, а не твой файл.»
  - `import { turnOn } from "./power";` (без `.js`) → лампа запроса вспыхивает и гаснет, монитор не загорается: щуп на строке `import` показывает `404`. В F12: `GET …/power net::ERR_ABORTED 404 (Not Found)` [проверить в браузере]. Модули не пришли, код не выполняется вовсе. «В браузере путь пишут целиком, с `.js`.»
  - `` turnOn(`door-lamp`) `` → `TypeError: Cannot read properties of null (reading 'classList')`, `power.js`, строка 3 [Node 24 / V8]
    - `Cannot read properties of null` — `querySelector` ничего не нашёл;
    - строка в `power.js` — упало в чужом файле, но из-за твоего аргумента.

    «Решётка `#` — «по id». Без неё ищется тег `<door-lamp>`.»
- **Код профи:** разницы в работе нет.
- **В мире:** наведи щуп на строку `import`, и монитор `power.js` вспыхивает. Щуп на `turnOn` в твоём коде показывает, откуда имя пришло: `power.js`. Пометка один раз за главу: «Теперь станция — один граф файлов. Если файл упадёт при подъёме, файлы после него в `main.js` не выполнятся. Так устроен настоящий сайт».

### 17.2 Отдать своё имя (`export`)

- **Новое:** `export` перед `const`
- **Опирается на:** `import` (17.1), `debounce` (гл. 15), `Ctrl+P` (гл. 10)
- **Файл(ы):** `archive.js`, `utils.js` (создаёшь ты)
- **Текст файла при входе:** (`archive.js`: сверху задача, ниже весь твой файл с главы 15, слово в слово. Здесь показаны строки, важные для задачи, `addRow` и `show` пропущены)

```js
// Хочу, чтобы debounce жил в одном файле.
//
// Дано:
// - debounce одинаково написан здесь и в файле станции
//   log/tag-hint.js
//
// Перенеси debounce отсюда в новый файл utils.js,
// открой его другим файлам и возьми оттуда здесь.
const key = `watch-0451`;
const log = document.querySelector(`#log`);

// …addRow и show

const debounce = (fn, ms) => {
  let timer;

  return (value) => {
    clearTimeout(timer);
    timer = setTimeout(() => fn(value), ms);
  };
};

const search = debounce(async (q) => {
  const params = new URLSearchParams({ q });
  const res = await fetch(`/api/finds?${params}`);
  show(await res.json());
}, 300);

document
  .querySelector(`#search`)
  .addEventListener(`input`, ({ target }) => {
    search(target.value);
  });

const res = await fetch(`/api/finds`);
show(await res.json());
```

- **Пометка при входе (поля):**
  1. «`export` перед `const` разрешает другим файлам брать это имя.»
  2. «Новый файл: `Ctrl+P`, имя, Enter.»
- **Подсказки по щелчку:**
  1. Создай `utils.js`. Его монитор появится на стене.
  2. Вырежи `debounce` из `archive.js`, вставь в `utils.js` и поставь перед `const` слово `export`. В `archive.js` наверху — `import`, как для `turnOn`.
  3. `______ const debounce = (fn, ms) => {` и `import { ________ } from "./_____.js";`
- **Эталонное решение:**

`utils.js`:

```js
export const debounce = (fn, ms) => {
  let timer;

  return (value) => {
    clearTimeout(timer);
    timer = setTimeout(() => fn(value), ms);
  };
};
```

`archive.js`:

```js
// Хочу, чтобы debounce жил в одном файле.
import { debounce } from "./utils.js";

const key = `watch-0451`;
const log = document.querySelector(`#log`);

// …addRow и show

const search = debounce(async (q) => {
  const params = new URLSearchParams({ q });
  const res = await fetch(`/api/finds?${params}`);
  show(await res.json());
}, 300);

document
  .querySelector(`#search`)
  .addEventListener(`input`, ({ target }) => {
    search(target.value);
  });

const res = await fetch(`/api/finds`);
show(await res.json());
```

- **Она проверяет:** на пульте быстро набирает в поиске `AB-012`. После паузы уходит один запрос: лампа на вводе мигает один раз, щуп на вводе показывает адрес `/api/finds?q=AB-012`. В журнале одна строка. Засчитано: так, в `archive.js` нет своего `debounce`, а `utils.js` пришёл по его `import`. «Почти»: если в `archive.js` осталась старая копия, всё работает, но пометка: «Работает. Но копия всё ещё здесь, а задача — одна копия на станцию».
- **Частые ошибки:**
  - В `utils.js` забыт `export` → `SyntaxError: The requested module './utils.js' does not provide an export named 'debounce'` [Node 24 / V8]
    - файл есть, а имени он не отдаёт.

    «Перед `const debounce` нужно слово `export`.»
  - В `archive.js` и `import`, и старый `const debounce` → `SyntaxError: Identifier 'debounce' has already been declared` [Node 24 / V8]
    - `Identifier 'debounce'` — имя `debounce`;
    - `has already been declared` — уже занято: его дал `import`.

    «Старую копию из `archive.js` надо удалить.»
- **Код профи:** разницы в работе нет: копия работала так же. Последствие в будущем: поправишь `debounce` в одном месте — поправится везде. Вариант `(...args)` из Журнальной ночью здесь тоже ничего не меняет: обоим файлам хватает одного значения.
- **В мире:** на стене появился монитор `utils.js`. Щуп на нём: его берёт `archive.js`. На подъёме `utils.js` приходит третьей волной: сначала `main.js`, потом `archive.js`, потом он.

### 17.3 Путь на папку выше (`path-up`)

- **Новое:** путь `../`: на папку выше
- **Опирается на:** `import` и `export` (17.1–17.2)
- **Файл(ы):** `log/tag-hint.js` (файл станции)
- **Текст файла при входе:**

```js
// Хочу, чтобы и подсказка бирки брала общий debounce.
//
// Дано:
// - это файл станции: пока она печатает бирку, он
//   спрашивает сервер, занята ли она
// - он лежит в папке log/, а utils.js — в корне
//   станции, на папку выше
//
// Убери отсюда копию debounce и возьми его
// из utils.js.
const debounce = (fn, ms) => {
  let timer;

  return (value) => {
    clearTimeout(timer);
    timer = setTimeout(() => fn(value), ms);
  };
};

const tagField = document.querySelector(`#tag`);
const tagError = document.querySelector(`#tag-error`);

const check = debounce(async (tag) => {
  const params = new URLSearchParams({ tag });
  const res = await fetch(`/api/finds?${params}`);
  const finds = await res.json();

  tagError.textContent = ``;

  if (finds.length > 0) {
    tagError.textContent = `бирка занята`;
  }
}, 300);

tagField.addEventListener(`input`, () => {
  check(tagField.value);
});
```

- **Пометка при входе (поля):** «`./` — эта папка, `../` — папка выше. Путь считается от файла, где написан `import`. Корень станции — самая верхняя папка, где лежат `main.js` и `utils.js`.»
- **Подсказки по щелчку:**
  1. На шильдике терминала полное имя: `log/tag-hint.js`. А `utils.js` лежит в корне.
  2. Удали копию, наверху `import`, путь — на папку выше.
  3. `import { debounce } from "__/utils.js";`
- **Эталонное решение:**

```js
// Хочу, чтобы и подсказка бирки брала общий debounce.
import { debounce } from "../utils.js";

const tagField = document.querySelector(`#tag`);
const tagError = document.querySelector(`#tag-error`);

const check = debounce(async (tag) => {
  const params = new URLSearchParams({ tag });
  const res = await fetch(`/api/finds?${params}`);
  const finds = await res.json();

  tagError.textContent = ``;

  if (finds.length > 0) {
    tagError.textContent = `бирка занята`;
  }
}, 300);

tagField.addEventListener(`input`, () => {
  check(tagField.value);
});
```

- **Она проверяет:** на пульте быстро набирает бирку `AB-007`: после паузы один запрос, под полем «бирка занята». Потом печатает в поиске журнала: там тоже один запрос после паузы. Засчитано: оба места работают, копий `debounce` в этих двух файлах нет, и `utils.js` запрошен один раз, хотя нужен двум файлам. «Почти»: если в одном из файлов осталась копия — пометка, как в 17.2. Если ты ночью в Журнальной делал проверку бирки сервером (приём профи), копия есть и в твоём `intake.js`. Пометка: «В `intake.js` тоже копия. Он лежит в корне: там путь `./utils.js`». Это по желанию, задача засчитана и так.
- **Частые ошибки:**
  - `import { debounce } from "./utils.js";` в `log/tag-hint.js` → браузер ищет `log/utils.js`, его нет. В F12: `GET …/log/utils.js net::ERR_ABORTED 404 (Not Found)` [проверить в браузере]. Щуп на строке `import`: `404`. Граф не собран, и не выполняется ни один файл станции: лампа у двери не горит, она ждёт в темноте. «Отсюда `./` — это папка `log/`. Нужен `../`.»
  - `import { debounce } from "../utils";` → то же: 404 на `…/utils`. «Путь целиком, с `.js`.»
- **Код профи:** разницы в работе нет. Честно на полях: «Копия работала так же. Выигрыш — в будущем: одна правка вместо двух».
- **В мире:** щуп на мониторе `utils.js`: запрошен один раз, берут два файла. Модуль выполняется один раз, сколько бы файлов его ни брали. Если поставить в `utils.js` строку `` console.log(`utils`) ``, телетайп стукнет один раз. Пометка: «Один модуль — один экземпляр на всю станцию».

### 17.4 Одна главная вещь в файле (`export-default`)

- **Новое:** `export default` и импорт без фигурных скобок
- **Опирается на:** `import` и `export` (17.1–17.2)
- **Файл(ы):** `machine.js`, `door.js` (создаёшь ты)
- **Текст файла при входе:** (`machine.js`: сверху задача, ниже код из 17.1)

```js
// Хочу, чтобы дверь открывалась, когда станция
// встала.
//
// Дано:
// - дверь: <div id="door" class="door">,
//   с классом open она открыта
//
// Сделай файл door.js с функцией, которая открывает
// дверь. Отдай её как главную вещь файла и вызови
// здесь.
import { turnOn } from "./power.js";

turnOn(`#door-lamp`);
```

- **Пометка при входе (поля):** «Главная вещь файла: `export default`. Берут её без фигурных скобок и под любым именем: `import имя from "./файл.js";`.»
- **Подсказки по щелчку:**
  1. У `door.js` одна работа — дверь. Её и отдают по умолчанию.
  2. `export default` и стрелка, без `const` и имени. В `machine.js` — `import` с любым понятным именем и вызов.
  3. `______ _______ () => { … };` и `import ________ from "./door.js";`
- **Эталонное решение:**

`door.js`:

```js
export default () => {
  document.querySelector(`#door`).classList.add(`open`);
};
```

`machine.js`:

```js
// Хочу, чтобы дверь открывалась, когда станция встала.
import { turnOn } from "./power.js";
import openDoor from "./door.js";

turnOn(`#door-lamp`);
openDoor();
```

- **Она проверяет:** рубильник, волны, она ждёт у двери. Когда всё пришло, загорается лампа и дверь отъезжает. Она делает шаг к проёму двери и останавливается: дальше пока темно. Засчитано: у `#door` есть `open`. «Почти»: дверь открыта, но не через `export default` (например, именованным `export`). Пометка: «Работает. Задача — главная вещь файла: `export default`».
- **Частые ошибки:**
  - `export default const openDoor = () => {…}` → `SyntaxError: Unexpected token 'const'` [Node 24 / V8]
    - разбор споткнулся о `const` сразу после `export default`.

    «После `export default` идёт сама вещь, без `const`.»
  - `import { openDoor } from "./door.js";` → `SyntaxError: The requested module './door.js' does not provide an export named 'openDoor'` [Node 24 / V8]
    - фигурные скобки ищут имя `openDoor`, а у файла есть только главная вещь.

    «Главную вещь берут без фигурных скобок.»
  - Обратная ошибка: в `door.js` именованный `export const openDoor`, а в `machine.js` `import openDoor from "./door.js";` → `SyntaxError: The requested module './door.js' does not provide an export named 'default'` [Node 24 / V8]. «Главной вещи у файла нет: есть только имя в фигурных скобках.»
- **Код профи:** разницы в работе нет. На полях честно: «Это договорённость: у файла одна главная вещь. Так устроен каждый компонент React». И: «Именованный `export` проще искать по проекту: имя одно везде. Многие команды поэтому пишут только его».
- **В мире:** у двери на стене монитор `door.js`, щуп на нём: его берёт `machine.js`. Волн столько же, сколько было: `door.js` приходит вместе с `power.js`, в одной волне.

### 17.5 Грузить, когда понадобится (`dynamic-import`)

- **Новое:** `import()` по требованию
- **Опирается на:** `async` и `await` (гл. 14), деструктуризация (гл. 6), `import` (17.1)
- **Файл(ы):** `machine.js`, `tides.js` (файл станции)
- **Текст файла при входе:** (`machine.js`, сверху задача, ниже код из 17.4)

```js
// Хочу, чтобы по кнопке «прилив» экран показывал
// время прилива, а станция не ждала таблицу.
//
// Дано:
// - кнопка <button id="tide-button">, экран
//   <pre id="tide-screen">
// - в файле станции tides.js: export nextTide(),
//   она отдаёт время ближайшего прилива строкой
// - tides.js сам тянет большую таблицу приливов
//
// Бери tides.js только тогда, когда нажали кнопку.
import { turnOn } from "./power.js";
import openDoor from "./door.js";

turnOn(`#door-lamp`);
openDoor();
```

- **Пометка при входе (поля):** «`import` сверху грузит до запуска. `` import(`./файл.js`) `` грузит, когда до него дошла строка, и отдаёт Promise. Это вызов, как у функции, поэтому в скобках обратные кавычки можно.»
- **Подсказки по щелчку:**
  1. Открой `tides.js` щелчком по его монитору: наверху `import` таблицы из `tide-data.js`. Это ещё одна волна.
  2. Датчик `click` на кнопке, функция `async`, внутри `await import(…)` и фигурные скобки, как при деструктуризации.
  3. `` const { ________ } = await ______(`./tides.js`); ``
- **Эталонное решение:**

```js
// Хочу, чтобы по кнопке «прилив» экран показывал
// время прилива, а станция не ждала таблицу.
import { turnOn } from "./power.js";
import openDoor from "./door.js";

turnOn(`#door-lamp`);
openDoor();

const screen = document.querySelector(`#tide-screen`);

document
  .querySelector(`#tide-button`)
  .addEventListener(`click`, async () => {
    const { nextTide } = await import(`./tides.js`);

    screen.textContent = nextTide();
  });
```

- **Она проверяет:** рубильник: волн столько же, сколько было в 17.4, она ждёт у двери столько же. Потом нажимает «прилив»: мигает лампа запроса на мониторе `tides.js`, потом на `tide-data.js`, две паузы, и на экране время, например `04:10`. Засчитано: при подъёме `tides.js` не запрошен, а по кнопке экран показывает время. «Почти»: если `tides.js` взят обычным `import` сверху, кнопка работает, но при подъёме прибавляются две волны, и она дольше стоит в темноте. Пометка: «Работает. Но станция теперь ждёт таблицу приливов при каждом подъёме».
- **Частые ошибки:**
  - Функция без `async`: `` addEventListener(`click`, () => { const { nextTide } = await import(…); }) `` → `SyntaxError: Unexpected reserved word` [Node 24 / V8]
    - `Unexpected reserved word` — `await` в модуле — особое слово, а в обычной функции ему не место.

    «Перед стрелкой нужно `async`.»
  - Без `await`: `` const { nextTide } = import(`./tides.js`); `` → по нажатию `TypeError: nextTide is not a function` [Node 24 / V8]
    - `nextTide is not a function` — в `nextTide` лежит не функция, а `undefined`: у Promise такого поля нет.

    «`import()` отдаёт Promise. Дождись его через `await`.»
  - `` await import(`./tide.js`) `` (опечатка) → по нажатию `TypeError: Failed to fetch dynamically imported module: …/tide.js` [проверить в браузере]. Выбивает только ветку кнопки, станция стоит. «Файл называется `tides.js`.»
- **Код профи:** это он и есть. Измеримо: при подъёме на две волны меньше. Цена честная: по кнопке ждёт она. Пометка: «Редкое — по требованию, нужное сразу — сверху».
- **В мире:** у строки с `import()` кромка «жду», как у всех строк датчика: файл будут грузить, когда нажмут. Второй раз по кнопке ламп запроса нет: модуль уже пришёл, ответ мгновенный.

### 17.6 Собрать станцию (`build`)

- **Новое:** сборка: скрипт `build` в `package.json` и `npm run build`
- **Опирается на:** модули и волны (17.1–17.5), строка `$` (гл. 16), JSON (гл. 4)
- **Файл(ы):** `package.json`, `index.html`, строка `$`
- **Текст файла при входе:** в JSON нет комментариев, поэтому задача — в листке `night.js`, как в главе 16 (git его не видит):

```js
// Хочу, чтобы станция вставала одной волной.
//
// Дано:
// - esbuild собирает main.js и всё, что он
//   импортирует, в один файл. Команда, одной строкой:
//   esbuild main.js --bundle --format=esm
//   --outfile=dist/station.js
// - npm run <имя> запускает скрипт из "scripts"
// - index.html грузит ./main.js
//
// Добавь в package.json скрипт build, собери
// станцию, и пусть index.html грузит сборку.
```

`package.json` (файл станции, теперь его правишь ты):

```json
{
  "name": "station",
  "version": "1.0.0",
  "type": "module",
  "scripts": {},
  "devDependencies": {
    "esbuild": "^0.25.0"
  }
}
```

- **Пометка при входе (поля):**
  1. «`package.json` — паспорт проекта: имя, версия, скрипты, зависимости.»
  2. «Это JSON: ключи и строки только в двойных кавычках, после последнего пункта запятой нет.»
  3. «`--bundle` — собрать в один файл. `--format=esm` — как модуль. `--outfile` — куда положить.»
- **Подсказки по щелчку:**
  1. Скрипты пишут внутри `"scripts": {}`. Потом `index.html` — щелчком по его монитору.
  2. Ключ `"build"`, значение — команда esbuild из задачи. В `$` — `npm run build`. В `index.html` путь `./dist/station.js`.
  3. `"build": "_______ main.js --______ --format=esm --outfile=____/station.js"` и `src="./____/_______.js"`
- **Эталонное решение:**

```json
{
  "name": "station",
  "version": "1.0.0",
  "type": "module",
  "scripts": {
    "build": "esbuild main.js --bundle --format=esm --outfile=dist/station.js"
  },
  "devDependencies": {
    "esbuild": "^0.25.0"
  }
}
```

```text
$ npm run build

> station@1.0.0 build
> esbuild main.js --bundle --format=esm --outfile=dist/station.js

  dist/station.js  14.2kb

⚡ Done in 9ms
```

Первые три строки вывода — npm [npm 11], остальное — esbuild [esbuild 0.25]. Размер и время — пример.

```html
<script type="module" src="./dist/station.js"></script>
```

- **Она проверяет:** рубильник. Одна волна: лампа запроса мигает только на мониторе `dist/station.js`, и сразу ток. Лампа у двери загорается, дверь отъезжает почти сразу, она проходит в проём двери и возвращается к конторке: свет у двери теперь есть с первой минуты. Засчитано: при подъёме один запрос модуля, и всё работает. По кнопке «прилив» отдельного запроса больше нет: без флага `--splitting` esbuild кладёт и `tides.js` с таблицей в тот же файл, а `import()` берёт его уже из сборки. Пометка честно: «Таблица теперь едет в общем файле. На ночной линии время то же: задержка у всех ответов одна». «Почти»: если сборка есть, а `index.html` грузит `./main.js`, ничего не меняется, она ждёт волнами. Пометка: «Сборка лежит в dist/, но станция всё ещё встаёт с main.js».
- **Частые ошибки:**
  - Команда без `--format=esm` → [esbuild 0.25]
    ```text
    ✘ [ERROR] Top-level await is currently not supported with the "iife" output format

        archive.js:…:
          const res = await fetch(`/api/finds`);
                      ~~~~~
    ```
    - `Top-level await` — `await` наверху файла, вне функции. Он есть в твоих `archive.js` и `cape.js`;
    - `not supported with the "iife" output format` — так по умолчанию собирается старый формат, весь код внутри одной функции, и верха файла в нём нет.

    «Допиши `--format=esm`: собрать как модуль. Рубильник не встанет, пока сборка падает.»
  - Запятая после последнего пункта в `"scripts"` → [npm 11]
    ```text
    npm error code EJSONPARSE
    npm error JSON.parse Invalid package.json: JSONParseError: Expected double-quoted property name in JSON at position 162 (line 7 column 3) while parsing near "...dist/station.js\",\n  },\n  \"devDependencie..."
    npm error JSON.parse Failed to parse JSON data.
    npm error JSON.parse Note: package.json must be actual JSON, not just JavaScript.
    ```
    - `EJSONPARSE` — npm не смог разобрать `package.json`;
    - `Expected double-quoted property name` — после запятой ждал новый ключ в кавычках, а пришла `}`;
    - `line 7 column 3` — вот где: строка 7, на ней эта `}`; лишняя запятая — в конце строки над ней;
    - `must be actual JSON, not just JavaScript` — JSON строже, чем JS.

    «Убери запятую после последнего пункта.»
  - Команда в обратных кавычках → [npm 11] `` npm error JSON.parse Invalid package.json: JSONParseError: Unexpected token "`" (0x60), ..." "build": `esbuild m"... is not valid JSON … `` и та же строка `Note: package.json must be actual JSON, not just JavaScript.` «В JSON строки только в двойных кавычках.»
  - `npm run biuld` → [npm 11]
    ```text
    npm error Missing script: "biuld"
    npm error
    npm error To see a list of scripts, run:
    npm error   npm run
    ```
    - `Missing script` — такого скрипта в `"scripts"` нет.

    «Опечатка в имени скрипта.»
  - `esbuild mian.js …` → `✘ [ERROR] Could not resolve "mian.js"` [esbuild 0.25]. «esbuild не нашёл входной файл.»
- **Код профи.** Флаги необязательные, у каждого своё измеримое последствие, и одно делается само:
  - `--minify`: сборщик убирает пробелы и укорачивает имена. Размер на ленте esbuild меньше. Честно: «На ночной линии время то же: задержка у всех ответов одна. Снаружи, на медленном интернете, меньше байт — быстрее».
  - Без флага, само: tree-shaking. Из `power.js` взят только `turnOn`, и `turnOff` в сборку не попал. «Под корпусом» поиск по `dist/station.js` слова `turnOff` ничего не находит.
  - `--splitting --outdir=dist` вместо `--outfile`: `import()` из 17.5 остаётся отдельным куском (chunk), и таблица приливов снова приходит только по кнопке. Главный файл теперь `dist/main.js`, поэтому в `index.html` путь меняется, а рядом лежит кусок `dist/tides-TMF5YLC4.js` с хэшем в имени. Размер главного файла на ленте esbuild меньше [esbuild 0.25]. Честно: «На ночной линии подъём от этого не быстрее: волна одна в обоих случаях. Снаружи меньший первый файл приходит раньше».
  - На полях: «Vite в разработке не собирает: с твоего диска файлы приходят мгновенно, и волны незаметны. `npm run build` собирает как раз для сайта в интернете».
  - На `npm install` строка `$` честно отвечает словами станции: «esbuild уже лежит в станции. Настоящий npm install качает пакеты в node_modules — это снаружи, в выгруженной папке».
- **В мире:** вместо волн — один монитор `dist/station.js`, на нём весь код станции одним файлом. Мониторы твоих файлов светятся по-прежнему: это исходники, ты правишь их. У `package.json` картинки нет, он виден «под корпусом» и на своём мониторе. Щуп на `^0.25.0`: «эта версия или новее, но совместимая». С этой задачи, пока `index.html` грузит сборку, рубильник перед запуском сам запускает `npm run build`, и две строки npm с размером файла печатаются на ленте. Пометка: «Снаружи так работает сборщик в режиме watch: пересобирает, когда ты сохраняешь файл».

### 17.7 Карта исходников (`source-map`)

- **Новое:** source map: флаг `--sourcemap`
- **Опирается на:** сборка (17.6), показ по шагам и кромка у выполненных строк (гл. 1–2)
- **Файл(ы):** `package.json`, строка `$`
- **Текст файла при входе:** (`night.js`)

```js

// мои строки.
//
// Дано:

  1. Нажми «прилив» сейчас: кромка у строк `machine.js` не загорается, станция видит только `dist/station.js`.
  2. Флаг дописывают в ту же строку `"build"`, через пробел. Потом рубильник: он пересоберёт сам. Или `npm run build` в `$`, чтобы увидеть вывод.

- **Эталонное решение:**

```json

```

```text

⚡ Done in 11ms

- **Она проверяет:** она нажимает «прилив». Кромка у строк `machine.js` в терминале вспыхивает по очереди, как до сборки, и экран показывает время. Засчитано: рядом со сборкой есть `dist/station.js.map`, а показ по шагам и ошибки снова указывают на строки твоих файлов. «Почти» здесь не бывает: флаг или есть, и карта появилась, или сборка падает (ошибки ниже), и рубильник не встаёт в зацеп.
- **Частые ошибки:**
  - `--source-map` (с дефисом) → `✘ [ERROR] Invalid build flag: "--source-map"` [esbuild 0.25]. «Флаг пишется слитно: `--sourcemap`.»
  - Флаг вынесен на отдельную строку JSON, за кавычки → `npm error code EJSONPARSE` [npm 11], как в 17.6. «Вся команда — одна строка в кавычках.»

## Глава 18. Насосная ночью — глубокая ночь (тесты)

**Место.** Насосная, тот же фон, что после полудня, ночь рисует код. Пять вентилей на трубе, люк в полосе пола, под ним сложенный трап, табло насосной. Светится твоё: табло и пятно лампы над люком.

**Её нужда.** Она устала. Она хочет сесть у трапа и отдохнуть, а вентили пусть проверяет кто-то другой. Пока ей нечем поверить, что всё работает, она сама ходит от вентиля к вентилю и крутит их, как в главе 5.

**Что учит глава.** Тест — её проверка, записанная кодом. Он работает за доли секунды и без неё. Хороший тест падает, когда код испорчен. Это проверяет сама станция: она подставляет испорченные копии твоего кода и смотрит, заметят ли их твои тесты.

**Почему задач 9, а не около 8.** Testing Library в CURRICULUM — одна тема из трёх инструментов: `getByRole`, `getByLabelText`, `user-event`. Здесь `getByRole` и `user-event` — две задачи, по одному новому в каждой. `getByLabelText` остаётся на полях как родственник `getByRole`: у вентилей нет `<label>`, и придумывать их ради метода нечестно. `toThrow` и `toContain` тоже только на полях: ни одна функция Насосной не бросает ошибок нарочно, и делать такую ради метода — выдумка (§10). Самая трудная задача — шестая (`user-event`), последняя — одна команда.

Вещи Насосной, настоящий HTML комнаты (`pumps.html`, его видно «под корпусом» и можно править, как `corridor.html` в главе 13):

```html
<div class="pipe">

```

`checked` — вентиль открыт. В HTML все пять открыты. В комнате первый и последний закрывают твои `roof.js` и `sea.js` (5.1, 5.2): они под потолком, она до них не достаёт. Она сама крутит только три средних. CSS станции из главы 5: `.hatch.open` — люк открыт, `.hatch.open + .ladder` — трап развёрнут.

**Чужой коммит.** Днём ты писал условие прямо в `if`, а его нельзя взять из другого файла. Перед этой главой станция сделала свой коммит: вынесла условия в две функции и больше ничего не поменяла. Так приходит чужой коммит на работе. `git log --oneline` показывает его сверху: `Насосная: условия в своих функциях`. Поведение прежнее, она это проверила.

`hatch.js` в начале главы:

```js
// Хочу, чтобы люк открылся, когда закрыты все вентили.
const valves = [...document.querySelectorAll(`.valve`)];
const hatch = document.querySelector(`#hatch`);

const allClosed = (list) =>
  list.every((valve) => !valve.checked);

valves.forEach((valve) => {
  valve.addEventListener(`change`, () => {
    if (allClosed(valves)) {
      hatch.classList.add(`open`);
    }
  });
});
```

`pump-board.js` в начале главы:

```js
// Хочу, чтобы табло говорило, какой закрыть сейчас.
const valves = [...document.querySelectorAll(`.valve`)];
const board = document.querySelector(`#pump-board`);

const openPipes = (list) =>
  list
    .filter((valve) => valve.checked)
    .map((valve) => valve.dataset.pipe);

const update = () => {
  const [now] = openPipes(valves);

  if (now) {
    board.textContent = `закрой ${now}`;
  } else {
    board.textContent = `тихо`;
  }
};

update();
valves.forEach((valve) => {
  valve.addEventListener(`change`, update);
});
```

**Как идут тесты.** Файл тестов называется `….test.js`. `Ctrl+Enter` или рубильник в нём запускает этот файл: станция открывает чистую страницу Насосной (её HTML, как после рубильника) и выполняет в ней файл тестов. В этой странице только HTML и то, что импортирует сам тест: `roof.js` и `sea.js` там не выполняются, поэтому все пять вентилей открыты. Каждый файл — своя чистая страница. Тесты внутри одного файла идут по очереди в одной странице.

**Бегунок.** Маленький, свой, с API как у Vitest: `test`, `describe`, `expect`. `import … from "vitest"` подставляет import map станции. Testing Library и `user-event` настоящие. Пометка говорит это прямо. После выгрузки те же файлы запускает настоящий Vitest; HTML комнаты туда кладёт файл настройки выгрузки, и это тоже сказано.

**Как это видно.** На стене щиток тестов: у каждого теста свой маленький автомат (спрайт `breaker` из среза). Тест прошёл — автомат стоит под током. Упавший `expect` выбивает только свой автомат, остальные тесты идут дальше. Отчёт печатает телетайп: строки тестов `✓` и `×` и разбор упавших, как у Vitest, но без итоговой строки со счётом.

**Испорченные копии.** Рядом второй щиток: копии `hatch.js` и `pump-board.js`, которые станция испортила руками, по одной строке в каждой. Каждая копия — автомат под током. После твоего запуска станция гоняет твои тесты на каждой копии. Если хоть один тест на копии падает, её автомат выбит: тесты поймали поломку. Если все проходят, копия остаётся под током: поломку никто не заметил. Пометка: «Так работает мутационное тестирование (Stryker). Здесь копии готовит станция, руками».

**Она.** Пока хоть одна копия под током, она не верит и сама крутит средние вентили. Когда все копии выбиты, а на настоящих файлах твои тесты проходят, она садится у трапа.

### 18.1 Первый тест (`test-tobe`)

- **Новое:** тест: `test(…)` и `expect(…).toBe(…)`
- **Опирается на:** `export` и `import` (гл. 17), `every` (гл. 5), объекты (гл. 4)
- **Файл(ы):** `pumps.test.js` (новый), `hatch.js`
- **Текст файла при входе:**

```js
// Хочу, чтобы вентили проверял тест, а не она.
//
// Дано:
// - в hatch.js есть allClosed(list): true, если все
//   вентили в списке закрыты. Её вынес коммит станции
// - вентиль для теста — простой объект:
//   { checked: false } закрыт, { checked: true } открыт
// - на щитке копий под током копия, где условие
//   перевёрнуто: !valve.checked стало valve.checked
//
// Открой allClosed другим файлам и проверь:
// один закрытый вентиль — ответ true.
import { test, expect } from "vitest";
import { allClosed } from "./hatch.js";
```

- **Пометка при входе (поля):**
  1. «Тест: `` test(`что проверяем`, () => { … }); ``.»
  2. «Проверка: `expect(что получилось).toBe(что ждём);`.»
  3. «`vitest` — пакет по имени, без `./`: где он лежит, станция знает сама. Такой список имён называется import map.»
- **Подсказки по щелчку:**
  1. Открой `hatch.js`: перед `const allClosed` нет `export`, тест её не видит.
  2. Внутри `test` одна строка: `expect`, а в нём вызов `allClosed` со списком из одного закрытого вентиля.
  3. `` test(`все закрыты`, () => { expect(allClosed([{ checked: _____ }])).toBe(____); }); ``
- **Эталонное решение:**

`hatch.js`, одно слово:

```js
export const allClosed = (list) =>
  list.every((valve) => !valve.checked);
```

`pumps.test.js`:

```js
import { test, expect } from "vitest";
import { allClosed } from "./hatch.js";

test(`все закрыты`, () => {
  expect(allClosed([{ checked: false }])).toBe(true);
});
```

Лента:

```text
✓ все закрыты
```

- **Она проверяет:** засчитано: тест проходит на настоящем `hatch.js`, а копия «перевёрнутое условие» выбита: на ней тест упал. Она перестаёт проверять руками случай «закрыто всё» и крутит теперь только по одному вентилю. «Почти»: тест, который проходит всегда, например `expect(true).toBe(true)`. Автомат теста под током, а копия тоже. Пометка: «Тест проходит, но ничего не проверяет: испорченная копия его тоже проходит».
- **Частые ошибки:**
  - Забыт `export` в `hatch.js` → `SyntaxError: The requested module './hatch.js' does not provide an export named 'allClosed'` [Node 24 / V8]. «Тест может взять только то, что файл отдаёт.» Станция грузит модули как браузер. Настоящий Vitest снаружи пишет здесь иначе: `TypeError: (0 , allClosed) is not a function` [Vitest 3.2].
  - Скобка не там: `expect(allClosed([{ checked: false }]).toBe(true))` → `TypeError: allClosed(...).toBe is not a function` [Node 24 / V8]
    - `allClosed(...).toBe` — `toBe` искали у ответа `allClosed`, а не у `expect(…)`;
    - `is not a function` — там его нет.

    «Закрой скобку `expect(…)` до `.toBe`.»
  - `` toBe(`true`) `` → `AssertionError: expected true to be 'true' // Object.is equality` [Vitest 3.2]
    - `AssertionError` — проверка не сошлась;
    - `expected true to be 'true'` — получили `true`, ждали строку `'true'`;
    - `Object.is equality` — `toBe` сравнивает «то же самое значение».

    «`true` в кавычках — строка. Ждём просто `true`.»
- **Код профи:** разницы в работе нет. Честно на полях: «Тест работает за доли секунды и без неё. Её утренняя проверка окна под корпусом станции записана так же: `test` и `expect`».
- **В мире:** на щитке тестов один автомат, `все закрыты`, под током. На щитке копий автомат «перевёрнутое условие» выбит. `pumps.test.js` висит монитором рядом с `hatch.js`.

### 18.4 Сравнить массивы (`toequal`)

- **Новое:** `toEqual`: «такой же по содержимому»
- **Опирается на:** тест (18.1–18.3), `filter`, `map` (гл. 5), `dataset` (гл. 3)
- **Файл(ы):** `pumps.test.js`, `pump-board.js`
- **Текст файла при входе:**

```js
// Хочу, чтобы тест проверял бирки на табло.
//
// Дано:
// - в pump-board.js openPipes(list) отдаёт бирки
//   открытых вентилей: [`north`, `south`]
// - бирка вентиля для теста: dataset: { pipe: `north` }
// - под током копия, которая отдаёт бирки закрытых
//
// Открой openPipes и проверь: из трёх вентилей
// выходят бирки открытых.
```

- **Пометка при входе (поля):** «`toBe` — «то же самое». Два разных массива с одним содержимым — не то же самое. Для них `toEqual`.»
- **Подсказки по щелчку:**
  1. На щитке копий снова один автомат под током. Она встала и смотрит на табло сама.
  2. `export` перед `openPipes` в `pump-board.js` и вторая строка `import` в тесте. Тест: три вентиля, у каждого `checked` и `dataset`, ждём массив бирок.
  3. `` expect(openPipes(valves)).________([`_____`, `_____`]); ``
- **Эталонное решение:**

```js
import { test, expect } from "vitest";
import { allClosed } from "./hatch.js";
import { openPipes } from "./pump-board.js";

// …тесты allClosed

test(`бирки открытых`, () => {
  const valves = [
    { checked: false, dataset: { pipe: `roof` } },
    { checked: true, dataset: { pipe: `north` } },
    { checked: true, dataset: { pipe: `south` } },
  ];

  expect(openPipes(valves)).toEqual([`north`, `south`]);
});
```

- **Она проверяет:** когда появилась копия «бирки закрытых», она встала: открывает средний вентиль и смотрит на табло, совпадает ли. Засчитано: тест проходит на настоящем коде, копия выбита. Она снова садится. «Почти»: проверена только длина ответа, например `expect(openPipes(valves).length).toBe(1)` на списке из одного закрытого и одного открытого вентиля. Копия отдаёт бирку закрытого вместо открытого, длина та же, и копия остаётся под током. Она стоит у табло. Пометка: «Длина у копии та же. Проверь сами бирки».
- **Частые ошибки:**
  - `` toBe([`north`, `south`]) `` → [Vitest 3.2]
    ```text
    × бирки открытых
    AssertionError: expected [ 'north', 'south' ] to be [ 'north', 'south' ] // Object.is equality

    If it should pass with deep equality, replace "toBe" with "toStrictEqual"

    Expected: [ 'north', 'south' ]
    Received: serializes to the same string
    ```
    - `expected [ 'north', 'south' ] to be [ 'north', 'south' ]` — с виду одинаково, но это два разных массива;
    - `serializes to the same string` — на письме они совпадают.

    «Для массивов — `toEqual`.»
  - `` toEqual([`south`, `north`]) `` → `AssertionError: expected [ 'north', 'south' ] to deeply equal [ 'south', 'north' ]` [Vitest 3.2]. «Порядок важен: сначала та бирка, что раньше в HTML.»
  - Забыт `export` перед `openPipes` → `SyntaxError: The requested module './pump-board.js' does not provide an export named 'openPipes'` [Node 24 / V8].
- **Код профи:** на полях честно: «Родственники: `` toContain(`north`) `` — «есть ли в списке», `toThrow()` — «бросает ли функция ошибку». Здесь они не нужны».
- **В мире:** на щитке тестов четыре автомата под током. Табло насосной под щупом показывает настоящий `textContent`, например `закрой north`.

### 18.5 Найти, как человек (`getbyrole`)

- **Новое:** `screen.getByRole`: искать вещь по роли и имени
- **Опирается на:** роли и доступное имя, `aria-label` (гл. 13), `import` без имён (гл. 17), пакет по имени (18.1)
- **Файл(ы):** `hatch.test.js` (новый), `pumps.html`
- **Текст файла при входе:**

```js
// Хочу, чтобы тест находил вентиль так, как его
// находит человек в темноте.
//
// Дано:
// - тест идёт в чистой странице Насосной, в ней
//   её HTML; import "./hatch.js" подключает датчики
// - вентили в pumps.html, у каждого своя бирка:
//   <input type="checkbox" data-pipe="north" …>
//
// Найди вентиль north по роли и имени «вентиль north»
// и проверь, что в начале он открыт.

```

- **Пометка при входе (поля):**
  1. «`` screen.getByRole(`роль`, { name: `имя` }) `` ищет так, как экранный диктор: по роли и доступному имени.»
  2. «Одна вещь — `getByRole`, все такие — `getAllByRole`.»
- **Подсказки по щелчку:**
  1. У `<input type="checkbox">` роль `checkbox`. А имя? Наведи щуп на вентиль: «доступное имя: пусто».
  2. Тест найдёт вентиль, когда у него будет имя: `aria-label` в `pumps.html` (`Ctrl+P` и имя файла), как в `corridor.html` в сумерках.
  3. `` const valve = screen.getByRole(`________`, { name: `вентиль north` }); `` и `aria-label="вентиль _____"`
- **Эталонное решение:**

`hatch.test.js`:

```js

Засчитано: тест проходит, у всех пяти вентилей есть имена, и она идёт прямо к вентилю `north`. «Почти»: имя дано только одному вентилю. Тест проходит, но щуп на остальных: «доступное имя: пусто». Пометка: «Тест прошёл, а остальные вентили по-прежнему безымянные».
- **Частые ошибки:**
  - До имён → [Vitest 3.2]
    ```text

      checkbox:

      Name "":

        checked=""
        class="valve"

    - `Name ""` — у вентилей имя пустое.

### 18.6 Её руки в тесте (`user-event`)

- **Новое:** `user-event`: настоящие щелчки из теста
- **Опирается на:** `getByRole` (18.5), `async` и `await` (гл. 14), `for…of` (гл. 3), `const [первый] = массив` (5.11), `export default` (гл. 17)
- **Файл(ы):** `hatch.test.js`
- **Текст файла при входе:** (сверху задача, ниже тест из 18.5)

```js
// Хочу, чтобы тест закрывал вентили её руками.
//
// Дано:
// - под током копия, которая забыла первый вентиль:
//   люк открывается, когда закрыты остальные четыре
// - люк: <div id="hatch" class="hatch">,
//   открыт — класс open
//
// Закрой все вентили, кроме первого, и проверь, что
// люк закрыт. Закрой первый и проверь, что открыт.
```

- **Пометка при входе (поля):**
  1. «`const user = userEvent.setup();` даёт руки. `await user.click(вещь)` — щелчок, как её: с теми же событиями.»
  2. «Первый и все остальные: `const [первый, ...остальные] = массив;`. Те же три точки, что в `[...список]`.»
- **Подсказки по щелчку:**
  1. Копию ловит только порядок «сначала остальные, потом первый». Если закрывать с первого, копия ведёт себя как настоящий код.
  2. `import userEvent from "@testing-library/user-event"`, тест `async`, `const [first, ...rest] = screen.getAllByRole(…)`, цикл с `await`.
  3. `` for (const valve of ____) await user._____(valve); `` и `` expect(hatch.classList.________(`open`)).toBe(_____); ``
- **Эталонное решение:**

```js
import { test, expect } from "vitest";
import { screen } from "@testing-library/dom";
import userEvent from "@testing-library/user-event";
import "./hatch.js";

test(`в начале вентиль north открыт`, () => {
  const valve = screen.getByRole(`checkbox`, {
    name: `вентиль north`,
  });

  expect(valve.checked).toBe(true);
});

test(`люк ждёт последний вентиль`, async () => {
  const user = userEvent.setup();
  const hatch = document.querySelector(`#hatch`);
  const [first, ...rest] = screen.getAllByRole(`checkbox`);

  for (const valve of rest) await user.click(valve);

  expect(hatch.classList.contains(`open`)).toBe(false);

  await user.click(first);

  expect(hatch.classList.contains(`open`)).toBe(true);
});
```

- **Она проверяет:** пока копия «забыт первый» под током, она встаёт, сама закрывает средние вентили и смотрит на люк. Засчитано: оба теста проходят, копия выбита. Она садится обратно. Тест закрывает вентили за доли секунды, и пометка честно: «Это её проверка люка, записанная кодом. Теперь её делает тест». «Почти»: тест закрывает вентили с первого по пятый. На настоящем коде он проходит, но копия под током. Пометка: «Копия забывает первый вентиль. Закрой его последним».
- **Частые ошибки:**
  - Нет `async` у функции теста → `SyntaxError: Unexpected reserved word` [Node 24 / V8]. «`await` работает только в `async`-функции.»
  - Нет `await` перед `user.click` → щелчок ещё идёт, а проверка уже бежит. `AssertionError: expected false to be true // Object.is equality` на последней строке [Vitest 3.2]. «Без `await` проверка бежит раньше её руки.»
  - `` screen.getByRole(`checkbox`) `` вместо `getAllByRole` → `TestingLibraryElementError: Found multiple elements with the role "checkbox"` [Vitest 3.2]. «Нужны все вентили: `getAllByRole`.»
  - Забыта строка `const user = userEvent.setup();` → `ReferenceError: user is not defined` [Node 24 / V8]
    - `user is not defined` — имени `user` нет: руки не выданы.

    «Сначала `userEvent.setup()`, потом щелчки.»
- **Код профи:** разницы в работе нет. Пометка: «Состояние люка проверено по классу, через `querySelector`. У люка нет роли: его не нажимают, на него смотрят».
- **В мире:** тест идёт в своей чистой странице, её не видно: в комнате ничего не щёлкает, есть лента и щиток. Щуп на автомате теста показывает настоящие события, которые сделал `user-event`: `click`, `input`, `change` на каждом вентиле.

### 18.8 Разложить тесты по группам (`describe`)

- **Новое:** `describe`: группа тестов
- **Опирается на:** тесты 18.1–18.4
- **Файл(ы):** `pumps.test.js`

// Хочу, чтобы отчёт читался по функциям.

- **Подсказки по щелчку:**
  1. Лента сейчас печатает тесты подряд, без имён функций.
  2. `describe` берут из `vitest`, как `test`. Внутрь — тесты целиком.
  3. `` import { ________, test, expect } from "vitest"; `` и `` describe(`allClosed`, () => { … }); ``
- **Эталонное решение:**

```js
import { describe, test, expect } from "vitest";
import { allClosed } from "./hatch.js";
import { openPipes } from "./pump-board.js";

describe(`allClosed`, () => {
  test(`все закрыты`, () => {
    expect(allClosed([{ checked: false }])).toBe(true);
  });

  test(`один открыт`, () => {
    const valves = [{ checked: false }, { checked: true }];

    const result = allClosed(valves);

    expect(result).toBe(false);
  });

  test(`вентилей нет`, () => {
    expect(allClosed([])).toBe(true);
  });
});

describe(`openPipes`, () => {
  test(`бирки открытых`, () => {
    const valves = [
      { checked: false, dataset: { pipe: `roof` } },
      { checked: true, dataset: { pipe: `north` } },
      { checked: true, dataset: { pipe: `south` } },

    expect(openPipes(valves)).toEqual([`north`, `south`]);
  });
});
```

Лента:

```text

✓ allClosed > один открыт
✓ allClosed > вентилей нет
✓ openPipes > бирки открытых
```

- **Она проверяет:** она сидит. Засчитано: на ленте тесты идут с именами групп, все проходят, копии выбиты. «Почти»: один тест остался вне групп — пометка: «Один тест без группы».
- **Частые ошибки:**

    - `ReferenceError` — такого имени нет;
    - `describe is not defined` — его не объявили и не импортировали.

    «Добавь `describe` в `import` из `vitest`.»
- **Код профи:** разницы в работе нет. Это для людей: в отчёте сразу видно, у какой функции беда.
- **В мире:** на щитке тестов автоматы встали двумя рядами, по группам.

## Глава 19. Комната с фальш-окном ночью — самый тёмный час (TypeScript)

**Место.** Комната с фальш-окном из главы 2. Самый тёмный час: светится только окно (твой `frame.js`) и монитор у двери. Рядом с ручкой цвета появилась вторая ручка, тот же спрайт `knob`: яркость.

**Её нужда.** Она крутит обе ручки, и ни одна ошибка не должна до неё дойти. Утром опечатка `vlaue` дала полый импульс: она крутила ручку впустую. Ночью такие ошибки должен ловить рубильник, раньше неё.

**Что учит глава.** TypeScript — тот же JavaScript, плюс типы: какого рода каждое значение. Проверка типов — шаг перед запуском. Ошибка типа не доходит до неё: рубильник просто не встаёт в зацеп.

**Почему задач 12, а не около 7.** В CURRICULUM это одна большая задача про `frame.ts` и россыпь приёмов. Перевести утренний файл сразу нельзя: в нём одиннадцать ошибок типов двух родов (проверено в tsc 5.9.3), и рубильник не встанет, пока не исправлены все. Поэтому сначала новый маленький файл `brightness.ts`, в нём по одному понятию на задачу, каждый раз с видимой победой. Утренний `frame.ts` — пятая задача, самая трудная, когда все нужные приёмы уже знакомы. Объединения, тип массива и тип события стоят в плане CURRICULUM одной строкой, но это три разные мысли, а акт VI читает первые две как знакомые. Поэтому у каждой своя короткая задача (19.9–19.11), и глава на одну задачу длиннее верхней границы в 11. Задачи короткие, вечер не растёт. Последняя — одна команда.

Трафарет `class="knob"` станция выбила на обеих ручках этой ночью, вместе со второй ручкой. Первый раз он нужен в 19.10.

`frame.js` в начале главы — твой файл с полудня (гл. 4), слово в слово:

```js
// Хочу, чтобы ручка стояла там, где её оставили.
const frame = document.querySelector(`.frame`);
const picker = document.querySelector(`#frame-picker`);

const paint = () => {
  frame.style.backgroundColor = picker.value;
  localStorage.setItem(`frame-color`, picker.value);
};

picker.value =
  localStorage.getItem(`frame-color`) || picker.value;
paint();

picker.addEventListener(`input`, paint);
```

CSS станции: ручка с классом `on` светится ярко, с классом `dim` тускло. Правило `dim` стоит ниже и побеждает, если на ручке оба. Яркость окна — `opacity`: рендер её понимает и сводит к палитре растром.

**Рубильник с проверкой типов.** Для файлов `.ts` рубильник сначала зовёт настоящий компилятор TypeScript (в воркере, грузится с этой главы), режим `strict`. Ошибка типа — рубильник не встаёт в зацеп и отскакивает, в коде засечка, как у `SyntaxError` (§3.3). Не выполняется ни одна строка, и она не узнаёт об ошибке вовсе. Текст ошибки дословный, с кодом: `TS2551`. Пока печатаешь, по-прежнему ничего не реагирует, красных подчёркиваний нет. Порядок рубильника теперь такой: проверка типов, сборка (гл. 17), запуск. Новый `brightness.ts` — файл задачи, станция сама подключила его в `main.js` (гл. 17).

**Справка на полях.** Наведи мышь на слово, и на полях настоящий тип от компилятора: `const knob: Element | null`. Значок `|` читается «или».

**Стирание типов.** Типы стираются пробелами (ts-blank-space), поэтому номера строк и столбцов в ошибках остаются твоими. «Под корпусом» видно чистый JS после стирания. Файлы `.ts` станция отдаёт по путям, как `.js`; в `import` путь пишут с `.ts`. Настройки компилятора — в `tsconfig.json`, его видно «под корпусом»: `strict`, `noEmit`, `allowImportingTsExtensions`, в `lib` — `ES2022`, `DOM` и `DOM.Iterable`.

**Тексты ошибок TypeScript** в этой главе проверены: каждый фрагмент прогнан через настоящий tsc 5.9.3 с `tsconfig.json` станции, тексты и позиции скопированы, пометка [tsc 5.9.3].

**Она** стоит между двумя ручками. После каждого запуска пробует ту, о которой задача, в трёх положениях: тёмное, среднее, светлое.

### 19.1 Тип и проверка перед запуском (`ts-null`)

- **Новое:** TypeScript: проверка типов перед запуском и `null` в типе
- **Опирается на:** `querySelector` и `null` (гл. 1), `addEventListener` (гл. 2), `?.` (гл. 6), телетайп (гл. 4)
- **Файл(ы):** `brightness.ts` (новый)
- **Текст файла при входе:**

```ts
// Хочу слышать, когда крутят ручку яркости.
//
// Дано:
// - ручка: <input type="range" id="brightness">
// - это файл .ts: перед запуском рубильник проверяет
//   типы, то есть ищет ошибки, не запуская код
// - TypeScript помнит, что querySelector может
//   ничего не найти и отдать null
//
// Повесь на ручку датчик input: на каждый поворот
// телетайп печатает «яркость».
```

- **Пометка при входе (поля):**
  1. «`.ts` — тот же JavaScript, плюс типы. Тип — какого рода значение: число, строка, вещь или `null`.»
  2. «С ошибкой типа рубильник не встаёт в зацеп, как с `SyntaxError`. До неё ошибка не доходит.»
  3. «Наведи мышь на слово — на полях его тип.»
- **Подсказки по щелчку:**
  1. Напиши, как утром, и запусти. Наведи мышь на `querySelector(…)`: тип `Element | null`, «вещь или ничего».
  2. С `null` ты уже встречался в Архиве, когда море принесло ящики: `?.` вызывает метод, только если слева не `null`.
  3. `` document.querySelector(`#__________`)__addEventListener(`input`, () => console.log(`яркость`)); ``
- **Эталонное решение:**

```ts
// Хочу слышать, когда крутят ручку яркости.
document
  .querySelector(`#brightness`)
  ?.addEventListener(`input`, () => console.log(`яркость`));
```

- **Она проверяет:** крутит ручку яркости в три положения. Телетайп трижды печатает `яркость`. Засчитано: проверка типов прошла, три строки на ленте. «Почти»: если рубильник не встал, она не узнаёт ни о чём: стоит у ручки и ждёт.
- **Частые ошибки:**
  - Как утром, без `?.` → `error TS2531: Object is possibly 'null'.` [tsc 5.9.3]
    - `error TS2531` — ошибка типа, её номер у компилятора;
    - `Object is possibly 'null'` — здесь может оказаться `null`.

    «В JS это выбило бы автомат, если бы ручки не было. TypeScript не даёт даже запустить.» Рубильник отскакивает. Засечка в начале цепочки, под `document`: компилятор отмечает весь поиск, это он может дать `null`.
  - `` querySelector(`brightness`) `` без решётки → проверка типов проходит, ручка не находится, `?.` тихо гасит импульс, на ленте пусто. Тихая. «Типы не проверяют селектор. Решётка — «по id».»
- **Код профи:** разницы в работе нет. Пометка: «Типы не делают код быстрее. Они переносят ошибку из её рук в твой терминал».
- **В мире:** при запуске рубильник сначала делает короткий холостой ход: идёт проверка типов. Прошла — клац, как обычно. Не прошла — отскок, гула нет, она не шевелится.

### 19.2 Сужение (`ts-narrowing`)

- **Новое:** сужение: внутри `if (вещь)` TypeScript знает, что `null` там нет
- **Опирается на:** `null` в типе (19.1), `if` (гл. 3), `classList.add` (гл. 1)
- **Файл(ы):** `brightness.ts`
- **Текст файла при входе:**

```ts
// Хочу, чтобы ручка светилась, когда подключена.
//
// Дано:
// - в CSS станции ручка с классом on светится
//
// Найди ручку один раз, в const. Если нашлась —
// дай ей класс on и повесь датчик.
```

- **Пометка при входе (поля):** «После `if (knob)` тип внутри уже без `null`. Это сужение: проверил — значит знаешь.»
- **Подсказки по щелчку:**
  1. Наведи мышь на `knob` выше `if`: `Element | null`. Внутри `if`: `Element`.
  2. Два действия с одной вещью: удобнее одна проверка `if`, чем два `?.`.
  3. `` const knob = document.querySelector(`#brightness`); if (____) { knob.classList.add(`__`); knob.addEventListener(…); } ``
- **Эталонное решение:**

```ts
// Хочу, чтобы ручка светилась, когда подключена.
const knob = document.querySelector(`#brightness`);

if (knob) {
  knob.classList.add(`on`);
  knob.addEventListener(`input`, () => {
    console.log(`яркость`);
  });
}
```

- **Она проверяет:** ручка светится синим. Она крутит её в три положения, на ленте три строки. Засчитано: у `#brightness` есть класс `on`, три строки. «Почти»: класс дан, датчика нет — ручка светится, ленты нет. Она крутит и ждёт.
- **Частые ошибки:**
  - Без `if` → `error TS18047: 'knob' is possibly 'null'.` [tsc 5.9.3], дважды: на строке `classList` и на строке `addEventListener`
    - `'knob' is possibly 'null'` — в `knob` может лежать `null`.

    «Проверь вещь один раз, `if (knob)`, и работай с ней внутри.»
  - `if (!knob) return;` (ранний `return`, как в главе 3) → `error TS1108: A 'return' statement can only be used within a function body.` [tsc 5.9.3]. Без проверки типов было бы `SyntaxError: Illegal return statement` [Node 24 / V8].
    - `can only be used within a function body` — `return` бывает только внутри функции, а это верх файла.

    «Ранний `return` — для функций. Наверху файла — `if (knob) { … }`.»
- **Код профи:** разницы в работе нет.
- **В мире:** ручка яркости светится синим — первое синее в комнате после окна. Щуп на `knob` внутри `if` показывает тип `Element`.

### 19.3 Сказать, что за вещь (`ts-generic`)

- **Новое:** дженерик на чтение: `querySelector<HTMLInputElement>(…)`
- **Опирается на:** сужение (19.2), `value` у поля (гл. 2)
- **Файл(ы):** `brightness.ts`
- **Текст файла при входе:**

```ts
// Хочу, чтобы телетайп печатал, где стоит ручка.
//
// Дано:
// - у ручки есть value, но TypeScript знает только,
//   что нашёлся какой-то Element
//
// Скажи querySelector, что ручка — поле ввода,
// и печатай её value на каждый поворот.
```

- **Пометка при входе (поля):** «В угловых скобках говорят, что за вещь ищем: `` querySelector<HTMLInputElement>(`#id`) ``. Это дженерик — тип как параметр.»
- **Подсказки по щелчку:**
  1. Наведи мышь на `knob`: `Element`. У `Element` нет `value`, у `HTMLInputElement` есть.
  2. Угловые скобки сразу после `querySelector`, до круглых. В датчике — `console.log(knob.value)`.
  3. `` document.querySelector<________________>(`#brightness`) ``
- **Эталонное решение:**

```ts
// Хочу, чтобы телетайп печатал, где стоит ручка.
const knob =
  document.querySelector<HTMLInputElement>(`#brightness`);

if (knob) {
  knob.classList.add(`on`);
  knob.addEventListener(`input`, () => {
    console.log(knob.value);
  });
}
```

- **Она проверяет:** крутит в три положения, лента: `20`, `60`, `100`. Засчитано: на ленте значения ручки. «Почти»: `console.log(knob)` печатает вещь целиком — пометка: «Это сама ручка. Нужно её value».
- **Частые ошибки:**
  - Без угловых скобок → `error TS2339: Property 'value' does not exist on type 'Element'.` [tsc 5.9.3]
    - `Property 'value' does not exist` — свойства `value` нет;
    - `on type 'Element'` — у того, что TypeScript знает про вещь.

    «TypeScript не видит HTML. Скажи ему, что это поле ввода.»
  - `querySelector<HTMLInputElement>` с ошибкой в имени, `HtmlInputElement` → `error TS2552: Cannot find name 'HtmlInputElement'. Did you mean 'HTMLInputElement'?` [tsc 5.9.3]. «Имена типов пишутся буква в букву: HTML заглавными.»
- **Код профи:** разницы в работе нет. На полях: «Угловые скобки — обещание о вещи. TypeScript поверит. Если по id найдётся не поле, а `div`, ошибка будет уже при запуске. Поэтому в угловых скобках пишут то, что правда стоит в HTML».
- **В мире:** щуп на импульсе с ленты показывает настоящее значение строкой: `"60"`. Тип на полях: `knob.value: string`.

### 19.4 У свойства свой тип (`ts-property-type`)

- **Новое:** тип свойства: `style.opacity` — строка
- **Опирается на:** дженерик (19.3), `style` (гл. 1), `Number()` (гл. 3), шаблонные строки (гл. 2)
- **Файл(ы):** `brightness.ts`
- **Текст файла при входе:**

```ts
// Хочу, чтобы окно тускнело вместе с ручкой.
//
// Дано:
// - окно: <div class="frame">; его яркость —
//   style.opacity, от 0 до 1
// - ручка даёт value от "0" до "100"
//
// Найди окно и на каждый поворот ставь ему
// opacity: value, делённое на 100.
```

- **Пометка при входе (поля):** «У каждого свойства свой тип. У `style.opacity` — строка, даже если в ней число.»
- **Подсказки по щелчку:**
  1. Окно ищется как утром, но с угловыми скобками: `HTMLElement`, у него есть `style`.
  2. `if (knob && frame)`. Наведи мышь на `opacity`: `string`. Число в строку переводит шаблонная строка.
  3. `` frame.style.opacity = `${Number(knob.value) / ___}`; ``
- **Эталонное решение:**

```ts
// Хочу, чтобы окно тускнело вместе с ручкой.
const knob =
  document.querySelector<HTMLInputElement>(`#brightness`);
const frame = document.querySelector<HTMLElement>(`.frame`);

if (knob && frame) {
  knob.classList.add(`on`);
  knob.addEventListener(`input`, () => {
    frame.style.opacity = `${Number(knob.value) / 100}`;
  });
}
```

- **Она проверяет:** ведёт ручку от тёмного к светлому в три положения. Окно гаснет почти до пола и снова светится: растр то реже, то гуще. Засчитано: трижды вычисленный `opacity` окна равен `value / 100`. «Почти»: `/ 10` — на середине окно уже целиком светится, `opacity` больше 1 браузер срезает до 1. Она останавливается на среднем положении. Пометка: «На середине окно уже полное. Проверь деление».
- **Частые ошибки:**
  - `frame.style.opacity = Number(knob.value) / 100;` → `error TS2322: Type 'number' is not assignable to type 'string'.` [tsc 5.9.3]
    - `Type 'number'` — ты даёшь число;
    - `is not assignable to type 'string'` — а свойство принимает только строку.

    «Оберни в шаблонную строку.»
  - Окно без угловых скобок → `error TS2339: Property 'style' does not exist on type 'Element'.` [tsc 5.9.3]. «Для `style` нужен `HTMLElement`.»
- **Код профи:** честно на полях: «В работе разницы нет: браузер сам превратил бы число в строку, и окно потускнело бы так же. TypeScript требует, чтобы ты сказал это явно».
- **В мире:** свет окна на полу тускнеет вместе с окном: параллелограмм то реже, то гуще. Щуп на окне: `opacity: "0.6"`.

### 19.5 Утренний файл на TypeScript (`ts-migrate`)

- **Новое:** перевод старого файла: ошибки читают сверху вниз и чинят по родам, а не по одной
- **Опирается на:** `null` в типе, сужение, дженерик, тип свойства (19.1–19.4), своя функция с именем и `||` (гл. 4)
- **Файл(ы):** `frame.js` → `frame.ts`
- **Текст файла при входе:**

Сверху задача, ниже код `frame.js` из начала главы, без изменений. Номера строк в ошибках ниже считаются по этому тексту: код начинается с 10-й строки.

```js
// Хочу, чтобы утренний frame.js тоже проверялся.
//
// Дано:
// - переименуй frame.js в frame.ts: щёлкни по имени
//   на шильдике терминала
// - ошибок будет сразу много, но они все знакомые
// - нельзя: as, any и знак ! после имени
//
// Добейся зацепа рубильника.
const frame = document.querySelector(`.frame`);
const picker = document.querySelector(`#frame-picker`);

const paint = () => {
  frame.style.backgroundColor = picker.value;
  localStorage.setItem(`frame-color`, picker.value);
};

picker.value =
  localStorage.getItem(`frame-color`) || picker.value;
paint();

picker.addEventListener(`input`, paint);
```

- **Пометка при входе (поля):**
  1. «Старый файл переводят так: читают ошибки сверху вниз и чинят целыми родами, а не по одной.»
  2. «`as`, `any` и `!` — способы заставить TypeScript замолчать. Здесь они не нужны, о них — после зацепа.»
- **Подсказки по щелчку:**
  1. Ошибок много, но рода у них два. `possibly 'null'` чинит `if`, `on type 'Element'` — угловые скобки.
  2. Найди обе вещи с угловыми скобками. Всё, что их трогает, оберни в `if (frame && picker)`, и функцию `paint` тоже: снаружи `if` проверка до неё не дойдёт.
  3. Строки с пропусками:

     ```ts
     const frame = document.querySelector<___________>(`.frame`);
     const picker =
       document.querySelector<________________>(`#frame-picker`);

     if (_____ && ______) {
       // paint, ручка, вызов и датчик — всё здесь
     }
     ```

- **Эталонное решение:**

```ts
// Хочу, чтобы утренний frame.js тоже проверялся.
const frame = document.querySelector<HTMLElement>(`.frame`);
const picker =
  document.querySelector<HTMLInputElement>(`#frame-picker`);

if (frame && picker) {
  const paint = () => {
    frame.style.backgroundColor = picker.value;
    localStorage.setItem(`frame-color`, picker.value);
  };

  picker.value =
    localStorage.getItem(`frame-color`) || picker.value;
  paint();

  picker.addEventListener(`input`, paint);
}
```

Рода два: `possibly 'null'` (нужен `if`) и `on type 'Element'` (нужны угловые скобки). Засечки стоят на каждом месте, номер строки на полях ставит туда курсор. Первая починка убирает сразу половину списка.

- **Она проверяет:** крутит ручку цвета в три положения: тёмное, `#3a6ea5`, светлое — окно следует. Потом ручку яркости — окно тускнеет. Рубильник: цвет на месте, стрелка ручки там же. Засчитано: проверка типов прошла, в коде нет `as`, `any` и `!` (это видно по разбору кода, без угадывания), обе ручки работают. «Почти»: зацеп добыт через `as` или `!`. Рубильник встаёт, ручки работают, но пометка: «Работает. Но это обещание, а не проверка. Попробуй без него». Задача не засчитана.
- **Частые ошибки:**
  - `if` есть, а `paint` стоит выше него → `error TS18047: 'frame' is possibly 'null'.` и `error TS18047: 'picker' is possibly 'null'.` на строках внутри `paint` [tsc 5.9.3]
    - `possibly 'null'` — здесь всё ещё может быть `null`.

    «`if` проверил вещи ниже себя. `paint` написана выше, туда проверка не дошла. Перенеси её внутрь `if`.»
  - `picker.vlaue` — утренняя тихая опечатка → `error TS2551: Property 'vlaue' does not exist on type 'HTMLInputElement'. Did you mean 'value'?` [tsc 5.9.3]
    - `Property 'vlaue' does not exist` — такого свойства нет;
    - `on type 'HTMLInputElement'` — у поля ввода;
    - `Did you mean 'value'?` — похожее есть.

    «Утром это был полый импульс, и она крутила ручку впустую. Теперь ошибку поймал рубильник, а её не позвали ни разу.»
  - `if (!frame || !picker) return;` → `error TS1108: A 'return' statement can only be used within a function body.` [tsc 5.9.3]. «Наверху файла `return` нельзя. Оберни код в `if (frame && picker)`.»
- **Код профи.** Почему без `as`, `any` и `!`:
  - `` document.querySelector(`#frame-picker`) as HTMLInputElement `` — обещание. Если ручку переименуют (`#color-picker`), `as` соврёт: в переменной `null`, и при запуске выбьет автомат `TypeError: Cannot read properties of null (reading 'value')` [Node 24 / V8]. С `if` честно: ручки нет — код внутри не выполняется, автомат цел.
  - `!` после имени — то же обещание, только короче.
  - `any` выключает проверку целиком: с ним `vlaue` снова молчит.
  - На полях честно: «Vite в разработке типы не проверяет и запускает код с ошибками типов. Проверку делают tsc перед сборкой и подчёркивания в VS Code».
- **В мире:** монитор у двери показывает уже `frame.ts`. «Под корпусом» — чистый JS после стирания: на месте `<HTMLElement>` пробелы, строки те же.

### 19.6 Функция с типом параметра (`ts-annotation`)

- **Новое:** аннотация параметра: `(percent: number)`; тип ответа TypeScript выводит сам
- **Опирается на:** тип свойства (19.4), функции-стрелки и `return` со значением (гл. 2, 14), ранний `return` и сравнение `<` (гл. 3), шаблонные строки (гл. 2)
- **Файл(ы):** `brightness.ts`
- **Текст файла при входе:**

```ts
// Хочу, чтобы окно не гасло совсем.
//
// Дано:
// - на нуле ручки окно пропадает целиком
// - самое тусклое — 10 из 100, то есть opacity 0.1
//
// Сделай функцию toOpacity(percent): ниже 10 —
// строка 0.1, иначе percent, делённое на 100,
// строкой. Скажи TypeScript, что percent — число.
```

- **Пометка при входе (поля):** «Тип параметра пишут после имени, через двоеточие: `(percent: number)`. Тип ответа TypeScript выведет сам — наведи мышь.»
- **Подсказки по щелчку:**
  1. Поставь ручку на ноль: окно исчезает, на полу ни точки.
  2. Ниже 10 — сразу `return` самого тусклого, как ранний `return`. Иначе — деление в шаблонной строке. Функция стоит над поиском вещей, вызов — в датчике.
  3. `` const toOpacity = (percent: ______) => { if (percent < __) return `0.1`; return `${percent / ___}`; }; ``
- **Эталонное решение:**

```ts
// Хочу, чтобы окно не гасло совсем.
const toOpacity = (percent: number) => {
  if (percent < 10) return `0.1`;

  return `${percent / 100}`;
};

const knob =
  document.querySelector<HTMLInputElement>(`#brightness`);
const frame = document.querySelector<HTMLElement>(`.frame`);

if (knob && frame) {
  knob.classList.add(`on`);
  knob.addEventListener(`input`, () => {
    frame.style.opacity = toOpacity(Number(knob.value));
  });
}
```

- **Она проверяет:** ставит ручку на ноль: окно еле видно, редкие синие точки, но оно есть. Середина и светлое — как раньше. Засчитано: на нуле `opacity` окна `"0.1"`, на сотне `"1"`. «Почти»: знак перевёрнут, `if (percent > 10)`. Всё выше 10 становится `"0.1"`, и окно всегда еле видно. Она крутит до светлого, окно не разгорается. Пометка: «Окно не светлеет. Проверь знак сравнения».
- **Частые ошибки:**
  - `(percent) =>` без типа → `error TS7006: Parameter 'percent' implicitly has an 'any' type.` [tsc 5.9.3]
    - `implicitly has an 'any' type` — тип не указан, и TypeScript не знает, что сюда придёт.

    «В режиме strict параметру нужен тип.»
  - `toOpacity(knob.value)` → `error TS2345: Argument of type 'string' is not assignable to parameter of type 'number'.` [tsc 5.9.3]
    - `Argument of type 'string'` — ты передал строку;
    - `parameter of type 'number'` — а функция ждёт число.

    «value — строка. Переведи: `Number(knob.value)`.»
- **Код профи:** разницы в работе нет. Пометка: «Наведи мышь на `toOpacity`: `(percent: number) => string`. Тип ответа ты не писал, TypeScript вывел его сам».
- **В мире:** на нуле на полу остаётся бледный параллелограмм из редких точек.

### 19.7 Тип объекта (`ts-type`)

- **Новое:** `type` для объекта и необязательное поле `?:`
- **Опирается на:** аннотация (19.6), `export` и `import` (гл. 17), объекты (гл. 4), `!== undefined` (гл. 3, 6)
- **Файл(ы):** `brightness.ts`, `paint.ts` (создаёшь ты), `frame.ts`
- **Текст файла при входе:** (`brightness.ts`: сверху задача, ниже код из 19.6)

```ts
// Хочу, чтобы окно красило одно место.
//
// Дано:
// - сейчас окно красят два файла, каждый по-своему
// - вид окна — объект: color — цвет, brightness —
//   яркость 0–100; каждая ручка знает только своё
//
// Сделай файл paint.ts: опиши вид окна типом Look,
// где оба поля необязательные, и функцию
// paint(frame, look). Зови её из обоих файлов.
```

- **Пометка при входе (поля):** «`type Look = { color?: string; brightness?: number };` — форма объекта. Знак `?` — поля может не быть.»
- **Подсказки по щелчку:**
  1. Ручка цвета знает только цвет, ручка яркости — только яркость. Поэтому оба поля необязательные.
  2. `paint.ts` — новый файл, `Ctrl+P`. Перенеси в него `toOpacity`. В `paint`: если есть цвет — красим, если яркость не `undefined` — гасим. `export` у `type` и `paint`. В обоих файлах ручек — `import { paint } from "./paint.ts";`, путь с `.ts`. Утренняя `paint` в `frame.ts` теперь мешает: назови её `update`.
  3. `` export const paint = (frame: HTMLElement, look: ____) => { if (look._____) …; if (look.__________ !== undefined) { … } }; ``
- **Эталонное решение:**

`paint.ts`:

```ts
export type Look = {
  color?: string;
  brightness?: number;
};

const toOpacity = (percent: number) => {
  if (percent < 10) return `0.1`;

  return `${percent / 100}`;
};

export const paint = (frame: HTMLElement, look: Look) => {
  if (look.color) frame.style.backgroundColor = look.color;
  if (look.brightness !== undefined) {
    frame.style.opacity = toOpacity(look.brightness);
  }
};
```

`brightness.ts`:

```ts
// Хочу, чтобы окно красило одно место.
import { paint } from "./paint.ts";

const knob =
  document.querySelector<HTMLInputElement>(`#brightness`);
const frame = document.querySelector<HTMLElement>(`.frame`);

if (knob && frame) {
  knob.classList.add(`on`);
  knob.addEventListener(`input`, () => {
    paint(frame, { brightness: Number(knob.value) });
  });
}
```

`frame.ts`:

```ts
// Хочу, чтобы утренний frame.js тоже проверялся.
import { paint } from "./paint.ts";

const frame = document.querySelector<HTMLElement>(`.frame`);
const picker =
  document.querySelector<HTMLInputElement>(`#frame-picker`);

if (frame && picker) {
  const update = () => {
    paint(frame, { color: picker.value });
    localStorage.setItem(`frame-color`, picker.value);
  };

  picker.value =
    localStorage.getItem(`frame-color`) || picker.value;
  update();

  picker.addEventListener(`input`, update);
}
```

- **Она проверяет:** крутит обе ручки в три положения каждую, яркость — с нулём. Засчитано: цвет и яркость меняются, на нуле окно еле видно, `paint` — единственное место, где меняется `style` окна. «Почти»: `if (look.brightness)` без `!== undefined`. На нуле условие ложно (0 — ложь, гл. 3), и окно остаётся таким, каким было. Она ставит ноль, а окно светлое. Пометка: «0 — ложь. Сравни с undefined».
- **Частые ошибки:**
  - `` paint(frame, { colour: picker.value }) `` → `error TS2561: Object literal may only specify known properties, but 'colour' does not exist in type 'Look'. Did you mean to write 'color'?` [tsc 5.9.3]
    - `may only specify known properties` — в объекте можно писать только поля из `Look`;
    - `'colour' does not exist in type 'Look'` — такого поля в типе нет;
    - `Did you mean to write 'color'?` — похожее есть.

    «В JS опечатка в имени поля молчит, и окно просто не красится. Тип поймал её до запуска.»
  - Нет `export` у `paint` → `error TS2459: Module '"./paint.ts"' declares 'paint' locally, but it is not exported.` [tsc 5.9.3]. «Отдай `paint` другим файлам: `export`.»
  - В `frame.ts` осталась утренняя `const paint`, а внутри неё уже зовётся новая → `error TS2554: Expected 0 arguments, but got 2.` [tsc 5.9.3]
    - `Expected 0 arguments` — эта `paint` ничего не принимает;
    - `but got 2` — а ей дали два значения.

    «Имя `paint` занято утренней функцией, и она зовёт сама себя. Назови её `update`.»
  - Поля `Look` без `?` → в `frame.ts` [tsc 5.9.3]
    ```text
    error TS2345: Argument of type '{ color: string; }' is not assignable to parameter of type 'Look'.
      Property 'brightness' is missing in type '{ color: string; }' but required in type 'Look'.
    ```
    - `Argument of type '{ color: string; }'` — ты передал объект только с цветом;
    - `is not assignable to parameter of type 'Look'` — а `paint` ждёт `Look`;
    - вторая строка — почему: `brightness` нет, а тип его требует.

    «Ручка цвета не знает яркость. Сделай поля необязательными: `?`.»
- **Код профи:** это он, с измеримым последствием: опечатка в имени поля больше не доходит до неё. Ещё на полях: «`interface Look { … }` — почти то же самое, что `type`. Бывает и так, читай оба».
- **В мире:** на стене новый монитор `paint.ts`, щуп на нём: его берут `frame.ts` и `brightness.ts`.

### 19.8 Неизвестное из хранилища (`ts-unknown`)

- **Новое:** `unknown`: значение неизвестного типа, которое сначала проверяют (проверка — `typeof`, её инструмент, на полях)
- **Опирается на:** `localStorage`, `JSON.parse` (гл. 4), `??` (гл. 6), сужение (19.2), `paint` и `Look` (19.7)
- **Файл(ы):** `brightness.ts`
- **Текст файла при входе:**

```ts
// Хочу, чтобы окно помнило и яркость.
//
// Дано:
// - храни яркость под ключом frame-brightness
// - в хранилище может лежать что угодно: его пишут
//   и другие версии кода, как днём в коридоре
// - JSON.parse отдаёт any, и TypeScript ему верит
//
// На поворот сохраняй. При запуске прочитай, скажи,
// что тип неизвестен, и бери, только если это число.
```

- **Пометка при входе (поля):** «`unknown` — «не знаю, что это»: пока не проверишь, пользоваться нельзя. `typeof x` называет род значения словом: `number`, `string`. Проверка: `` typeof x === `number` ``.»
- **Подсказки по щелчку:**
  1. Наведи мышь на `JSON.parse(…)`: `any`. С `any` TypeScript молчит про всё.
  2. `const saved: unknown = JSON.parse(…)`. `getItem` может дать `null`: на этот случай `` ?? `100` ``. Потом `if (typeof saved === …)`.
  3. `` const saved: _______ = JSON.parse(localStorage.getItem(`frame-brightness`) ?? `100`); if (typeof saved === `______`) { … } ``
- **Эталонное решение:**

```ts
// Хочу, чтобы окно помнило и яркость.
import { paint } from "./paint.ts";

const knob =
  document.querySelector<HTMLInputElement>(`#brightness`);
const frame = document.querySelector<HTMLElement>(`.frame`);

if (knob && frame) {
  const saved: unknown = JSON.parse(
    localStorage.getItem(`frame-brightness`) ?? `100`,
  );

  if (typeof saved === `number`) {
    knob.value = `${saved}`;
    paint(frame, { brightness: saved });
  }

  knob.classList.add(`on`);
  knob.addEventListener(`input`, () => {
    paint(frame, { brightness: Number(knob.value) });
    localStorage.setItem(`frame-brightness`, knob.value);
  });
}
```

- **Она проверяет:** ставит яркость на середину. Рубильник: окно и ручка снова на середине. Потом станция сама кладёт в хранилище чужое значение — строку `"тускло"` в JSON, будто её записал старый код. Рубильник: окно светит как по умолчанию, ручка на сотне, автомат цел. Засчитано: оба запуска так. «Почти»: без `unknown` и без проверки `typeof` в `saved` лежит `any` от `JSON.parse`, и проверка типов проходит. На чужом значении в `paint` уходит строка `"тускло"`, `opacity` становится `"NaN"`, браузер молча его не принимает, а ручка встаёт на середину. Окно и ручка показывают разное. Она останавливается. Пометка: «any пропустил строку туда, где ждали число. unknown заставил бы проверить».
- **Частые ошибки:**
  - `` JSON.parse(localStorage.getItem(`frame-brightness`)) `` без `??` → [tsc 5.9.3]
    ```text
    error TS2345: Argument of type 'string | null' is not assignable to parameter of type 'string'.
      Type 'null' is not assignable to type 'string'.
    ```
    - `'string | null'` — `getItem` даёт строку или `null`;
    - `parameter of type 'string'` — а `JSON.parse` ждёт только строку;
    - вторая строка — мешает именно `null`.

    «На случай `null` поставь запасное значение: `` ?? `100` ``.»
  - `paint(frame, { brightness: saved })` без проверки → `error TS2322: Type 'unknown' is not assignable to type 'number | undefined'.` [tsc 5.9.3]
    - `Type 'unknown'` — в `saved` неизвестно что;
    - `'number | undefined'` — а поле `brightness` необязательное: в нём число или ничего.

    «Сначала проверь, что это число.»
  - `knob.value = saved;` внутри проверки → `error TS2322: Type 'number' is not assignable to type 'string'.` [tsc 5.9.3]. «У `value` тип строка, как у `opacity`.»
- **Код профи:** это он. На полях: «Данные снаружи — из хранилища, с сервера, из файла — всегда unknown. Проверяй их на входе, и дальше типы честные».
- **В мире:** у хранилища картинки нет (§6): видно только, что окно и ручка помнят яркость. «Под корпусом» — настоящее значение в `localStorage`.

### 19.9 Только два значения (`ts-union`)

- **Новое:** объединение значений: `` type Имя = `одно` | `другое` ``
- **Опирается на:** `type` (19.7), значок `|` в типах (19.1), `classList.remove` (гл. 3), `if` / `else` (гл. 3)
- **Файл(ы):** `brightness.ts`
- **Текст файла при входе:**

```ts
// Хочу, чтобы на нуле и ручка светилась тускло.
//
// Дано:
// - в CSS станции ручка с классом dim светится тускло,
//   с классом on — ярко; нужен один из двух
// - опечатку в имени класса JS не заметит:
//   classList.add(`dimm`) просто ничего не изменит
//
// Сделай тип Glow, где можно только on или dim, и
// функцию setGlow(knob, glow): сними оба класса и дай
// нужный. Ниже 10 — dim, иначе on.
```

- **Пометка при входе (поля):** «`` type Имя = `значение` | `значение`; `` — можно только эти значения. `|` ты видел в `Element | null`, читается «или». Это объединение.»
- **Подсказки по щелчку:**
  1. Поставь ручку на ноль: окно еле видно, а ручка горит, как на сотне.
  2. Тип и функция — над поиском вещей. В датчике запомни число в `const percent`, потом `if` ниже 10 и `else`.
  3. Строки с пропусками:

     ```ts
     type Glow = `__` | `___`;

     const setGlow = (knob: HTMLElement, glow: ____) => {
       knob.classList.remove(`on`);
       knob.classList.remove(`dim`);
       knob.classList.add(____);
     };
     ```

- **Эталонное решение:**

```ts
// Хочу, чтобы на нуле и ручка светилась тускло.
import { paint } from "./paint.ts";

type Glow = `on` | `dim`;

const setGlow = (knob: HTMLElement, glow: Glow) => {
  knob.classList.remove(`on`);
  knob.classList.remove(`dim`);
  knob.classList.add(glow);
};

const knob =
  document.querySelector<HTMLInputElement>(`#brightness`);
const frame = document.querySelector<HTMLElement>(`.frame`);

if (knob && frame) {
  const saved: unknown = JSON.parse(
    localStorage.getItem(`frame-brightness`) ?? `100`,
  );

  if (typeof saved === `number`) {
    knob.value = `${saved}`;
    paint(frame, { brightness: saved });
  }

  knob.classList.add(`on`);
  knob.addEventListener(`input`, () => {
    const percent = Number(knob.value);

    paint(frame, { brightness: percent });
    localStorage.setItem(`frame-brightness`, knob.value);

    if (percent < 10) {
      setGlow(knob, `dim`);
    } else {
      setGlow(knob, `on`);
    }
  });
}
```

- **Она проверяет:** ставит ручку на ноль: ручка светится тускло. Ведёт до сотни: ярко. Снова на ноль: тускло. Засчитано: на нуле у `#brightness` есть `dim` и нет `on`, на сотне наоборот, а у параметра `glow` тип — объединение (это видно по разбору кода). «Почти»: нет `` remove(`dim`) ``. На сотне у ручки оба класса, в CSS станции `dim` стоит ниже и побеждает, ручка не разгорается. Она стоит у ручки. Пометка: «Ручка не разгорается: старый класс остался». Ещё «почти»: `glow: string`. Всё работает, но пометка: «Работает. Но `string` пропустит и `dimm`. Сузь тип». Задача не засчитана.
- **Частые ошибки:**
  - `` setGlow(knob, `dimm`) `` → `error TS2345: Argument of type '"dimm"' is not assignable to parameter of type 'Glow'.` [tsc 5.9.3]
    - `Argument of type '"dimm"'` — ты передал именно такое значение;
    - `parameter of type 'Glow'` — а можно только то, что в `Glow`.

    «Утром такая опечатка молчала. Теперь её поймал рубильник.»
  - `type Glow = on | dim;` без кавычек → `error TS2304: Cannot find name 'on'.` и то же про `dim` [tsc 5.9.3]
    - `Cannot find name 'on'` — без кавычек это имя типа, а типа с таким именем нет.

    «Значения пишут в кавычках, как обычные строки.»
  - `` type Glow = `on` || `dim`; `` → `error TS1005: ';' expected.` [tsc 5.9.3]
    - `';' expected` — разбор ждал конец строки там, где стоит `||`.

    «В типах «или» — одна черта: `|`.»
- **Код профи:** это он, с измеримым последствием: опечатка в имени класса не доходит до неё. На полях: «Так же описывают состояния: загрузка, ошибка, готово. Значений всего три, и четвёртого не написать».
- **В мире:** у ручки яркости теперь два кадра свечения. На полях при наведении на `glow`: `glow: Glow`, на `Glow`: `` "on" | "dim" ``. TypeScript пишет значения в двойных кавычках, смысл тот же.

### 19.10 Обе ручки (`ts-array`)

- **Новое:** тип массива: `Тип[]`
- **Опирается на:** аннотация параметра (19.6), дженерик (19.3), `[...список]` и `forEach` (гл. 3, 5), новый файл (гл. 17)
- **Файл(ы):** `knobs.ts` (новый)
- **Текст файла при входе:**

```ts
// Хочу, чтобы и ручка цвета светилась, когда подключена.
//
// Дано:
// - на обеих ручках теперь трафарет: class="knob"
// - «массив таких» в типе пишут со скобками: Тип[]
//
// Сделай функцию lightUp(knobs): всем ручкам в массиве
// класс on. Скажи TypeScript, что knobs — массив полей
// ввода, найди обе ручки и позови lightUp.
```

- **Пометка при входе (поля):** «`Тип[]` — массив таких: `HTMLInputElement[]`. То же самое пишут и через дженерик: `Array<HTMLInputElement>`.»
- **Подсказки по щелчку:**

### 19.11 Какую ручку крутят (`ts-event`)

- **Новое:** тип события: `({ target }: Event)` и проверка `вещь instanceof Тип`
- **Опирается на:** `({ target })` (гл. 6), сужение (19.2), аннотация параметра (19.6), `knobs` (19.10), `console.log` (гл. 4)
- **Файл(ы):** `knobs.ts`
- **Текст файла при входе:**

```ts
// Хочу, чтобы телетайп печатал, какую ручку крутят.
//
// Дано:
// - одна функция report на обе ручки: какую крутят,
//   скажет только target
// - про target TypeScript знает одно: EventTarget
//   или null. Событие может прийти откуда угодно
//
// Напиши report: печатай id и value той ручки, что
// прислала событие. Отдай report датчикам обеих ручек.
```

- **Пометка при входе (поля):**
  1. «Функции отдельно от датчика TypeScript не знает, что ей придёт. Скажи: `({ target }: Event)`.»
  2. «`вещь instanceof Тип` — `true`, если вещь этого типа. Внутри `if` тип сужен, как после `if (knob)`.»
- **Подсказки по щелчку:**
  1. Наведи мышь на `target`: `EventTarget | null`. У него нет ни `id`, ни `value`.
  2. Проверка: `target instanceof HTMLInputElement`, без кавычек. Внутри `if` можно брать `id` и `value`. Датчик вешается в `forEach`, функция отдаётся по имени, без скобок.
  3. Строки с пропусками:

     ```ts
     const report = ({ target }: _____) => {
       if (target instanceof ________________) {
         console.log({ id: target.__, value: target.value });
       }
     };

     knobs.forEach((knob) => {
       knob.addEventListener(`input`, ______);
     });
     ```

- **Эталонное решение:**

```ts
// Хочу, чтобы телетайп печатал, какую ручку крутят.
const lightUp = (knobs: HTMLInputElement[]) => {
  knobs.forEach((knob) => knob.classList.add(`on`));
};

const report = ({ target }: Event) => {
  if (target instanceof HTMLInputElement) {
    console.log({ id: target.id, value: target.value });
  }
};

const knobs = [
  ...document.querySelectorAll<HTMLInputElement>(`.knob`),
];

lightUp(knobs);
knobs.forEach((knob) => {
  knob.addEventListener(`input`, report);
});
```

Лента:

```text
{ id: 'frame-picker', value: '#3a6ea5' }
{ id: 'brightness', value: '60' }
```

- **Она проверяет:** крутит ручку цвета, потом ручку яркости. На ленте каждый раз `id` той ручки, что она крутила. Она отрывает ленту. Засчитано: на ленте верные `id` и значения от обеих ручек. «Почти»: в `report` стоит `knobs[0]` вместо `target`. На ленте всегда первая ручка. Она крутит вторую и не отрывает ленту. Пометка: «На ленте всегда ручка цвета. Какую крутят, знает target».
- **Частые ошибки:**
  - `({ target })` без типа → `error TS7031: Binding element 'target' implicitly has an 'any' type.` [tsc 5.9.3]
    - `Binding element 'target'` — имя, которое ты достал в скобках;
    - `implicitly has an 'any' type` — TypeScript не знает, что в нём.

    «Функция стоит отдельно от датчика. Скажи тип: `({ target }: Event)`.»
  - Без проверки, `console.log(target.id, target.value)` → [tsc 5.9.3]
    ```text
    error TS18047: 'target' is possibly 'null'.
    error TS2339: Property 'id' does not exist on type 'EventTarget'.
    ```
    - `'target' is possibly 'null'` — может быть и «ничего»;
    - `on type 'EventTarget'` — про него известно только, что он шлёт события.

    «Проверь, что это поле ввода: `instanceof`.» Эту же пару ошибок ты получишь, если напишешь по привычке `({ target }) => target.value` прямо в датчике.
  - `target instanceof Element` → `error TS2339: Property 'value' does not exist on type 'Element'.` [tsc 5.9.3]. «`Element` — любая вещь. `value` есть у `HTMLInputElement`.»
  - `` target instanceof `HTMLInputElement` `` в кавычках → [tsc 5.9.3]
    ```text
    error TS2359: The right-hand side of an 'instanceof' expression must be either of type 'any', a class, function, or other type assignable to the 'Function' interface type, or an object type with a 'Symbol.hasInstance' method.
    ```
    - `right-hand side` — то, что справа от `instanceof`;
    - `must be … a class, function` — там должен быть класс, а не строка.

    «`HTMLInputElement` здесь настоящее имя класса браузера. Без кавычек.»
- **Код профи:** разницы в работе нет. На полях честно: «Если вещь у тебя уже есть, как `knob`, бери её, а `target` не нужен. `target` нужен, когда функция одна на много вещей. На полке Архива так же: `if (target instanceof Element)`, и только потом `closest`». Ещё: «Бывают типы точнее: `MouseEvent`, `KeyboardEvent`, `SubmitEvent`. Наведи мышь на параметр прямо в датчике, там TypeScript подскажет сам».
- **В мире:** на её поворот датчик на ручке вспыхивает, на миг обведена ручка, откуда пришло событие. Телетайп стучит. Щуп на импульсе: настоящий `target`.
