# Программа: до уровня junior

Решение пользователя 7 (01.11.2026): игра ведёт до junior целиком. Составлено панелью: три независимых черновика (от вакансий 2026, от механики, от темпа), синтез, строгая проверка по CLAUDE.md и MECHANICS.md. Источник правил по-прежнему CLAUDE.md и MECHANICS.md; срез глав 1–2 — docs/SLICE.md.

## Устройство суток

Одни сутки на станции остаются. На экране нет ни актов, ни карты. Время видно только по свету и по твоим мониторам. Свет — это полоска дневного света из-под рулонного ставня (решение 1 от 01.11): утром бледная, днём яркая, к вечеру тускнеет, ночью её нет. Акты нужны только нам, чтобы проектировать и выпускать игру по частям.

Мест 10 вместо 8.
- Новые: Насосная, Журнальная, Аппаратная.
- «Крыша с мачтой» становится закрытой Радиорубкой под мачтой: с крыши видно море, а по решению 1 его до финала видно быть нельзя.
- «Переезд» убран, модули и сборка ушли в Аппаратную.
- Отдельной Вахтенной нет. Вахтенный пост стоит в зале проёма, у самого ставня. Последние две главы ты работаешь лицом к тому ставню, который поднимешь в финале. Это на один фон дешевле и сильнее для финала.

Первый раз места проходятся вдоль стены, к проёму. Потом игра возвращается в знакомые места: когда море приносит новое и во время ночного обхода. Твой старый код встречается там с новыми условиями (§7). Арт на возвратах дешёвый: сумерки и ночь рисует код по таблице «на ступень темнее» (этап 9 среза).

- I «Утро» (гл. 1–4): найти и зажечь. DOM, события, отладка.
- II «День» (гл. 5–9): данные и язык.
- III «Вечер» (гл. 10–13): HTML и CSS своими руками. Она пользуется тем, что ты разметил и сверстал. В гл. 13 свет в коридоре гаснет.
- IV «Ночь» (гл. 14–15): связь и HTTP. Полоски под ставнем нет, в кадре светится только твоё.
- V «Ночной обход» (гл. 16–19): она в последний раз перед рассветом обходит тёмную станцию. Ты возвращаешься к своему утреннему коду с инструментами профи: git, модули и сборка, тесты, типы. Так и выглядит работа junior: большую часть времени он работает со старым кодом.
- Пауза у Щитовой, без задачи: горит твоя первая лампа. Она поворачивается к проёму и идёт вдоль всей стены мимо твоих мониторов.
- VI «Перед рассветом» (гл. 20–21): вахтенный пост в зале проёма, React и свой журнал моря.
- Рассвет (гл. 22): тот же зал. Финал по решению 5 без изменений.

Темп. В каждом месте одна большая идея. Глава занимает один вечер: 30–70 минут, 5–11 задач. Первая задача главы — 1–3 строки и победа за минуту. Самая трудная стоит в середине, последняя короткая, после неё необязательное «как тише». Тяжёлые темы разнесены по разным главам.

Помощь тает по актам. Каждая новая тема (HTML, git, тесты, типы, React) начинается заново: полный «Дано» в первой задаче и новый инструмент на полях в общем виде (решение 6), к концу главы снова коротко. Три подсказки по щелчку остаются везде.
- I: полный «Дано» (HTML вещей, CSS станции, что сделать), пометки до трёх фраз.
- II: «Дано» — вещи и цель, пометки в одну фразу.
- III: «Дано» — цель и что она будет делать. Разметку пишешь ты, пометки называют страницу MDN.
- IV: одна строка задачи и контракт API (адрес, метод, пример ответа), как в настоящей документации.
- V: в первой задаче новой темы полный «Дано», дальше одна строка.
- Гл. 21: README с историями пользователя. Последнюю задачу пишешь ты сам, и подсказки к ней общие, про метод.
- Гл. 22: «Дано» и пометок нет, три подсказки по щелчку есть.

Много файлов (с гл. 10). Файл открывается щелчком по его монитору на стене или по Ctrl+P и имени, как в VS Code. Дерева файлов и колонок нет. Имя открытого файла — на шильдике корпуса, как в срезе.

Финал попадает сильнее прежнего:
- Позади React, типы, тесты и сборка. Две главы ты смотрел на закрытый ставень. Последний файл shutter.js — снова одна строка той же формы, что самая первая, и ты понимаешь в ней каждый символ. Под любым фреймворком лежит этот же DOM.
- После титров станция остаётся песочницей. Её можно выгрузить двумя способами.
- Первый — один .html-файл, его собирает настоящий esbuild из гл. 17. Радио и журнал в нём честно пишут «нет связи» твоей же обработкой ошибок: из файла на диске service worker не работает.
- Второй — папка проекта Vite + React + TS + Vitest с настоящей историей git. Сервер станции в ней записан обработчиками MSW, так API подменяют и на работе. Дальше работа идёт снаружи, по README из выгрузки.

## Главы

### 1. Щитовая (срез) — раннее утро

**Темы:** document; querySelector; id и класс; classList; style; textContent и шаблонные строки; const и let; первая ошибка дословно: TypeError … null.

**Что нужно ей.** Свет, чтобы дойти от полоски дневного света под ставнем до двери.

**Главная задача:**

// Хочу, чтобы в щитовой загорелась лампа.
//
// Дано:
// - на стене лампа: <div id="lamp" class="lamp">
// - в CSS станции лампа с классом on горит
//
// Найди лампу по id и добавь ей класс on.

Проверка (как в срезе): если у лампы по снимку правда есть класс on, она идёт по синему пятну к двери. С `On` или `#lamb` она стоит в полоске света у ставня, а на полях дословная ошибка и «На лампе выбито lamp, у тебя lamb». Остальные четыре задачи главы — в той же щитовой, после лампы: вторая лампа у двери по классу, табло щитовой (textContent и шаблонная строка), приглушённый свет через style, const и let.

**Код профи и его последствие.** Приёма профи здесь нарочно нет: эта глава — только победа меньше чем за две минуты. Короткая цепочка живёт в одну строку, Prettier её не трогает, и игра прямо говорит, что разницы в работе нет.

**Как это видно в мире.** Всё как в срезе. Поиск — провод, изменение — свет, null — провод в пустоту и выбитый автомат. Щуп показывает настоящий <div id="lamp" class="lamp on">. Табло щитовой — тот же monitor, текст на нём — настоящий textContent.

**Новый арт:** ничего сверх среза: bg-switchroom, lamp, monitor, lever, breaker, её листы из среза.

Задач в главе: около 5.

### 2. Комната с фальш-окном (срез) — утро

**Темы:** addEventListener; функции-стрелки; evt и target; события input, change, click; лесенка Prettier, Shift+Alt+F; найти один раз: const до датчика; ({ target }) в параметре.

**Что нужно ей.** Чтобы окно светило тем цветом, что стоит на ручке.

**Главная задача:**

Как в срезе: задача из §4, `#frame-picker` и `.frame`.

Проверка: она ставит ручку в три положения (тёмное, #3a6ea5, светлое) и каждый раз сравнивает вычисленный background-color первого `.frame` со значением ручки. Совпало трижды — она садится в свет окна. Если окно покрашено без датчика, она так и стоит у ручки.

**Код профи и его последствие.** Найти один раз (§4, шаги 8–9). У новичка провод к окну дрожит, реле трещит, агент насчитывает один поиск на событие. У профи ноль поисков, провод висит на 50 %, и море слышнее. Про ({ target }) на полях честно: «Не быстрее. Короче читать».

**Как это видно в мире.** Без изменений против §4: датчик, кабель 50 %, импульс на каждый поворот, полый импульс на vlaue.

**Новый арт:** ничего сверх среза: bg-frame-room, frame-big, frame-small, knob, её лист «крутить, сесть».

Задач в главе: около 6.

### 3. Архив находок — позднее утро

**Темы:** querySelectorAll и NodeList; forEach и for…of; dataset: значения всегда строки; if / else и ранний return; truthy и falsy, !, && и ||; Number() и === против ==; объект с данными: { tag, count }.

**Что нужно ей.** Взять находки из ящиков, где что-то лежит, и не дёргать пустые.

**Главная задача:**

// Хочу, чтобы открылись только ящики, где что-то есть.
//
// Дано:
// - ящики: <div class="drawer" data-count="2">, их шесть
// - у пустого data-count="0"
// - в CSS станции ящик с классом open выдвинут
//
// Пройди по всем ящикам и открой те, где больше нуля.

Проверка: она идёт вдоль полки и берёт находку из каждого открытого ящика. Если открыт пустой, она задвигает его и ждёт.

**Код профи и его последствие.** Главное — truthy и falsy. `if (drawer.dataset.count)` открывает пустой ящик: строка "0" непустая, значит истина. Щуп на импульсе показывает "0" в кавычках.

Второе — === без перевода в число. `count === 0` всегда false, потому что в dataset строка, и выезжают все шесть ящиков, пустые тоже. Правильно — Number(count) > 0.

Про == честно: здесь `count == 0` сработал бы, он сам приводит типы. Но тот же == считает истиной `'' == 0`. Поэтому профи переводит тип сам и пишет ===, а в выгруженном проекте за этим следит ESLint (правило eqeqeq).

Про for…of против forEach тоже честно: в работе разницы нет, только из for…of можно выйти через break.

**Как это видно в мире.** querySelectorAll — жгут ко всем ящикам. Цикл виден в трассе: импульс обходит ящики по одному в порядке разметки. dataset — бумажная бирка. У truthy/falsy и === своей картинки нет: видно последствие (выехал пустой ящик) и настоящее значение под щупом.

**Новый арт:** bg-archive (был в старом плане); shelf ≈96×40, 1 кадр; drawer ≈14×12, 3 кадра: закрыт, выдвинут, заперт; find ≈8×6, 2 вида; её лист 3: трогать, нести.

Задач в главе: около 8.

### 4. Коридор — полдень

**Темы:** чтение чужого кода станции (corridor.js); console.log({ x }) и console.table; debugger; щуп и настоящий F12 на песочнице; room.querySelector; localStorage; JSON.stringify и JSON.parse; try / catch; три типа ошибок рядом: SyntaxError, TypeError, ReferenceError.

**Что нужно ей.** Свет там, где она идёт. И окно из главы 2 должно помнить свой цвет: она идёт мимо открытой двери в его комнату.

**Главная задача:**

// Хочу, чтобы окно помнило цвет после рубильника.
//
// Дано:
// - твой frame.js из комнаты с окном
// - localStorage.setItem(`ключ`, строка) кладёт строку,
//   localStorage.getItem(`ключ`) отдаёт её или null
// - ключ: `frame-color`
//
// Сохраняй цвет на поворот ручки, ставь его при запуске.

Проверка: она ставит на ручке цвет. Рубильник даёт чистую страницу, как F5, и свет из двери комнаты с окном того же цвета. Она идёт по нему. Перед самым первым запуском станция очищает хранилище песочницы. Окно горит цветом по умолчанию, и ничего не ломается: getItem даёт null.

**Код профи и его последствие.** Первое — try / catch вокруг JSON.parse, в задаче про лампы коридора. Ты хранишь, какие лампы горят, массивом через JSON.stringify. Старый corridor.js станции ты читал в начале главы. Он по-настоящему успел записать в тот же ключ свой формат: on,off,on. Твой код его заменил, а значение в хранилище осталось, как у настоящих пользователей после обновления сайта.
- У новичка дословно SyntaxError: Unexpected token 'o', "on,off,on" is not valid JSON. Автомат выбит, лампы коридора тёмные, она стоит.
- У профи catch даёт лампы по умолчанию, и она идёт.

Второе — room.querySelector (§5). У новичка провод уходит в соседнюю комнату: свет загорается там, а она идёт здесь.

**Как это видно в мире.** debugger — стоп-кадр: мир замер, щуп читает любое значение. Консоль — лента телетайпа. У localStorage картинки нет (§6), видно только, что окно помнит цвет. Хранилище живёт на origin песочницы и поэтому переживает рубильник: каждый запуск — новая страница, но тот же сайт. Здесь на полях первый раз: песочница — обычная страница, её можно открыть в настоящем F12.

**Новый арт:** bg-corridor (был в старом плане): три дверных проёма, один из них в комнату с окном; лампы коридора — тот же спрайт lamp.

Задач в главе: около 8.

### 5. Насосная (новое место) — после полудня

**Темы:** массив: литерал, индекс, length; for, while, break и сторож; NodeList не массив: [...список] и Array.from; find, findIndex, some, every; filter и map; деструктуризация массива; состояние через classList, а не style.

**Что нужно ей.** Люк в полу откроется, только когда закрыт каждый вентиль. Тогда она сойдёт по трапу вниз и пойдёт дальше.

**Главная задача:**

// Хочу, чтобы люк открылся, когда закрыты все вентили.
//
// Дано:
// - вентили: <input type="checkbox" class="valve">,
//   их пять; checked — открыт
// - люк: <div id="hatch" class="hatch">; с классом open
//   он открыт, и под ним разворачивается трап
// - [...список] делает из NodeList массив
//
// На каждый поворот вентиля проверь все и открой люк.

Проверка: она трижды закрывает вентили в разном порядке, это настоящие click по чекбоксам. Если люк открылся раньше последнего вентиля, она не сходит вниз. Если люк открылся после последнего и трап развёрнут, она сходит по нему и скрывается под линией пола.

**Код профи и его последствие.** Первое — classList вместо style (§5). С `hatch.style.transform` люк отъезжает, а трап остаётся сложенным, и она стоит у края. Правило `.hatch.open + .ladder` в CSS станции срабатывает только по классу.

Второе — дословно TypeError: valves.every is not a function. У NodeList нет every, нужен [...valves].

Третье — while. Если ждать её циклом `while (!allClosed())`, мир застывает, клацает сторож, а её повороты не доходят до кода. Ждать её — работа датчика, а не цикла.

Про every честно: трасса показывает, что он остановился на первом открытом вентиле. По времени разницы нет, просто нет лишней работы.

**Как это видно в мире.** Импульс бежит по вентилям друг за другом — это цикл. every и some видно по тому, где импульс остановился. Бесконечный цикл ловит сторож (§3.3). Трап разворачивается настоящим CSS станции. Спуск — её обычное «идти» со сдвигом на ступень вниз за шаг, новых кадров нет.

**Новый арт:** bg-pumproom 320×180, только серые, люк в полосе пола; valve ≈12×12, 2 кадра: открыт, закрыт; hatch ≈24×8, 2 кадра; трап (.ladder) ≈10×24, 2 кадра: сложен, развёрнут.

Задач в главе: около 8.

### 6. Архив (возврат): море приносит ящики — после полудня

**Темы:** всплытие и делегирование, closest; ?. и ??; createElement, append, <template>; sort с функцией сравнения, toSorted; Set против дублей; деструктуризация объекта.

**Что нужно ей.** Море принесло новые ящики, и твой утренний код на них не работает. Она хочет открыть и новый.

**Главная задача:**

// Хочу, чтобы открывались и новые ящики.
//
// Дано:
// - твой shelf.js с утра: датчик на каждом ящике
// - полка <div class="shelf">, море кладёт на неё .drawer
// - target.closest(`.drawer`) ищет ящик вверх от щелчка
//
// Сделай так, чтобы работали все ящики, даже будущие.

Проверка: она дёргает три ящика. Во время проверки море приносит ещё один (настоящий append от кода станции), и она тянет именно его.

**Код профи и его последствие.** Делегирование (§5). У новичка новый ящик мёртвый, а у профи работает сразу, и вместо 24 кабелей висит один. Слушателей считает агент.

Обратная сторона «найти один раз» (§5). Море меняет разбухший ящик на новый через replaceWith, а const держит снятый: щуп показывает isConnected: false, провод уходит за полку в пустоту.

?? вместо ||: честный 0 на бирке остаётся нулём.

Сортировка. Без функции сравнения номера 1, 10, 11, 2 встают как строки, и она останавливается не у того ящика. sort ещё и переставляет сам массив finds. Поэтому экран #manifest, который показывает порядок прихода, тоже перемешивается. toSorted делает копию.

**Как это видно в мире.** Всплытие видно буквально: импульс поднимается от ящика к полке. Щелчок в щель между ящиками — closest даёт null, и ?. гасит импульс у предохранителя (§5). Созданные ящики — заранее нарисованный тип вещи, их порядок — настоящий порядок в DOM. У Set картинки нет: просто нет второго ящика.

**Новый арт:** нового фона нет: bg-archive; 1–2 новых вида находок; экран #manifest — готовый monitor.

Задач в главе: около 9.

### 7. Журнальная (новое место) — день к вечеру

**Темы:** строки: trim, toUpperCase, includes, split / join, slice, padStart; числа: Number, parseFloat, NaN, toFixed, Intl.NumberFormat; регулярные выражения: test, match, replace; Date и Intl.DateTimeFormat с timeZone; reduce; textContent против innerHTML.

**Что нужно ей.** Записать в журнал станции сегодняшние находки так, чтобы бирку можно было прочитать.

**Главная задача:**

// Хочу, чтобы бирка на экране читалась: AB-007.
//
// Дано:
// - поле <input id="tag">: она набирает бирку с находки
//   как попало: ` ab-7 `, `Ab-12`
// - экран <pre id="entry">
// - trim() срезает пробелы по краям,
//   padStart(3, `0`) дописывает нули слева
//
// Приводи бирку к виду AB-007 и выводи на экран.

Проверка: она приносит три находки и набирает с них бирки ` ab-7 `, `Ab-12` и `AB-123`. Каждый раз на экране должно стоять AB-007, AB-012, AB-123, иначе она не кладёт находку на стойку. Вес ("0.40" → 0,4 кг), время по бирке и итог за день — следующие задачи главы, по одной на инструмент.

**Код профи и его последствие.** Регулярное выражение /^[A-Z]{2}-\d{3}$/ вместо includes(`-`). includes пропускает мусорную бирку TAB-LE, на экране появляется лишняя строка, и эту находку она не берёт.

textContent против innerHTML. Подпись `кассета <tape>` через innerHTML теряет `<tape>`: браузер принял его за тег, щуп показывает новый пустой элемент. Через textContent текст остаётся целым.

**Как это видно в мире.** У строк и чисел картинки нет (§6). Их видно на экране ЭЛТ (textContent), на ленте и щупом: "0.40" в кавычках — это строка. Условие видно по трассе: импульс отскакивает ровно от строки `if (!re.test(tag)) return;`. В журнале станции только её находки, никаких записей прежнего смотрителя (§10).

### 8. Сигнальная — предвечерье

**Темы:** setTimeout, setInterval, clearInterval; область видимости: блок, функция, модуль; замыкания: функция-фабрика, счётчик; let и var в цикле с таймером; ReferenceError до объявления; порядок: синхронный код, Promise.then, setTimeout 0; { once: true }; AbortController в «горячей» комнате.

**Что нужно ей.** Сигнальный фонарь, который мигает и вовремя гаснет.

**Главная задача:**

// Хочу, чтобы фонарь мигнул пять раз и погас.
//
// Дано:
// - фонарь <div id="beacon" class="beacon">,
//   с классом on горит
// - setInterval(функция, мс) повторяет и даёт номер,
//   clearInterval(номер) останавливает
//
// Мигай раз в 400 мс, остановись после пятой вспышки.

Проверка: она стоит у фонаря и ждёт. Агент считает настоящие смены класса через MutationObserver. Нужно ровно пять вспышек, и потом в песочнице не должно остаться живых интервалов. Если clearInterval забыт, фонарь тикает дальше, а она продолжает ждать.

**Код профи и его последствие.** var в цикле с таймером. Три импульса выходят вовремя, но каждый идёт в beacons[3], и три ветки выбивает дословный TypeError: Cannot read properties of undefined (reading 'classList'). С let у каждого круга свой i.

AbortController (§5). В «горячей» комнате после трёх запусков новичка один поворот рычага мигает трижды, у профи один раз.

Порядок цикла событий — короткая задача кодом, а не викторина. «Позже» печатается через setTimeout(…, 0), «потом» — через Promise.resolve().then(…). Телетайп должен напечатать «сразу», «потом», «позже». Она отрывает ленту, только если порядок верный. Игра честно говорит: в работе это почти не встречается, но это спросят на собеседовании.

**Как это видно в мире.** setTimeout — импульс, который выйдет позже, щуп показывает, сколько осталось. setInterval пульсирует сам. Забытый интервал тикает, и у этого шума есть видимый двойник. Замыкание: в стоп-кадре debugger щуп показывает, какие переменные держит функция, как Scope в DevTools. Долгий цикл замораживает мир, и её нажатие ждёт: агент меряет настоящую задержку.

**Новый арт:** bg-signal (был в старом плане); beacon ≈12×16, 2 кадра; рычаг #beacon-lever ≈10×16, 2 кадра.

Задач в главе: около 9.

### 9. Сигнальная — закат

**Темы:** объект с методами; this: кто вызвал; потеря this, когда метод отдают датчику; стрелка и bind; class: constructor, методы, поля, #приватные; прототип: где живут методы класса (щуп); extends и super; class StormError extends Error; Map: ключом может быть сама вещь; класс или замыкание: честно; по желанию: свой элемент, customElements.define.

**Главная задача:**

//
// Дано:
// - фонари <div class="beacon" data-ms="300">, их три

//
// Допиши start и stop, создай Beacon на каждый фонарь.

Проверка: агент меряет ритм каждого фонаря по времени смены класса. Потом она нажимает stop под средним. Гаснуть должен только средний, два других продолжают мигать.

**Код профи и его последствие.** У каждого экземпляра свой #timer. Новичок держит один let timer на весь файл. Второй фонарь затирает таймер первого, и stop гасит не тот фонарь, это видно по ритму.

Про this. Если отдать beacon.stop датчику кнопки, this станет кнопкой, и V8 пишет дословно TypeError: Cannot read private member #timer from an object whose class did not declare it. Профи пишет () => beacon.stop().

Map. Чтобы по нажатию найти объект фонаря, новичок кладёт их в обычный объект: beacons[el] = …. Ключ обычного объекта — строка, и все три фонаря становятся одним ключом "[object HTMLDivElement]": stop под любым фонарём гасит последний созданный. Щуп показывает этот ключ. Map держит ключом саму вещь.

На полях честно: «Замыкание сделает то же. Класс удобен, когда вещей много и у каждой своё состояние».

**Как это видно в мире.** У класса картинки нет. Видны экземпляры: три фонаря, у каждого провод (50 %) к своему объекту. Щуп на экземпляре показывает [[Prototype]]: start и stop лежат один раз в Beacon.prototype, а #timer у каждого свой. Щуп на импульсе показывает настоящий this, в ошибке это <button>. Своя ошибка выглядит как тот же выбитый автомат, только в тексте твоё имя. Свой элемент <sea-beacon> до define — серая пластина с именем тега (§9), после define это вещь (настоящий :defined). Фонари стоят внутри, а не на мачте: мачта снаружи, а небо до финала не видно.

**Новый арт:** нового фона нет: bg-signal, закат рисует код; стойка фонарей — часть bg-signal; key ≈8×6, 2 кадра: отжата, нажата (дальше нужна в гл. 10–13).

1. progress.js (этап 9) хранит файлы станции как виртуальную папку «путь → текст» (station/lamp.js вместе с room.html и room.css).

2. Агент должен уметь запускать файл по пути, а не только из blob-URL (этап 2). Сейчас blob годится. Но import по относительному пути из blob-модуля не работает, а с гл. 10 страницы и модули пойдут по настоящим путям через service worker. Достаточно не зашивать blob в интерфейс агента.
3. Трасса `__s(n)` (этап 10) записывает каждое выполнение, а не только первое. Это нужно для every и find (гл. 5–6) и для тестов (гл. 18).

## Риски

- Длина: 22 главы. Меры: глава — один вечер, первая задача главы на минуту, тяжёлые темы разнесены, после каждого акта заметно меняется свет, выгрузка доступна в любой момент.
- Повторы мест (Архив, Журнальная, Сигнальная, Аппаратная — по два-три раза) могут показаться повтором. Меры: при каждом возврате другой свет, а старый код ломается в новых условиях.
- Главы про инструменты (git, сборка, тесты, типы) легко превращаются в «работу для тебя». Меры: у каждой есть её маленькая нужда ночью — взять ящик, дождаться подъёма станции, отдохнуть, покрутить ручку.
- Числа на ленте и экранах: вывод твоего кода, хэши git, Expected/Received. Это текст программ, как console.log. Правило §7 записать именно так и проверять в каждой главе. Итоговой строки со счётом тестов, процентов и времени нет нигде.
- Синтетическое событие не нажимает Tab и не двигает фокус. Поэтому она идёт по порядку, который считает user-event, а настоящий Tab проверяет сам игрок. :focus-visible после focus() из скрипта может не включиться: проверить в Chrome и Firefox до гл. 13, запасной путь — focus({ focusVisible: true }). Esc, Ctrl+Enter и Shift+Alt+F должны работать и из песочницы: агент пересылает их игре.
- Пузырь проверки формы браузер рисует своим окном поверх кадра. Станция гасит его через preventDefault у invalid и показывает validationMessage щупом. Этот текст браузер пишет на языке своего интерфейса, иногда по-русски. Это не ошибка JS: показывать как есть и так и подписать.
- Service worker нужен уже с гл. 10: файлы по путям. На первой загрузке страница идёт без него, нужен clients.claim. После зависания песочница переезжает на новый хост run-N.localhost. Там worker надо зарегистрировать заново, а localStorage и IndexedDB пусты. Станция переносит их через агента и говорит это. На «пустом» origin GitHub Pages worker не работает вовсе: нужен второй настоящий сайт (это уже есть в SLICE).
- import по относительному пути из blob-URL не работает (Failed to resolve module specifier). Поэтому модули отдаются по путям. Импорт-карта стоит в run/index.html до первого модуля: импорт-карту, добавленную после загрузки модулей, браузеры постарше игнорируют.
- CORS сам не сработает. Vite по умолчанию разрешает запросы с localhost и 127.0.0.1, а GitHub Pages отдаёт Access-Control-Allow-Origin: *. Для урока нужен адрес, где заголовка нарочно нет: в разработке выключить cors у Vite, на сайте песочницы — свой _headers. Проверить на обоих.
- Вес: компилятор TypeScript, esbuild-wasm и React — мегабайты. Грузить лениво, в воркерах, с главы, где они нужны, и кэшировать.
- React и часть Testing Library публикуются в CommonJS и тянут зависимости. Их нужно заранее собрать в ES-модули при сборке игры, в development-версии, чтобы предупреждения были на месте.
- git внутри — подмножество команд. diff и revert наши, тексты вывода — дословные формулировки git, говорить это прямо. Слияние с маркерами в isomorphic-git (abortOnConflict: false) проверить заранее.
- Бегунок тестов — не Vitest, хотя отчёт в его формате, и это сказано прямо. В jsdom после выгрузки нет вёрстки.
- Номера строк после TS и JSX. ts-blank-space держит позиции, JSX идёт через карту исходника. Проверить, что ошибка показывает строку игрока, как в этапе 10 среза.
- React рисует любые теги, а рендер знает только набор вещей. Компоненты строятся из известных вещей, незнакомый тег — серая пластина с именем (§9). Агент должен отличать мутации React от мутаций игрока.
- Табло вахты и README журнала не должны стать дашбордом или списком квестов: одна история за раз, без галочек и счётчиков. Лампа «всё у проёма» вместо числа неотмеченных.
- Новые звуки (автоматы тестов, строка git, провод наружу) сразу заносить в таблицу звуков с видимым двойником и подписью (решение 4).
- Настоящая вёрстка в кадре 320×180: поля и пульты размером в десятки пикселей. До гл. 10 нужен макет набора полей. Размер rem в CSS станции свой, и это сказано прямо.
- Ctrl+P перехватить у браузера (печать) и проверить в обеих раскладках; у перехода к файлу есть видимый аналог — щелчок по монитору.
- Даты: у игроков разные часовые пояса. Во всех задачах время только с явной зоной.
- Журнал станции и находки не должны превратиться в записки с историей (§10): только её находки, без прежнего смотрителя.
- Без её новых анимаций: спуск по трапу — это «идти» со сдвигом вниз, а пульт лежит на конторке, а не у неё в руках. Каждую новую сцену проверять на восемь действий.

## Открытые вопросы

1. Сроки. Весь путь до junior — это 5–7 месяцев работы после среза, а не 2–3. Выпускать игру по частям: сначала утро и день (гл. 1–9), потом вечер и так далее? Я за выпуск по частям.
2. Git внутри игры. Внизу того же ЭЛТ появляется строка для команд (`$`). Git в ней настоящий, но команд около десяти, это не полная командная строка. Enter в ней — тот же запуск, что рубильник. Или git только снаружи, после выгрузки? Я за строку внутри.
3. CSS при наборе. Пока печатаешь, закрытый селектор правила тянул бы провода ко всем подходящим вещам, как querySelectorAll. Код при этом не выполняется, но это расширение закона «реагируют только две вещи». Без твоего слова CSS при наборе молчит. Я за провода.

## Почему так

Что я исправил после проверки по CLAUDE.md и MECHANICS.md:

1. Свет. По решению 1 от 01.11 свет — полоска из-под рулонного ставня, а не «щель» и не «косая полоса». Фонари гл. 9 стоят на стойке внутри Сигнальной, а не на мачте: мачта снаружи, а небо до финала не видно.
2. Вахтенная — не новое место, а вахтенный пост в зале проёма. Один фон на гл. 20–22, и ставень, на который ты смотришь две главы, поднимается в финале. Мест 10, фонов на один меньше.
3. Гл. 3. Два приёма профи противоречили друг другу: с размытой биркой `==` и Number() > 0 давали разные «правильные» ответы. Оставлено честное:
   - строка "0" — истина;
   - `count === 0` со строкой открывает все ящики;
   - про == сказано, что здесь он сработал бы и почему профи его не пишет (eqeqeq).
4. Гл. 4. JSON.parse для строки цвета не нужен, задача была натянутой. Главная задача — простая строка под ключом из «Дано». try/catch перенесён в задачу про лампы коридора. Там старый corridor.js станции правда успел записать старый формат on,off,on. Текст ошибки V8 проверен в Node 24.
5. Гл. 5. Подъём по лестнице — новая анимация, её нет среди восьми действий. Вместо лестницы трап: она сходит по нему шагом «идти».
6. Гл. 7. Главная задача давала восемь новых инструментов сразу. Теперь в ней только бирка, остальное — отдельными задачами. Она набирает бирку в поле, это знакомый датчик. Неверный факт: `<3 кг` через innerHTML остаётся текстом, потому что после < не буква. Заменено на `<tape>`, который браузер правда принимает за тег. Map ушёл в гл. 9.
7. Гл. 9: Map с измеримым последствием. Обычный объект делает все фонари одним ключом "[object HTMLDivElement]". Прототипы показывает щуп.
8. Гл. 8. Порядок цикла событий проверяет она: отрывает ленту только при верном порядке. Игра честно говорит, что это для собеседования.
9. Гл. 10. Пузырь проверки формы — родное окно браузера, оно всплыло бы поверх кадра. Станция гасит его и показывает тот же текст щупом. allow-forms и перезагрузку формой хост должен пережить.
10. Гл. 11. Спрайт не растягивается под рамку вёрстки, иначе ломается пиксельная сетка.
11. Гл. 12. Нажимать на пульт, держа его в руках, — новая поза. Пульт лежит на конторке.
12. Гл. 13. Контраст 1,3:1, а не 1,2 (посчитано). Tab нельзя нажать синтетическим событием: она идёт по порядку, который считает user-event, а настоящий Tab проверяешь ты. Риск :focus-visible после focus() из скрипта вынесен в проверку.

14. Гл. 16–17. .gitignore перенесён в гл. 17: до сборки игнорировать нечего. diff и revert в isomorphic-git нет, их делаем мы, сказано прямо. Задача git — комментарий в shelf.js, как все задачи.

16. Гл. 18. Итоговой строки со счётом тестов нет: это ближе всего к очкам. Испорченные копии станция готовит руками, сказано.
