# План вертикального среза

Главы 1 (`#lamp`) и 2 (комната с фальш-окном, `#frame-picker`). Источник правил — `CLAUDE.md` и `docs/MECHANICS.md`; этот файл — порядок работы. Составлен 31.10.2026: три независимых черновика, синтез, проверка по правилам проекта, исправление.

Каждый этап заканчивается тем, что можно открыть в браузере (`npm run dev`) и увидеть. После каждого — коммит и пуш.

## Этап 1. Кадр: тёмная щитовая и ЭЛТ, в котором можно печатать

**Цель.** С первой сессии увидеть игру: пиксельная комната, белая полоса из щели ставня, верх большого ЭЛТ на переднем плане, и в нём можно печатать чётким шрифтом. Заодно закрыть риски экрана: целый множитель на любом мониторе, чёткий текст на 60 колонок внутри пиксельной рамки и место на полу для всего, что будет в срезе.

**Что строим:**

- Проект без шаблона Vite (в шаблоне лишние counter.js и картинки). package.json с `"type": "module"`. Зависимости: vite, @codemirror/state, view, commands, language, lang-javascript, @fontsource/jetbrains-mono (обычный и курсив, с кириллицей). Prettier ставим точной версией: `npm i -D -E prettier@3.9.10` (сейчас это latest в npm). Позже браузер берёт prettier/standalone из этого же пакета
- Скрипты без Unix-команд, чтобы работали в Windows: dev, build, test (`node --test`, встроен в Node 24), format, check (prettier --check, затем test, затем `python tools/check_palette.py assets/sprites`)
- `.gitattributes` (`* text=auto eol=lf`, png/webp/woff2 — binary), затем `git add --renormalize .` и повторный checkout рабочих файлов: при core.autocrlf=true иначе Prettier ругается на CRLF. Ещё `.editorconfig`, `.prettierrc` (printWidth 80 для исходников игры), `.prettierignore` (docs, assets, tools, *.md)
- vite.config.js: `server.host: '127.0.0.1'`, порт 5173, strictPort. В начале index.html маленький скрипт: если страница открыта на 127.0.0.1 (так печатает Vite), перейти на тот же адрес на localhost. Игра всегда живёт на одном origin, и прогресс потом не «пропадёт»
- src/screen/scale.js: S = floor(min(innerWidth·dpr/320, innerHeight·dpr/180)) в физических пикселях, CSS-переменная --u = S/dpr, кадр по центру со сдвигом на целое число физических пикселей. Проверка через ResizeObserver devicePixelContentBoxSize, пересчёт при resize и при смене dpr
- src/screen/layout.js: все прямоугольники кадра в пикселях сцены (корпус, кромка, стекло, номера строк, код, разделитель, поля, рубильник, полоса пола). Два набора, «крупный» и «компактный»; клавиша переключает их только в режиме разработки
- src/render/canvas.js (буфер 320×180, вывод без сглаживания), src/render/palette.js (9 цветов из assets/palette.json: одна палитра на игру и Python-скрипты), src/render/sprites.js
- src/rooms/switchboard/backdrop.js: временная щитовая кодом — серые стены и пол, ставень, белая щель и полоса на полу, тёмный дверной проём. Рамку ЭЛТ тоже рисует код, пока нет ответа на вопрос 1
- Макет пола (только в разработке, по клавише): в обоих вариантах терминала поверх временной комнаты рисуются места под всё, что появится в срезе — полоса пола, по которой она ходит, белая полоса, пятно лампы до порога двери, синий параллелограмм от окна, силуэт 14×36 стоя и сидя. Вариант выбираем по всей картинке, а не только по размеру кода
- src/terminal/editor.js + theme.js: CodeMirror 6 без basicSetup. Есть история, номера строк, Tab = отступ в 2 пробела. Нет автоскобок, автодополнения и подчёркиваний, перенос строк выключен. Подсветка только яркостью (§8): мел #C9CDD2, ключевые слова белые, комментарии #9AA1A9. Лигатуры выключены (`font-variant-ligatures: none` и `"liga" 0, "calt" 0`). Редактор монтируется только после `document.fonts.load('1em "JetBrains Mono"')`, при смене множителя вызывается `requestMeasure()`. Первая строка файла — комментарий-задача главы 1, код пишется со второй
- src/terminal/notes.js: колонка полей справа (пока одна статичная пометка); имя файла `lamp.js` на шильдике корпуса с самого начала
- Выгрузка кадра 320×180 в PNG по клавише (только в разработке), чтобы на каждом этапе прогонять кадр через tools/check_palette.py

**Что увидишь.** `npm run dev` → открываешь ссылку, которую напечатал Vite, и адрес сам меняется на http://localhost:5173. Тёмная серая щитовая, сквозь щель ставня на пол падает белая полоса. Внизу слева на переднем плане верх большого ЭЛТ, его низ срезан краем кадра. В стекле файл `lamp.js`: первая строка — задача, курсор на второй. Печатаешь — буквы чёткие, `=>` видно как два знака. Тянешь окно — картинка меняет размер ступеньками ×3/×4/×5/×6 и ни разу не мылится. Одна клавиша разработчика переключает крупный и компактный терминал, другая показывает макет пола: где лягут пятно лампы и параллелограмм окна и где она будет стоять и сидеть.

**Ассеты:**

- Обязательных нет: комнату и рамку ЭЛТ рисует код. Пока идёт этап, Codex рисует лампу (нужна к этапу 4). Терминал заказываем после ответа на вопрос 1

**Рисует код:**

- временная щитовая (серые плоскости), ставень и тёмный дверной проём
- белая щель в ставне и полоса света на полу
- рамка ЭЛТ, пока нет ответа на вопрос 1
- пунктирный разделитель кода и полей (#2C3034)
- макет пола с местами под свет и силуэт (только в разработке)
- поля #1B1B1B вокруг кадра

**Какие риски закрывает:**

- целый множитель при масштабе Windows 125/150 % и при зуме браузера: считаем в физических пикселях
- чёткий текст в пиксельной рамке: размер шрифта через --u, без `transform: scale` (он мылит текст и сбивает замеры CodeMirror)
- 60 колонок и поля помещаются на ×3–×6
- лигатуры JetBrains Mono (они в calt) выключены
- CodeMirror меряет знаки уже загруженного шрифта
- на полосе пола хватает места для всего среза: видно в макете
- прогресс привязан к одному адресу игры
- CRLF при core.autocrlf=true против Prettier
- Vite и Node 24 на Windows

**Готово, когда:** В окне 1280×720 холст ровно 1280×720 физических пикселей (devicePixelContentBoxSize), то же при масштабе Windows 125 %. На увеличенном скриншоте каждый пиксель сцены — квадрат без полутонов. Строка из 61 знака `=`: 60 стоят до разделителя, 61-й уехал; то же сразу после перезагрузки с пустым кэшем. Видно 12 строк. `=>` и `!==` не склеены. Ссылка http://127.0.0.1:5173 сама переходит на localhost. В макете пола в обоих вариантах целиком видны полоса пола, белая полоса, пятно лампы, параллелограмм и силуэт 14×36. Выгрузка кадра проходит check_palette. `git ls-files --eol` показывает lf у всех текстовых файлов. `npm run check` зелёный. Закоммичено и запушено.

## Этап 2. Лампа загорается по-настоящему: песочница, рубильник, силуэт

**Цель.** Первая настоящая победа и сразу самый тяжёлый риск. Набрал строку, нажал Ctrl+Enter или щёлкнул рубильник — код выполнился в настоящем DOM на отдельном origin, лампа зажглась, силуэт пошёл к двери. Песочница пока простая: снимки состояния, без трассы.

**Что строим:**

- public/run/index.html, agent.js (модуль, единственный скрипт страницы) и core.js (чистые функции агента: сборка снимка, разбор стека, реестр вещей). Vite отдаёт public как есть, без HMR-клиента, поэтому в разработке и на сайте это одни и те же байты. core.js импортируют и агент, и `node --test`
- Агент первым делом сохраняет настоящие функции и геттеры браузера: Reflect.apply, Object.getOwnPropertyDescriptor, querySelector/All, геттеры classList, id, className, value, textContent, isConnected, getBoundingClientRect и геттеры DOMRect, getComputedStyle и getPropertyValue, MutationObserver, методы WeakMap, MessagePort.prototype.postMessage, JSON.stringify, performance.now, setTimeout, requestAnimationFrame. Вызывает всё через сохранённый Reflect.apply. Внутри агента нет for-of, spread и методов массивов. Цель — не крепость (безопасность даёт отдельный origin), а чтобы эксперимент игрока не ломал снимки
- Порт MessageChannel агент принимает один раз и только от origin игры из своего списка. Если его origin совпал с origin родителя, отказывается работать
- Агент строит комнату из HTML и CSS, которые присылает игра (src/rooms/switchboard/room.html и room.css, импорт `?raw`), и сразу привязывает вещи манифеста к самим элементам в закрытом WeakMap. Поэтому после `lamp.id = 'x'` лампа не теряется
- Файлы игрока агент запускает через import() из blob-URL, поэтому номера строк совпадают с файлом. Ошибку передаёт дословно: `String(error)` и место из стека
- Снимок вещей сразу после запуска и по MutationObserver: есть ли вещь, классы, вычисленный background-color, рамка из настоящей вёрстки (CSS станции написан в координатах сцены)
- src/sandbox/host.js: на каждый запуск новый iframe `sandbox="allow-scripts allow-same-origin"` на http://127.0.0.1:5173/run/. iframe лежит под холстом внутри окна (pointer-events: none): Chrome тормозит чужие кадры вне экрана. Агент шлёт пульс раз в 250 мс. Пропал дольше секунды — iframe удаляется, и следующий запуск идёт на новый хост run-1.localhost, потом run-2.localhost… (каждый — отдельный сайт и отдельный процесс)
- src/rooms/switchboard/manifest.js: `#lamp` → лампа, класс `on` = кадр «горит». Пока нет спрайта, лампа — заглушка кодом в палитре
- Рубильник-заглушка кодом, 2 кадра (разомкнут, замкнут); щелчок по нему = Ctrl+Enter. Сам Ctrl+Enter — через Prec.highest (иначе CodeMirror вставит пустую строку) и глобально, когда фокус вне терминала
- src/girl/stub.js: силуэт кодом, 1 кадр, покачивание на 1 px. Стоит в белой полосе. Если снимок говорит, что у лампы есть класс `on`, идёт к дверному проёму. Это заглушка сценария главы 1; на этапе 9 её заменит спрайт
- Сырой текст ошибки на полях, без разбора (разбор — на этапе 8), чтобы опечатка не была немой
- tests/agent-core.test.js: разбор стеков V8 и Firefox, сборка снимка

**Что увидишь.** Печатаешь строку — лампа не горит: пока печатаешь, ничего не выполняется. Ctrl+Enter или щелчок по рубильнику — лампа загорается, силуэт выходит из белой полосы и идёт к двери. Стёр `.classList.add(…)` и запустил — лампа тёмная, силуэт снова стоит в полосе: каждый запуск начинается с чистой страницы. С опечаткой `#lamb` лампа тёмная, а на полях дословно `TypeError: Cannot read properties of null (reading 'classList')`.

**Ассеты:**

- Обязательных нет: лампа, рубильник и силуэт — заглушки кодом. Codex тем временем рисует lamp (этап 4)

**Рисует код:**

- лампа-заглушка: серый корпус, в кадре «горит» синее стекло
- рубильник-заглушка на 2 кадра
- силуэт 14×36 с покачиванием на 1 px
- комната, которая честно гаснет, если игрок стёр DOM

**Какие риски закрывает:**

- отдельный origin в разработке
- агент сильнее кода игрока: функции и геттеры сохранены до его запуска, вещи привязаны к элементам
- каждый запуск — чистая страница, слушатели не копятся
- песочница на другом сайте живёт в отдельном процессе
- после зависания следующий запуск работает: новый хост, новый процесс
- браузер не тормозит iframe, который лежит под холстом
- снимки через postMessage (первая версия)
- у Ctrl+Enter с первого дня есть видимый аналог — рубильник
- «первый успех до двух минут»: свет → она идёт уже здесь

**Готово, когда:** С `` .classList.toggle(`on`) `` каждый Ctrl+Enter даёт «горит», а не горит/не горит по очереди. Щелчок по рубильнику делает то же, что Ctrl+Enter. `parent.document` → на полях дословная SecurityError, игра цела. После `` document.body.innerHTML = ``; `` комната гаснет, следующий запуск её возвращает. После `Document.prototype.querySelector = null; EventTarget.prototype.addEventListener = null; Array.prototype.push = null; Array.prototype[Symbol.iterator] = null; Function.prototype.call = null;` снимки по-прежнему приходят. Код ``const lamp = document.querySelector(`#lamp`); lamp.id = `x`; lamp.classList.add(`on`);`` → лампа на месте и горит. `while (true) {}` не замораживает игру (курсор в терминале мигает); стёр строку, написал строку с лампой, Ctrl+Enter → лампа загорается меньше чем за 2 с, iframe уже на run-1.localhost. В DevTools у первого iframe origin http://127.0.0.1:5173, у игры http://localhost:5173. `npm test` зелёный. Закоммичено и запушено.

## Этап 3 (только если на вопрос 5 ответ «да»). Ссылка в интернете

**Цель.** Срез открывается по ссылке на любом компьютере без новых аккаунтов. Если ссылка не нужна, этап выпадает, а тема сайта уходит за пределы среза.

**Что строим:**

- .github/workflows/pages.yml: сборка и выкладка на GitHub Pages через Actions после каждого push. В vite.config `base: '/JSGame/'` только для сборки
- Режим «пустой origin»: iframe с `sandbox="allow-scripts"` без allow-same-origin. Его origin — `null`, указать его адресатом нельзя, поэтому порт уходит `postMessage(hello, '*', [port])`, но только в ответ на «готов», у которого `event.source === iframe.contentWindow`. Агент проверяет, что hello пришёл от https://chebupeka.github.io
- Проверить import() из blob:null внутри такой песочницы. Если браузер его не грузит, запасной путь — data:text/javascript (номера строк те же)
- VITE_SANDBOX_ORIGIN и флаг «пустой origin» задаются переменными в workflow, а не файлом .env (в .gitignore стоит `.env.*`)

**Что увидишь.** Ссылка https://chebupeka.github.io/JSGame/ открывается на другом компьютере или у друга, и лампа зажигается так же, как дома.

**Какие риски закрывает:**

- на GitHub Pages песочница не делит origin с игрой
- подделать порт нельзя и при пустом origin
- выкладка автоматическая, руками ничего не копируем

**Готово, когда:** Лампа горит на chebupeka.github.io/JSGame. `parent.document` в коде игрока → дословная SecurityError. `localStorage` в коде игрока → дословная ошибка браузера на полях, игра цела. `while (true) {}` не вешает вкладку навсегда (полностью спасёт сторож на этапе 12; до него допустимо, что вкладку придётся перезагрузить — записать это в README). Action зелёный. Закоммичено и запушено.

## Этап 5. Провод, пока печатаешь

**Цель.** Главное чудо механики: закрыл кавычку селектора — от терминала к лампе тянется призрачный провод. Код при этом не выполняется, игра ничего не угадывает и не врёт.

**Что строим:**

- src/code/preview.js: после паузы ~150 мс разбор acorn-loose, обход acorn-walk. Берём только `document.querySelector` / `querySelectorAll` с закрытой строкой без `${…}` и проверяем, что закрывающая кавычка правда есть в тексте, а не дорисована парсером. Поиск внутри функции — «искать каждый раз». Селектор из переменной, через `${…}` или поиск не от `document` — «узнаем при запуске»
- Честность превью: если раньше по ходу выполнения есть инструкция, которая может поменять разметку, классы или id (classList, `id =`, `className =`, setAttribute, innerHTML, append, remove, createElement… или вызов своей функции), ответ — «узнаем при запуске», а не «нашлось» и не «не нашлось». Для поиска внутри функции «раньше» — это весь файл
- Запасной прогретый iframe: чистая станция плюс уже решённые файлы. Ему можно только «прочитать» — настоящий querySelectorAll в try/catch. Любая другая команда запасному запрещена; если его что-то изменило, он выбрасывается и прогревается заново. Мир на экране — всегда другой iframe. - искра на одном звене
- погасшая строка
- тумблер «выровнять» на кромке корпуса

**Какие риски закрывает:**

- Prettier в браузере: размер и ленивая загрузка
- Shift+Alt+F рядом с переключением раскладки Windows (Alt+Shift) и в русской раскладке
- сочетания клавиш, перехваченные браузером или ОС
- у Shift+Alt+F есть видимый аналог в мире
- игра полностью проходима без звука (решение 4)

**Готово, когда:** `npm test`: Shift+Alt+F на однострочнике из шага 10 даёт ровно то же, что Prettier 3.9.10 в Node с printWidth 60; код профи из шага 9 не меняется. В русской раскладке Shift+Alt+F форматирует и не переключает раскладку. Во вкладке Network Prettier не грузится до первого нажатия. С `?reset` обе главы, вариант с ошибкой и переписывание как профи проходятся с выключенным звуком. Все сочетания из §3 работают в Chrome/Edge и Firefox в обеих раскладках. Закоммичено и запушено.

## Раскладка экрана

Терминал — верх большого пузатого ЭЛТ вплотную к камере, как камера на референсе. Нижний край кадра нарочно срезает низ корпуса и кинескопа: ты сидишь прямо перед монитором. Это и есть вопрос 1: нынешний terminal.png (215×161, стекло 121×83) сюда не подходит — один только код на 60 колонок при шрифте 3,5u занимает 126u, а поля ещё 56u. Пока ответа нет, рамку рисует код.

Главное правило: размеры текста привязаны к пикселям сцены (u), а не к пикселям экрана. При ×4, ×5 и ×6 раскладка одна и та же, меняется только чёткость.
- Шрифт кода 3,5u. Знак JetBrains Mono шириной 0,6 em = 2,1u, значит 60 колонок — ровно 126u.
- Строка 5u — целое число пикселей сцены, поэтому синяя кромка и провода совпадают со строками на любом множителе.

Размеры в сцене 320×180 (крупный вариант):
- Корпус: x 0–224, y 108–180. Видно ≈224×72, около 28 % кадра.
- Верхняя кромка корпуса (y 108–117), чёткий текст 2,5u: слева имя файла (`lamp.js`); в середине подписи к звукам; правее шильдик «показано медленно то, что случилось мгновенно» (только во время показа); справа два маленьких тумблера (медленный повтор и «выровнять», под каждым его сочетание клавиш) и гнездо для проводов около x 214, y 111.
- Стекло: x 12–212 (200u), y 117–180. Видно 63u, ниже оно уходит за край кадра.
- Стекло по ширине: отступ 2 | синяя кромка 1 (рисует холст) | номера строк 7 | код 126 (60 колонок) | щель 5 с пунктиром #2C3034 | поля 56 (курсив 3u, ≈31 знак) | отступ 3. Итого 200.
- Стекло по высоте: код с y 119, 12 строк по 5u. Поля — строки по 4u, ≈15 строк; самая длинная пометка (разбор ошибки) занимает 12–14, если больше — прокрутка внутри стекла.

Пол — самое тесное место, поэтому он есть в макете этапа 1:

- Правило для фонов Codex: левый нижний прямоугольник 224×72 пустой, справа ниже y 118 — рубильник и телетайп, всё важное выше y 106. Таблички рисует код на ровных площадках высотой 7 px.
- На этапе 1 оба варианта терминала показывают этот макет целиком: полоса пола, белая полоса, пятно лампы, параллелограмм, силуэт 14×36 стоя и сидя.

Обрезает ли рамка:
- Корпус и низ кинескопа — да, нарочно.
- Строки кода — нет: все 12 видны целиком.
- По ширине код обрезается на 60-й колонке, дальше горизонтальная прокрутка CodeMirror. На этом построен шаг 10: однострочник «уезжает за край».

Как это выглядит на экране:
- ×4, окно 1280×720: стекло 800×252 px, код 14 px (60 колонок = 504 px), строка 20 px, поля 12 px.
- ×5, развёрнутый браузер на мониторе 1920×1080 (≈1600×900 места), в том числе при масштабе Windows 125 %: код 17,5 px.
- ×6, F11 на 1920×1080: стекло 1200×378 px, код 21 px, строка 30 px.
- ×3, окно меньше 1280×720 (ноутбук 1366×768 в обычном окне): код 10,5 px, мелко. На стекле одна строка «Разверни окно или нажми F11», игра работает. В F11 на 1366×768 будет ×4.

Техника:
- Холст 320×180 с `image-rendering: pixelated`.
- S = floor(min(innerWidth·dpr/320, innerHeight·dpr/180)) в физических пикселях, CSS-размер холста 320·S/dpr, сдвиг кадра — целое число физических пикселей, проверка через devicePixelContentBoxSize.
- CodeMirror и поля — слой DOM поверх стекла, позиция и шрифт через CSS-переменную --u = S/dpr. Никакого `transform: scale`. Редактор монтируется после загрузки JetBrains Mono, при смене множителя — `requestMeasure()`.
- Цвета текста (#C9CDD2, белый, #9AA1A9, #81B5F6) живут только в стекле (§8); пиксельный буфер проверяется на палитру отдельно.
- Компактный вариант (вопрос 2): код 3u (12 px при ×4), строка 4u, стекло ≈172×52, корпус с y ≈ 124; полоса пола становится y 78–122.

## Отдельный origin для песочницы

Разработка: один сервер Vite, разные origin.
- vite.config: `server.host: '127.0.0.1'`, порт 5173, strictPort. Наружу сервер не открыт, брандмауэр Windows ничего не спрашивает.
- Игра всегда на http://localhost:5173/. Vite печатает http://127.0.0.1:5173, и маленький скрипт в начале index.html переводит на localhost. Так прогресс (localStorage игры) всегда в одном месте. Если какой-то браузер не достучится до localhost, меняем роли: игра на 127.0.0.1, песочница сразу на run-N.localhost.
- Песочница: http://127.0.0.1:5173/run/index.html — папка public/run (index.html, agent.js, core.js) без зависимостей. Vite отдаёт public как есть, без HMR-клиента: в разработке и на сайте одни и те же байты. Скрипт перехода на localhost стоит только в странице игры.
- Другой хост — другой origin и другой сайт (IP-адрес считается отдельным сайтом). Chrome, Edge и Firefox держат такой iframe в отдельном процессе, и `while (true) {}` не замораживает игру.
- Если пульс агента пропал дольше секунды (процесс завис), следующий iframe — и мир, и запасной — открывается на http://run-1.localhost:5173/run/, потом run-2… Каждое имя *.localhost — отдельный сайт и новый процесс; браузеры сами ведут *.localhost на этот компьютер, Vite такие имена пускает по умолчанию. Без этого новый iframe того же сайта попал бы в старый зависший процесс.
- Адрес песочницы в разработке вычисляется в коде, а не берётся из .env: в .gitignore стоит `.env.*`, и такой файл не попал бы в git. На сайте адрес задаёт VITE_SANDBOX_ORIGIN в workflow.

Связь игры и песочницы:
- У iframe `sandbox="allow-scripts allow-same-origin"`, без allow-top-navigation, allow-popups и allow-modals. На чужом origin это безопасно.
- Агент шлёт родителю «готов»; игра проверяет event.source и отвечает `iframe.contentWindow.postMessage(hello, SANDBOX_ORIGIN, [port])`. Агент принимает только первый hello и только от origin игры из своего списка. Если его собственный origin совпал с origin родителя, он отказывается работать.
- Дальше всё идёт через MessagePort, который агент спрятал до запуска кода игрока. `parent.postMessage` из кода игрока игра не слушает, поэтому подделать снимок нельзя.
- iframe два: мир на экране (сюда идут act, её действия и ручка мышью) и запасной (только чтение для превью). Запуск забирает запасной — он становится миром, а новый запасной прогревается заново. Так каждый запуск начинается с чистой страницы.

На сайте (вопрос 5):
- GitHub Pages даёт один origin на все проекты аккаунта: chebupeka.github.io. Песочница с allow-same-origin там была бы тем же origin, что игра, и код игрока дотянулся бы до страницы игры и её localStorage. Так нельзя.
- Для среза хватит GitHub Pages без новых аккаунтов (этап 3): игра на chebupeka.github.io/JSGame/ (`base: '/JSGame/'`, выкладка через GitHub Actions). Песочница — та же папка run/, но iframe с `sandbox="allow-scripts"` без allow-same-origin, у него «пустой» origin `null`. Порт уходит `postMessage(hello, '*', [port])`, но только в ответ на «готов» от `event.source === iframe.contentWindow`. import() из blob:null проверяем, запасной путь — data:text/javascript.
- Цена пустого origin: localStorage в песочнице бросает ошибку (он нужен в главе 4), service worker не работает (глава 6), процесс может быть общим, и смена хоста там не поможет — спасает только сторож в циклах (этап 12).
- К главе 4 нужен второй настоящий сайт. Вариант А: Cloudflare Pages из этого же репозитория, адрес вида jsgame-run.pages.dev; нужен бесплатный аккаунт Cloudflare, заводишь его ты. Вариант Б: бесплатная организация на GitHub, адрес jsgame-run.github.io, выкладка через Action с токеном. pages.dev и github.io есть в Public Suffix List, поэтому это отдельные сайты.
- Поддомен своего домена (run.example.com) даёт другой origin, но тот же сайт и, возможно, общий процесс. Не советую.
- В коде при этом меняются только VITE_SANDBOX_ORIGIN и флаг «пустой origin».
